# scene3d 計測記録

## WebGPU へ移す前の基準（0.95.0・GL / WebGL2）

測った日 2026-11-14 / 機械: Apple M4 Pro・macOS（GL は Apple の Metal の上の OpenGL。ブラウザは Chrome 156 のヘッドレス・ANGLE Metal・WebGL2）/
engine 0.95.0（コミット cd7a7ce2 の上にベンチの直しだけ）/ 垂直同期なし（`FLIX_GE_NO_VSYNC=1`）・音なし / 1 区間は頭の 60 コマを捨てて 300 コマ。
回し方: `bench/baseline.sh bench/baseline/0.95.0`（1 本ごとに別のプロセス・数は軽い方から・間 20 秒・同じ組を 2 回通す）。
生の数字は `bench/baseline/0.95.0/pc.jsonl`・`web.jsonl`（1 行 = 1 区間）・`web-env.jsonl`。時間は ms。**セルの「a / b」は 1 回目 / 2 回目**。scene3d は 1 回の中で同じ条件を 2 区間続けて測るので「a / b / c / d」= 1 回目の 2 区間 / 2 回目の 2 区間。
「揺れ」は同じ条件の中の p50 の（最大 − 最小）÷ 最小。診断（`App.withDiagnostics`）は付けたまま測っている（`diag=1`）。

- PC の frame = 1 コマの間隔（`frame#dt`）・submit = GL へ命令を出し終えるまで・gpu = GPU の時間の query。
- ブラウザの cpu = wasm が 1 コマに使った時間（rAF から戻ってから次に待つまで・`fgeStats`）。frame は rAF の周期（16.7 ms の倍数）に張り付くので比べに使わない。
  ブラウザの時計は 0.1 ms 刻み。GPU の時間はブラウザでは取れない（WebLayer が query を持たない）。
窓 960x540（design 320x180・`Resolution.Native`）。`room` = 固定の部屋。`field` = 小さな箱と柱を格子に並べた場面（`src/Field.flix`）:
物は全部カメラに入る・太陽 1 つ・`moving` = 毎コマ位置と向きを変える物の %・`alpha` = 半透明の物の %・`shadow=1` で太陽の影（2048）。
材質の種類は「同じプログラムで色の値（params）だけが違う」材質。形の種類は寸法の違う箱（6 面）。

- **同じ形・同じ材質の物は、今の engine でも 1 本の draw にまとまる**（12,000 個で draw call 2 = 物 1 本 + 地面）。それでも 1 コマ 21 ms で、
  ほとんどが `split`（描く物を分けて束ねる CPU の区間・15.7 ms）。GPU は 0.7 ms。
- **動かない物でも安くならない**: 動く割合 0% で 16.1〜16.7 ms（`split` 14.2 ms）。毎コマ全部の物を分け直している。
- 形 16 × 材質 16 は draw 257 本で 24.4〜25.9 ms（+4 ms）。**形が物ごとに違うと draw 12,001 本・75〜77 ms**（`draw` 39.8 ms・GPU 33 ms）。
- 半透明 10% は draw 1,202 本（半透明の物は 1 個ずつ・遠い順）で +4 ms。太陽の影は +5 ms（`split` が 15.7 → 20.4 ms。影の地図へも分ける）。
- ブラウザは PC の 約 3 倍（12,000 個で cpu 62〜66 ms・`split` 57 ms）。形が物ごとに違う場面は 1.6 倍（124 ms）。
- 揺れ: PC は 1〜9%。**動く割合 10% だけ 1 回目 13.8〜14.5 ms・2 回目 17.4〜17.8 ms で 29% 開いた**（理由は【不明】。比べる時は同じ日に背中合わせで取る）。
  ブラウザの部屋は 1.3〜2.2 ms で、時計の刻み（0.1 ms）と軽さのために比が大きく出る（69%）。
- `gl-capture` の scene3d の 6 コマは、ベンチを直す前と後でバイトまで同じ（同じ機械・同じ日の 2 回）。
  `bench/baseline/0.88.4/gl-capture.sha256` の scene3d の行とは違う（直す前のソースで撮っても違う。0.88.4 の後の engine の変更による物で、基準の取り直しは別の話）。
