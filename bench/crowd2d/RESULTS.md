# crowd2d 計測記録

## WebGPU へ移す前の基準（0.95.0・GL / WebGL2）

測った日 2026-11-14 / 機械: Apple M4 Pro・macOS（GL は Apple の Metal の上の OpenGL。ブラウザは Chrome 156 のヘッドレス・ANGLE Metal・WebGL2）/
engine 0.95.0（コミット cd7a7ce2 の上にベンチの直しだけ）/ 垂直同期なし（`FLIX_GE_NO_VSYNC=1`）・音なし / 1 区間は頭の 120 コマを捨てて 300 コマ。
回し方: `bench/baseline.sh bench/baseline/0.95.0`（1 本ごとに別のプロセス・数は軽い方から・間 20 秒・同じ組を 2 回通す）。
生の数字は `bench/baseline/0.95.0/pc.jsonl`・`web.jsonl`（1 行 = 1 区間）・`web-env.jsonl`。時間は ms。**セルの「a / b」は 1 回目 / 2 回目**。
「揺れ」は同じ条件の中の p50 の（最大 − 最小）÷ 最小。診断（`App.withDiagnostics`）は付けたまま測っている（`diag=1`）。

- PC の frame = 1 コマの間隔（`frame#dt`）・submit = GL へ命令を出し終えるまで・gpu = GPU の時間の query。
- ブラウザの cpu = wasm が 1 コマに使った時間（rAF から戻ってから次に待つまで・`fgeStats`）。frame は rAF の周期（16.7 ms の倍数）に張り付くので比べに使わない。
  ブラウザの時計は 0.1 ms 刻み。GPU の時間はブラウザでは取れない（WebLayer が query を持たない）。
窓 1280x720（design 640x360）。探し方は SpatialGrid だけ（`SEARCH=grid`）。規則 = `Crowd.advance` の 1 コマ。

- **20,000 体は完走する。** 探し方を両方（既定）にすると 2 分かかる: 全部と比べる形は 1 コマ 200 ms（規則 164 ms）で、300 コマに 約 90 秒。
  その直後の SpatialGrid の区間は熱で遅く出うるので、20,000 体は `SEARCH=grid` で測る（コマ数は `FRAMES=` で減らせる）。
  2026-11-14 の 1 回: 全部と比べる形 frame p50 200.4 ms / SpatialGrid 54.8 ms（同じプロセスで続けて測った値）。
- 20,000 体の 1 コマ 56.6 ms のうち規則が 25.5 ms・GL へ送るのが 5.9 ms。残りの 約 25 ms は描く物の列を作る所（engine の上の層）【割り算】。
  1 体のまわりの相手は 55.6 体（場の広さは同じなので、数を増やすと混む）。
- ブラウザは PC の 約 1.6 倍（20,000 体で cpu 88.7 ms・規則 44.5 ms）。
- 揺れは 0〜1%。

## 描く物の列を作る所の直し（P1・ループを JIT に乗せる）

測った日 2026-11-14 / 同じ機械 / 垂直同期なし・音なし・診断あり / 頭の 120 コマを捨てて 300 コマ・`COUNTS=6000,10000,20000 SEARCH=grid`。
直す前 = main の 6855cdb2・後 = 57291f90（1 つ目の直し）。1 本ごとに別のプロセスで、前 → 後 → 前 → 後の順に交互に測った（間 15 秒）。「a / b」は 1 回目 / 2 回目。時間は ms。

| 条件 | 前 frame p50 | 後 frame p50 | 差 | 前 規則 p50 | 後 規則 p50 | 前 submit p50 | 後 submit p50 |
|---|---|---|---|---|---|---|---|
| n=6000 | 14.93 / 14.54 | 7.17 / 7.24 | −51% | 5.66 / 5.18 | 3.67 / 3.67 | 1.76 / 1.79 | 0.61 / 0.62 |
| n=10000 | 22.63 / 22.25 | 12.62 / 12.59 | −44% | 9.06 / 8.88 | 7.67 / 7.63 | 1.03 / 1.02 | 0.98 / 0.98 |
| n=20000 | 53.02 / 53.12 | 31.84 / 31.99 | −40% | 25.56 / 25.50 | 21.34 / 21.32 | 1.98 / 2.02 | 2.12 / 2.13 |

- 規則と送るのを引いた残り（描く物の列を作る所）は、20,000 体で 約 25 ms → 約 8 ms。
- 規則も速くなった（20,000 体で −16%）。`SpatialGrid.cellIndexOf` が末尾呼び出しで終わっていて、それを呼ぶ `countCells` と、
  ベンチの側の 1 体ごとのループ（`Crowd.moveByGrid`）がインタプリタのまま回っていた（JFR の標本で 10,000 体の 1 コマの 約 15%）。ベンチの .flix は直していない。
- 20,000 体の 1 コマ 約 32 ms のうち 21 ms は規則（押し合いの計算）で、描く側の残りは 約 8 ms。
- 内訳の取り方と直した形は `bench/sprite_stress/RESULTS.md` の同じ題の節と `docs/performance.md` の 13 節。
