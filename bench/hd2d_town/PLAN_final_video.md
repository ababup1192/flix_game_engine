# 最終動画の計画（60 秒・町が降ってくる → 北へ歩きながら昼・夕方・夜・霧 → 火山と氷の高低差）

人の言葉（11-18）:「上からものが降ってきてから　上に歩くと　夕方・夜・霧って　あるきながら変わる感じに」「上まで行ったら　火山・氷　と右に階段を登る　下に下る　みたいな　高低差を見せて終わる」。
人の決め: エンジンで作る / 町の北の端から火山・氷へは場面転換（白飛び）/ 全体は 60 秒くらい（降る 20 秒・町を北へ 20 秒・火山と氷 20 秒）。

**人の決め（計画の了承・11-18「入ってよい」）**:
- 階段は「右へ曲がって奥へ上る」（今の手本の段のまま。東へ上る段は作らない）。
- スマホの操作は B（engine_web に画面のスティックを足して `frame#leftStick` へ。engine の拡張として了承済み）。
- ブラウザ版のカメラは C3（歩く向きへ 1〜2 m 先をなめらかに見せる）・建物に隠れた時は H1（隠れない地図にする・engine 無改修）。
- リリースは R1（テンプレートまで作ってから engine の枝と一緒に 1 回で出す。リリースと push はその時に人に確かめる）。
- 地図から立体を組む作りは T1（テンプレートに写しで持つ）。
- 進め方: F1〜から順に、節目ごとに絵か動画を人に見せる。最初の節目は記念碑のドスンの前後と、夕方の Doc（昼・夕方・夜の 3 枚並べ）。

ここに書くのは bench/hd2d_town の中の作りだけ。engine に手を入れる所は 6 節に分けて並べ、どれもゲーム側だけで済ませる別案を添える。

## 2. 町の作り

### 2.1 道を北へ延ばす

- 新しい写し `assets/town_final.map.json`（64 行）を、上から次の 3 つを積んで作る（Blender の地図は触らない）:
  1. 行 0〜25: **北の新しい部分**（26 行）。北の大通り（3 マスの石畳・両脇の水路・植え込みの帯・街灯 3 マスおき）と両脇の建物 2〜3 軒、行 0〜3 に北の門（建物 2 軒の間の 3 マスの口・石の柱 2 本）。
  2. 行 26〜51: **hd2d_lab f730800 の town_avenue.map.json をそのまま**（26 行・十字の広場は行 41〜51）。広場のにぎやかしの props の座標がそのまま使えるように、今の南へ広げた写しのように広場を作り替えない（レビューの指摘 1）。夜の街灯の差分（nightlamps）は入れる。
  3. 行 52〜63: **南の大通り**（12 行・今の南へ広げた写しの行 20〜31 と同じ作り）。立つ所は列 13・行 54。
- 池の東の回り道（指摘 2）: 写しの地図の行 30（元の行 4）の夜の街灯 (15,30) を (16,30) へ 1 マス動かす。道は (13,33) → (15,33) → (15,28) → (13,28)。行 33（元の行 7）の街灯 (16,33) は動かさない（道は列 15 で曲がる）。仲間の 2 人は先頭の道をなぞるので、角が 4 つ続く所はカメラのならし（0.35 秒）が続けてかかる。前の版の撮りで角の続く所がぎこちなければ、(15,33)→(15,28) を 1 本にまとめる。
- 輪の出来方（指摘 6）: `Buildup.radialFront` の「一番遠い角」を **元の範囲（行 26〜63）の角**で決め、北の新しい部分（行 0〜25）のマスの時刻は輪の終わりで頭打ちにする（輪の終わりの頃に霞の奥でまとめて出来る）。こうすると、見えている所の出来方は今の中心の動画と同じ時間配分になる。北の部分を歩きながら前線で出す案は、歩きの区間の重さが増えるので採らない。

### 2.2 歩きながら昼 → 夕方 → 夜 → 霧

- Look の Doc を 4 つ（昼 `town.json`・夕方 `town_dusk.json`（新しく作る）・夜 `town_night.json`・霧 `town_night_fog_mid.json`）並べ、**先頭の行で隣の 2 つの値の間をなめらかにつなぐ**（`TownLook.blend(a, b, u)`・u は smoothstep）。境目の行は 1 節の道のりの表。時刻でなく道のりで決めるのは、歩きの速さや止まる時間を直しても、どの通りで夜になるかが変わらないようにするため。
- つなぐ値: 環境光・空・霞（fogNear・fogFar・色）・露出・ColorGrade・街灯の強さ（行 29 までは 0・そこから夜の 260 へ）・火袋とハローの強さ（同じく行 29 から）・HeightFog。街灯を板の切り替えと同じ行 29 から点けるのは、光を当てる板に北の街灯の光が裏から当たる形（前の影絵）を作らないため。
- **HeightFog の None と Some**: None は「霧の Doc の値で density 0」と同じと決め、色・落ち方・むらは霧の Doc の値を使う。濃さだけを 0 → 0.8 でつなぐ。
- **太陽から月への受け渡し**（指摘 4）: 夕方の太陽は高さ 10°・向き −75°（西寄り）・色 (1.0, 0.55, 0.3)。夕方 → 夜の区間の前半で太陽の強さを 0 まで落とし、強さ 0 の行（行 29）で向きと色を月の物（高さ 40°・向き −35°・(0.68, 0.64, 0.98)）へ替え、後半で月の強さを上げる。高さと向きは隣どうしでつながない。
- つながない値（場面の頭で 1 回決める）: 光の量の読み方（Physical）・点光源の影（4 本）・影の地図の大きさ。**昼も Physical に揃える**。Physical の 1/π は太陽と点光源にだけ掛かり、環境光には掛からないので、昼の太陽の強さを 3.3 × π ≒ 10.4 にすれば今の昼と同じ絵になるはず。1 枚撮って今の昼と数で比べて確かめる。昼から影を落とす灯り 4 本を付けたままにすると、強さ 0 の灯りの影の地図も描くかもしれないので、CPU と GPU の 1 コマの時間を測る（重ければ街灯の強さが 0 の間は点光源の影を外す）。
- **キャラと木の板の夜の明るさ**（指摘 3）: 光を当てる板と当てない板（`Scene3d.unlit`）は二択で、1 枚の板の中で混ぜられない。夕方 → 夜の区間の中の、暗くて差の目立たない 1 点（行 29・太陽の強さ 0 の所）で、隊列と町の人（charLit）と木・低木・広場の小物（lampLit）を一斉に光を当てない板へ切り替える。その手前の行で光を当てる板の明るさを測り、切り替えの瞬間の光を当てない板の色の掛け目を同じ明るさに合わせる（そこから夜の値へつなぐ）。切り替えの前後のコマを並べて、跳ねが見えないかを確かめる。
- 夕方の Doc は新しく作る（空は橙から紫・影は長い）。Blender の夕方の版は無いので、昼と夜の間の 1 枚を人に見せて決める。

### 2.3 広場のにぎやかし

- Blender の `props`（hd2d_lab f730800・park の案・18 件）を、写しの地図の `props` 欄へそのまま写す（at・off・z・frames・frameSec・seq・phase・flip・sway・move・variant・shadow・cast・height）。
- 絵は hd2d_lab の sprites から写す: market_stall・peddler_idle・balloon_kid_idle・balloon・dog・townsman_idle・townswoman_idle・elder_idle・horse・carriage・pigeon・barrel・crate_td（flower_pot は有る）。project.json の textures に足す（GPU の板は project.json の名前で引く）。
- 地図の格子の `Prop`（`Owner.Prop`）と紛れないよう、`props` 欄を読む型は `Decor`（飾りの板）とする。`Decor` はコマの欄（帯・コマ数・コマの秒・seq・phase）と揺れ（sway）を持ち、毎コマ `TownScene` で切り出す（歩く板と同じ切り出し方）。move（行き来）は park の案では使わないので作らない。
- 座標は 2.1 の積み方で 26 行ずれるので、写す時に行へ 26 を足す（props だけでなく、写す hd2d_lab の部分の buildings の y・variants の差分・camera.frame の anchor にも足す）。
- 夜の街灯の差分（nightlamps）の (10,47)（元の (10,21)）は植木鉢 [10,21] と同じマスになるので、植木鉢を 1 マス西（[9,21]・行を足して [9,47]）へ動かす。(16,47) の街灯は犬 [16,22]・風船の子 [17,21] のすぐ隣なので、犬を [15,22] へ 1 マス動かす（Blender の props は昼の地図（nightlamps なし）で置いた物で、bench は昼も夜も 12 本のため）。新しい path の形でも、町の人の印（1・2・3）を外す列（skipNpcColumn）に歩く列 13 が渡るかを F2 で見る。
- 夜は町の人と同じく charLit（灯りから遠いと沈む）。
- 出来ていく動画では、広場の人と物は**記念碑の揺れが収まった後**に 1 つずつ出る: 出る時刻 = 揺れの終わり（着地 約 15.3 秒 + 0.9 秒）+ 0.1 秒 × 並び順（18 件で 1.8 秒・16.2〜18.0 秒・降ってきて着地・土ぼこり・`Owner.Prop` と同じ動き）。揺れの間に出ると跳ねと重なるので、揺れの終わりを待つ。

### 3.4 歩きの台本とカメラ

- 炎: [10,3] → [10,15] → [16,15] → [16,10]。上の広場（レベル 9）から南へ下り、行 6〜7 の階段で 9 → 7・行 10〜11 で 7 → 5・行 13 の岩の橋で溶岩を渡り、行 15 で右（東）へ・列 16 を北へ戻って行 13 → 12 の階段で 5 → 7 へ上り、北を向いて止まる。「右へ曲がって上る・下る」がこの 1 本で見える。
- 氷: [10,22] → [10,4]。北へまっすぐ・行 11 → 10 の階段で 1 → 3 へ上って止まる。
- カメラ: 人の決めの B（横と奥は先頭を追う・高さは遅れて追う）。曲がりと止まる所だけ丸める（今の追従と同じ）。
- 南へ下る所は、パーティが画面の手前へ来るので背中でなく正面の帯（dirs の s）を使う。
- 足の高さ `TownMap.groundZAt` には、Blender の `ground_z` の 2 つ目の分かれ（段の 1 つ手前のマスの奥 1/4 で、最初の蹴上げまで上げておく）も入れる。無いと段に入る瞬間に足が跳ねる。
- カメラの距離は町の追従（walkZoom 1.35）とそろえる。炎・氷の地図の camera.frame（width 16.3）でなく、町と同じ目の位置の作り方に「足元からの距離の倍率」を掛ける形にし、白飛びの前後でキャラの大きさが跳ねないようにする。
- **「右に階段を登る」の読みを F4 の前に人へ確かめる**（指摘 9）。手本の段（Blender の `build_stairs`）は北（奥）へ登る段だけで、計画の道は「右（東）へ曲がってから奥へ登る」。横から見える東へ登る段が要るなら、`shape` に向きを書けるようにして（`>` = 東へ登る など・plans §5.2 の案）、段の形と足の高さを 4 向きにする（+2 時間）。絵コンテの 1 枚（炎の地図の上に道と段の向きを描いた物）で聞く。

### 3.5 場面転換

- 白飛び（指摘 5）: 露出を足す形は場面の露出（霧 −2.0 段・炎は Standard）で白への届き方が変わるので使わない。**画面全体の白い 2D の四角を α で重ねる**（0.8 秒で α 0 → 1・白の間に場面を差し替え・1.2 秒の 1−(1−u)^2.5 で α 1 → 0）。GPU では App の `hudView`（後がけの外）に置き、CPU で撮る道（HeadlessRender）でも同じ四角を後がけの後に重ねる。F7 の頭で両方 1 コマずつ撮り、露出とブルームが掛からないのを確かめる。
- 3 つの場面（町・炎・氷）は、それぞれの地図と Look を読み込んだ「場面の値」にし、動画の時刻で切り替える。1 回の起動で 3 つとも読み込む（GPU の板は project.json の名前で引くので、絵は全部 project.json に足す）。

## 4. 撮り方

- GPU（GL）で撮る。WebGPU は影を落とす灯りが 2 本以上で材質の値の置き場（64 KB）に入らず黒くなる（光の担当が直しをコミット済み・取り込みは別に頼まれる）。取り込んだら WebGPU でも撮って同じ絵になるかを確かめる。
- 1 回の起動で 64 コマなので、60 秒 × 30 fps = 1800 コマ ≒ 29 回の起動。1 回の起動では、その 64 コマに要る場面（町か炎か氷）だけを読み込む。読み込みが重い場面の起動は 20 秒より延びるので、F7 で 1 回測ってから全体の時間を直す（dt は固定なので、読み込みの遅さは絵には効かない）。
- 段ごとに CPU の静止画で見比べてから GPU で撮る（段ごとの見せ物は 5 節）。

## 8. ブラウザ版（F8）: 昼の町を歩き回る（PC とスマホ）

人の言葉: 「最後は街の中を歩き回るようにWEB版を吐き出すこと出来る？　PC・スマホ両対応」「画面上にスティック　場面は昼だけでよいよ」。

- **中身**: 昼の町（2.1 の地図・広場のにぎやかし入り）だけ。夕方・夜・霧・火山・氷は入れない。町は出来上がった姿から始める（降ってくる演出は入れない）。書き出しは `bin/fge export-web`。
- **前提**: 昼だけで点光源の影を使わないので、WebGPU の材質の置き場の直し（光の担当の 5459049e）は要らない（黒くなるのは影を落とす灯りが 2 本以上の時だけ）。取り込みは頼まれた時に別にする。最終動画の 2.2（場面の頭で Physical と点光源の影 4 本）はブラウザ版に持ち込まず、昼の Look を単独で使う。

### 8.1 操作（先に調べた事）

- PC: キーボード（矢印と WASD）。パッドは engine が `frame#leftStick`（長さ 0〜1・右が +x・上が +y）を渡すので、倒した向きと強さで歩く（キーは 8 方向・強さ 1）。
- スマホ: engine にあるのは **画面の十字キー**（engine_web の `web.virtualPad`・dpad と押しボタン。指で押した腕をキーとして渡す・**4 方向**: `fgeDpadDir` は上下左右のどれか 1 つだけを返し、斜めは作れない。書き方は docs/migrations/0.85.0.md と templates/rpg-starter/project.json）。**倒した量で速さが変わるアナログの画面のスティックは無い**（plans/engine-analog-stick.md は実機のパッドのスティックだけで、「キーボードやマウスからスティックの値を作るのはゲームの側」と書いてある）。
- canvas の上の指は、engine_web が「離した時のタップ・縦のドラッグはホイール・横のドラッグはマウスの左を押したまま動かす」に読み替える（主な指 1 本だけ）。そのため、ゲームの側で canvas の指の位置から斜めのスティックを作るのは、縦の動きがホイールに取られて作れない。
- 案（人に相談して決める）:
  - A（engine 無改修）: 画面の十字キー（`web.virtualPad` の dpad）を左下に出し、**4 方向で歩く（斜めには歩けない）**。押しボタンは無し。見た目は engine の部品のまま。人の言葉は「画面上にスティック」なので、斜めと倒した量が要るなら B。
  - B（engine に足す・相談・人の言葉に近いので推し）: engine_web に、指の位置からの倒した向きと強さを `frame#leftStick` に入れる画面のスティック（`web.virtualStick`）を足す。PC のパッドと同じ口で受けられ、ゲームの作りは A と同じ。engine_web の JS と、`leftStick` を作る所（実機のパッドと同じ道）に足す。見積もり +3 時間。
- 速さ: キーは決まった速さ（約 3.46 マス/秒・キーボードは 2 つ押しで斜め）、スティックは倒した量 × 同じ速さ。向きの絵は 4 方向（背中・右・正面・左は右の反転）を、動く向きの近い方で選ぶ。

### 8.2 ぶつかり

- 地図からマスごとの「通れる・通れない」の格子を作る: 建物・水路（w）・生垣（H）・低木の帯（h）・木（T・C）・街灯の柱（L）・木箱（X）・柵（f）・記念碑と池・広場のにぎやかし（屋台・馬車と馬・立ち話の 3 人・行商人・風船の子ども・犬。鳩は通れる）は通れない。
- 段差は階段（`^`）からだけ上り下りできる（町の地図は今は平らなので、作りだけ入れておく）。
- 動き: パーティの先頭を半径 0.3 m の円として、通れないマスの四角とぶつけて壁に沿って滑らせる。仲間の 2 人は先頭の通った道をなぞる（今の隊列と同じ）。

### 8.3 カメラ（決めずに案を並べる・人に相談してから決める約束）

- 追いかけ方:
  - C1: 今の追従と同じ（横と奥は遅れ 0・止まる時だけなめらかに）。歩き回ると、向きを変えるたびに画面が揺れて見えるかもしれない。
  - C2: 遊びの枠（画面の真ん中の小さな四角）の中では動かさず、外へ出た分だけ追う。
  - C3: 歩く向きへ少し先を見せる（先読み 1〜2 m をなめらかに）。
- 建物に隠れた時:
  - H1: 地図を隠れない作りにする（建物の北側の 1〜2 マスを通れなくする）。engine 無改修。
  - H2: 隠れている間だけ、間の建物の板と形を薄くする（形ごとの α が要るので、engine に足すなら相談）。
  - H3: 隠れている間だけ、キャラの影絵を建物の上に描く（板を奥行きの検査なしで重ねる。engine の口を調べてから）。

### 8.4 スマホの重さ

- 測る段取り: `make bench-web`（engine の根）か、書き出した物を手元のサーバーで出し、手元のスマホで開いて 1 コマの時間を測る（スマホの 3D の基準は fps3d-room で 46.5 fps・cpu 20.7 ms）。PC のブラウザでも同じ物を測って並べる。
- 落とす手（重い時）: 影を落とす灯り 2 本（昼は街灯の強さ 0 なので、点光源の影ごと外してもよい）・点光源の影の絵 256・太陽の影の地図を 4096 → 2048 → 1024・手前と奥のぼけ（DoF）を外す・描く解像度を下げる。霧は昼なので無し。
- 町の部品は 2600 ほどになるので、動かない物は全部 staticGroup に入れる（スマホでは staticGroup ありで 12,000 個 60 fps の実績）。起動時に町を組む時間もスマホで測り、長ければ LoadProgress で進み具合を出す。`App.withPostStack` の Auto はスマホで Low になる点も確かめる。
