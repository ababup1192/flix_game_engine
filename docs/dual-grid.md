# デュアルグリッド地形 — チップ絵なしで壁や水を描く仕組み（概念ノート）

初学者向けの1画面の概念説明。実装の詳細は `engine_world/src/DualGrid.flix` /
`Terrain.flix` / `Material.flix` の冒頭 doc コメントを参照。

## 何をする層か（3層の分業）

マップの「壁・水・マグマ」などの地形を、タイルセット PNG（チップ絵）を1枚も使わずに
**多角形（形）+ 色と質感（塗り）** だけで描く。3つのモジュールが役割を分ける:

- **DualGrid** — 純粋な幾何。「どの角がどんな形になるか」だけ。色も z も持たない。
- **Material** — その形に質感を着せる。塗り・フチ・持ち上げの前面・表面の粒（きらめき・泡）。
- **Terrain** — 「どのセル文字にどの Material を着せるか」の表と、`rows`（文字格子）の入口。

チップ絵を貼りたい場合は別経路の **MapResource**（タイルセット PNG）を使う。DualGrid は
「絵を持たず、色と質感パラメータで手続き的に作る」並立の道。テーマ替え・ホットリロードで
色や質感を即座に振り直せるのが強み。

## デュアルグリッドとは（ざっくり）

ふつうのタイルは「1マス = 1枚の絵」。デュアルグリッドは視点を**半セルずらし**、
**セルの角**に注目する。1つの角のまわりには4つのセルが接する（左上・右上・左下・右下）。
その4つが「埋まっている／いない」の組み合わせ（2⁴ = **16通り**）だけで、その角に置く
多角形の形が決まる。だから地形データは「どのセルが壁か」を持つだけでよく、角の丸みや
斜めのつなぎ目は**自動で**出る。壁と壁の間が滑らかにつながり、角が丸まり、飛び地は
ちゃんと切れる — マスごとに「角用チップ」を描き分ける必要がない。

```
セル格子（■=壁, ・=床）        角に注目（●）と、そのまわり4セル
                                          tl │ tr
  ■ ■ ・                                    ●          この角の4セルは
  ■ ・ ・            →                    bl │ br      tl=■ tr=■ bl=■ br=・
  ・ ・ ・                              → 4ビット = 1110₂ = ケース14
                                        → 「右下だけ欠けた」形の多角形が出る
```

角の4セルを `tl,tr,bl,br` の4ビット（tl=8, tr=4, bl=2, br=1）にまとめたのが
`caseIndex`（0〜15）。ケース0は「4セルとも空」で形なし、ケース15は「4セルとも埋まり」で
まるごと1マス。残りが縁・角・斜めのつなぎ目。対角2セルだけ（ケース 9/6）は三角2枚になる。

## rows を塗るだけで地形になる

`Terrain.fromRows` は上の仕組みを1発でまとめた教科書 API。文字格子（`rows`）と
「文字→質感」の表（Doc 由来）を渡すだけで、置き場所つきの描画物が返る:

```
rows = [ "WWW",     W を壁の質感に割り当てておくと、
         "W.W",     この W の並びから角の変化形（丸角・縁・
         "WWW" ]    中空の角）が自動生成される。'.' は床。
```

床（角の変化形を持たないベタ塗り）は DualGrid の仕事ではなく、呼び側（View）が全セルに
敷く。表に無い文字・未知文字は自動的に床へ落ちる（fail-open）。

## 向いている物・向いていない物

境目が必ずマスの中央を通る＝**マス目と絵が半マスずれる**のが本質。
判定は「そのマスは**面の一部**か、**その場所**か」。

- **向く（面）** — 芝⇔土⇔水、壁⇔床、洞窟の岩。境目が半マスずれても困らない。種類は 2〜3 種まで
- **向かない（場所）** — ワールドマップの町・城・山のような**マス = 1 枚のスタンプ**、
  国境・道のように**境界自体が情報**の物、クリック当たり・移動コストがマス単位で意味を持つ物
- **向かない** — 方眼をわざと見せる戦略マップ（グリッドを消すのが DualGrid の目的なので逆）

ワールドマップは分けて描く: 海と陸の下地だけ DualGrid、町・山・森は 1:1 のスプライト層を上に重ねる。

## なぜチップ絵を描かないのか

- **調整が速い** — 色・フチの太さ・粒の density は Doc（JSON）の数値。保存即反映で振り直せる。
- **決定的** — 表面のゆらぎ（粒の位置・位相）は座標ハッシュ（`Hash01`）で出すので、
  種を持たず毎回同じ。gallery/ vs reference/ のバイト比較（bench）が安定する。
- **テーマ替えが1箇所** — 「石垣」「氷」「溶岩」は同じ幾何に別の Material を着せるだけ。

## 見本はこのリポジトリに無い

`DualGrid` / `Material` / `Terrain` / `TerrainDoc` を呼ぶコードも `.terrain.json` も、
このリポジトリには 1 つも無い（`templates/` にも `bench/` にも無い）。使うときは
`engine_world/src/DualGrid.flix` / `Material.flix` / `Terrain.flix` / `TerrainDoc.flix` の
冒頭 doc コメントと `engine_world/test/TestTerrainDoc.flix`（Doc の形）を写経元にする。
描画の導出を守るスナップショットも無いので、絵の確認は自分のゲーム側でやる。
