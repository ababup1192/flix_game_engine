# エラー処理の決まり — 既定値で続けるか・止めるか・言うか

壊れた入力への反応は 3 つだけ: 既定値で続ける（fail-open）・`Err` を返す・`bug!` で止める。
続けてよいかは呼ぶ側の文脈で決まるので、読み込む側が決めない。

- 読み込みはまず `Result` を返す `load*` を書き、要るならその上に薄いラッパを足す:
  `loadOr`（既定値で続けて 1 行言う）/ `loadOrBug`（起動時の必須入力が欠けたら止める）。
- ゲームが呼ぶ口は `loadOr` / `loadOrBug` の側（値がそのまま返る）。既に fail-open で使われている口を
  `Result` へ変えない。名前が実態と合わないなら、直すのは名前。
- `bug!` は `*OrBug` の中・プログラマの前提が破れた所（到達不能な分岐など）・起動時にアセットの実体
  （テクスチャ・音・フォント）が読めない所だけ。読み込みの途中では止めない。
- 既定値で続けたら `Log.fellBack(領域, 対象, 既定値の名前, 理由)` で 1 行言う（純粋な関数の中は
  `Log.fellBackThen` / `Log.warnThen`）。任意 Doc が**無い**のは正常系なので黙り、有るのに読めない時だけ言う
  （`ErrorKind.NotFound` で分ける）。毎フレーム通る経路では名前ごとに初回 1 回だけ。
- `Err` の中身は JSON / Doc 由来なら `Util.Json.JsonError`、それ以外は `String`。新しいエラー型は作らない。

以下は詳しい本文（`.claude/rules/error-handling.md` には上の芯だけが出る）。

同じ Doc が GL 実機・`make render-all`・`flix test`・Studio プレビューの 4 経路から読まれる。
実機なら「面が黒くなるだけ」で遊べても、headless では実機と違う絵がスナップショットに固定される。

## 決まり 1 — 読み込みは 3 つの関数に分ける

| 関数 | すること |
|---|---|
| `load*` | `Result` を返す。既定値で続けない。判断しない |
| `loadOr` | `load*` に薄く被せるラッパ。既定値で続け、**そうしたことを 1 行言う** |
| `loadOrBug` | `load*` に薄く被せるラッパ。起動時の必須入力が欠けているので loud に止める |

3 つとも既にある。`ShaderJson.load` / `loadOr`、`HitDoc.load` / `loadOrBug`、`UiDoc.load` / `loadOrBug`、
`LwjglLayer.withProject`（`loadProject` の `Err` を起動時に止める）。**新しく読み込み関数を書くときは
`load*` を先に書き、フォールバックする形が要るならその上に薄いラッパを足す。**

**ゲームが呼ぶ口には `Result` を出さない。** ゲームの View やロジックから呼ぶ物は
`loadOr` / `loadOrBug` の側で、値がそのまま返る。毎回 `match` で捌かせると使い勝手が落ちる。
`Result` を返す `load*` を直接呼ぶのは engine の中と、失敗を画面に出せる側
（Studio・CLI）だけ。**既に fail-open で使われている口を `Result` へ変えない**
（呼ぶ側全部に `match` が生える）。名前が実態と合っていないなら、直すのは名前の方。

## 決まり 2 — `bug!` を使ってよい場所

- **正当 A: `*OrBug` ラッパの中。** 呼ぶ側が「起動時に loud に止める」を選んだ結果なので正しい
- **正当 B: プログラマが書いた前提が破れたとき。** 到達不能な分岐・呼び出し規約違反・
  自分が直前に作った値の破れ・Flix の型と `*.schema.json` の食い違い
- **正当 C: アセットが無い・壊れているときに起動時で止まる。** テクスチャ・音・フォントの実体が
  読めないのは遊ぶ前に必ず出るので、リリース前に確実に気づける。fail-open で「絵が出ない音が鳴らない
  まま完成したことにする」方が悪い
- **違反: 読み込みの途中で `bug!` する。** 呼ぶ側に選ぶ機会を与えていない

**判定に doc コメントを使わない。`Result` を返す兄弟関数があるラッパかどうか、という構造だけで決める。**
「この関数は失敗したら panic させる方針」と書いてあっても、それは正当化にならない
（そう書けば何でも通ってしまい、決まりが違反を裁けなくなる）。

## 決まり 3 — 既定値で続けたら 1 行言う

何も知らせずに既定値へ替えると「絵だけ別物」「保存したのに効かない」の原因が追えない。

- **常駐プロセス（ゲーム / GL / Studio）は stderr。** stdout は描き出しのログが使うので混ぜない
- **CLI の描き出し（engine_tools / headless）は stdout でよい。** そこでは stdout がログそのもの
- **無い ≠ 読めない。** 任意 Doc の不在は正常系なので何も知らせず既定値でよい。
  ファイルが有るのに読めないときだけ言う（`IoError` の `ErrorKind.NotFound` で分ける）
- **毎フレーム通る経路では出さない。** 名前ごとに初回 1 回だけ（`Ref[Set[String]]` に見た名前を貯める）

文面はそろえる: `<領域> fail-open: <path> を<既定値の名前>に替えました — <理由>`

**自分で `System.err.println` を呼ばない。`Log.fellBack(領域, 対象, 既定値の名前, 理由)` を呼ぶ**
（engine/src/core/Log.flix）。定型に収まらない 1 行だけ `Log.warn` を使う。効果は `Log` の中で
`unsafe IO` に隠してあるので、知らせるために呼ぶ側の効果行が広がることはない。

**戻り値が純粋な `Unit` なので、値を捨てると知らせごと消える。** Flix は純粋な式の値を
`let _ =` で捨てるとコード生成で式ごと消し、純粋な関数を渡した `List.forEach` の中の呼び出しも消す
（どちらも型検査は通り、実行しても何も出ない）。書き方は呼ぶ場所で決まる:

| 呼ぶ場所 | 書き方 |
|---|---|
| 純粋な関数の中（読み込み・decode） | `Log.fellBackThen(領域, 対象, 既定値の名前, 理由, 返す値)` / `Log.warnThen(行, 返す値)` |
| 純粋な関数の中で何件も | 行を `List.map` で集めて `Log.warnAllThen(行の列, 返す値)`（定型文は `Log.fellBackLine`） |
| 効果のある関数（`\ IO` など）の中 | 式の値として置く（末尾に `Log.warn(..)`・`if` の枝・`match` の枝） |
| 関数で渡された知らせ（`ViewCtx#warnOnce`） | `match ctx#warnOnce(行) { case () => 続き }` |

`let _ = Log.warn(..);` は `bin/fge value-discard` が保存時とコミット時に止める
（`let _ =` は全部止まる。効果のある式を捨てるのは `discard 式;` で、こちらは純粋な式に使うと Flix が止める）。

## 決まり 4 — `Err` の中身の型

- JSON / Doc 由来 → `Util.Json.JsonError`
- それ以外（glob 失敗・パッキング破綻など JSON でない失敗）→ `String`

**新しいエラー型は作らない。** Flix に `must_use` は無いので、専用の型にしても握り潰しはコンパイル
エラーにならない。呼ぶ側が捌く型の種類が増えるだけになる。
