# engine 0.76.0 → 0.77.0 の手当て

コア設計の仕上げ（`plans/engine-core-polish.md`）の C0 と C1 をこの版に入れる。C0 は基準・dt を固定する口・CPU の速さを測る口、C1 は小さな直し（材質の鍵・`Num`・光の上限の知らせ・`App.emptyFrame`）。

**版を固定しているゲームへ**: `flix.toml` の engine が 0.76 より前のゲームは、この版へ上げる時に間の版の移行メモもまとめて要る。
手当て前のまま 0.76 を当てると止まるのは fps3d_lab（0.74.0）・Studio の server（0.37.0）・internet_dungeon（0.70.0）で、
どれも 0.76.0 までの移行メモの「ゲームで直す物」で直る（`Scene3d.SpotLight` の `innerFovY`・`SoftRaster.RasterReq` の `scenes`・
`App.Frame` の `mouseDelta` / `windowFocused` / `diagnostics`・`Render.Item.Scene3d` の case）。直した形は
`bench/baseline/0.76.0/upgrade/<ゲーム>.patch` にある（`make check-external` が写しへ当てて、7 本とも通るのを基準にした）。

## C0: 基準・dt を固定する口・CPU の速さを測る口

新しい環境変数を置かないゲームの絵と振る舞いは 1 bit も変わらない（空の値の撮る口の扱いだけ下の「振る舞いが変わる物」。gl-parity の全部の行で GL と CPU の絵の SHA-256 が 0.76.0 と同じ・
テンプレートの reference-check の結果が 0.76.0 と同じ顔ぶれ）。

### ゲームで直す物

無い。

### 振る舞いが変わる物

- 実機の窓は、起動の頭で自分の `FLIX_GE_*`（HIDDEN・MUTE・FRAME_STATS・FRAME_SHOT・SPLASH_SHOT・FIXED_DT）を 1 回だけ読む
  （前は `FLIX_GE_FRAME_SHOT`・`FLIX_GE_SPLASH_SHOT` を書くたびに読んでいた）。走っている途中で環境変数を変えることはできないので、見える違いは無い
- `FLIX_GE_FRAME_SHOT=`・`FLIX_GE_SPLASH_SHOT=`（空の値）は置いていないのと同じになった（前はファイルシステムの根 `/` の `frame-1.png` へ書きにいった）

### 足した物（使わなければ何も変わらない）

- `FLIX_GE_FIXED_DT=<秒>`（`0.016`・`1/60`）: 実機の毎コマの dt を実時間の代わりにその値にする（`maxDeltaTime` で切る）。
  `FLIX_GE_HIDDEN`・`FLIX_GE_FRAME_SHOT`・`START` と組んで、同じ場面を 2 回撮れば 2 コマ目以降もバイトで比べられる。
  置いていなければ何も変わらない。読めない値は実時間のまま続けて 1 行知らせる（`docs/flow.md` の「実機の dt を固定する」）
- CPU の速さを測る口: `CpuTiming.measure({ warmup, runs }, 仕事)`（`(まとめ, 最後の回の値)` を返す）・`CpuTiming.summarize`（`Nel` の時間から中央値・最小・最大）・
  `HeadlessRender.renderImageFull(cfg, scene)`・`renderImageSoft(cfg, soft)`（renderPngFull と同じ塗りで、描き出しのキャッシュを通さず 1 枚描いた画像を返す）（`docs/performance.md` の §5）
- engine の開発の口（ゲームには配らない）:
  - `make gl-capture OUT=<フォルダ>`・`make gl-capture-check`（`bin/gl-capture.sh`。テンプレの場面と bench/scene3d を実機の GL で撮り比べる）
  - `make scene3d-cpu`（3D の部屋を CPU で温めてから何回か描き、1 枚の時間の中央値）・`make gl-parity-cpu`（gl-parity の場面ごとの同じ値）
  - `make check-external`（`bin/check-external.sh`。外のゲームの写しを今の engine で型検査し、基準から増えたエラーだけ出す。ゲームのフォルダは汚さない）
  - engine_tools のテスト `TestSoftRaster3dPinned`（3D の CPU の絵の画素の SHA-256 を 2 枚固定）
  - `make baseline-check [GALLERY=1]`（`bin/baseline-check.sh`。gl-parity の行と絵・3D の部屋の CPU の絵・テンプレの gallery を基準と比べる）
  - 基準の控え `bench/baseline/0.76.0/`（gl-parity の差の数と絵の SHA・撮り比べの SHA・3D の CPU の絵と時間・gl-parity の場面ごとの CPU の時間・テンプレの reference と gallery の SHA・外のゲームの型検査（と上げた写しの patch）。`docs/backend-parity.md` の「基準」）

### 気をつける事

- `make scene3d-still` が出していた描く時間は消した。2 回目からは描き出しのキャッシュが写すだけの回があり、速さの比べに使えなかった。時間は `make scene3d-cpu` で測る

## C1: 材質の鍵を中身から・数の関数を Num へ・落とした光を数える・App.emptyFrame

絵は 1 bit も変わらない（gl-parity の全部の行・3D の部屋の CPU の絵の SHA・実機の撮り比べが C0 の基準と同じ）。

### ゲームで直す物

- 字で `FrameDiagnostics.Scene3dCounts`（`{ instances = .., drawn = .., drawCalls = .. }`）を組んでいる所は、欄が 2 つ増えたので
  `{ instances = .., drawn = .., drawCalls = .. | FrameDiagnostics.emptyScene3dCounts() }` に替える（テストで診断の行を作る所だけのはず）
- 字で `Scene3d.MaterialFields` の欄を全部パターンで開いている所（`case { spec = .., …, doubleSided = .. } =>`）は、`shaderHash = _` を足す
  （engine の外では見当たらない）

### 振る舞いが変わる物

- GL は材質のプログラムを spec の名前ではなく **spec と emission の中身の鍵**で引く（`ShaderGen.hashMaterial`。読む絵の名前は入れない）。
  同じ名前で木の違う材質（emission の mask だけ違う部品など）が並んでも、毎コマ組み直さない。前は「中身の違う材質が同じ名前 … で同じコマに来た」と
  知らせて組み直していた。読む絵の名前だけが違う材質は 1 つのプログラムを共有する（spec の名前が違えば今までどおり別）
- 鍵は木の数（`Const`・色）も含むので、View で木の数を毎コマ変える材質（明滅の色を emission の `Solid` に入れるなど）は毎コマ新しいプログラムを組む
  （前は同じ名前のまま組み直して知らせていた）。30 コマ続くと 1 回知らせる。毎コマ変わる数は ShaderDoc の `param` にして `Scene3d.withParams` で渡す
  （使わないプログラムは今までどおり数の上限で追い出す）
- `Scene3d.withSpecName` は名前を替えるだけの口になった（知らせの文面・GL のプログラムの名前に出る）。鍵の衝突を避けるために名前を分ける必要は無い。
  night_apartment の `Stage.renamed` のような「emission を足した材質に別の名前を付ける」手当ては要らなくなった（残しても害は無い）
- 3D の場面で点光源が 8 本・スポットが 2 本を超えると、種類ごとに初めての時に 1 回だけ知らせる（GL と CPU の描き出しで同じ文面）。選び方（目に近い順）は変わらない

### 足した物（使わなければ何も変わらない）

- `Num.sqrt`・`Num.sin`・`Num.cos`・`Num.atan2`・`Num.pi`・`Num.tau`（値は `Vec2` の同じ名前と同じ）
- `App.emptyFrame()`: 全部の欄が既定の `App.Frame`。テストや台本では `{ down = Set#{Key.Space}, justPressed = Set#{Key.Space}, dt = 0.016 | App.emptyFrame() }` の形で組む
- `FrameDiagnostics.Scene3dCounts` の `droppedPointLights`・`droppedSpotLights`（`Scene3d.pickLights` が落とした光の数。`summaryLines` の 3D の行の末尾に出る）・
  `FrameDiagnostics.emptyScene3dCounts()`
- `Scene3d.droppedLightsOf(cmd)`・`Scene3d.droppedLightsWarnings(cmd)`（落とす光の数と知らせの行。GL と CPU の描き手が使う）
- `ShaderGen.hashMaterial(spec, emission)`（材質の中身の鍵。`eqMaterial` が真なら同じ値）
- lint-forbid の規則の `notice`（真なら当たりを知らせるだけで止めない）と、その形の規則 2 つ:
  - `num-from-vec2`: `Vec2.sqrt`・`sin`・`cos`・`atan2`・`pi`・`tau` を `Num.*` へ
  - `frame-literal`: `App.Frame` を字で全部の欄を書く所を `App.emptyFrame()` の更新へ（見つけるのは `padKind = PadKind.Unknown` が `|` の無い行にある所だけ。
    `padKind` を書かない古い版の字のレコードは拾わない）

### 旧い名前（0.84.0 で消える）

- `Vec2.sqrt`・`Vec2.sin`・`Vec2.cos`・`Vec2.atan2`・`Vec2.pi`・`Vec2.tau` → `Num` の同じ名前。中身は `Num` を呼ぶだけで、値は同じ。
  外のゲームで約 240 か所あるので、0.84.0 までの間に置き換える（`bin/fge forbid --all` が `num-from-vec2` の知らせで場所を出す。
  置き換えは `bin/fge refactor rewrite --from 'Vec2.sqrt($x)' --to 'Num.sqrt($x)'` のような形でまとめて書き替えられる）。
  engine を `mount = "fge"` で入れているゲームは、`use fge::{…, Vec2}` の並びに `Num` も足す（足さないと `Undefined name 'Num.sqrt'`）
- 字で全部の欄を書いた `App.Frame` は今も通るが、次の版で `Frame` に `mouseButtons` などの欄が増えるとコンパイルが止まる。
  今のうちに `App.emptyFrame()` の更新へ替える（`frame-literal` の知らせが場所を出す）

### 気をつける事

- 材質を View で毎コマ作り直すゲーム（fps3d_lab の炎・扉の材質、night_apartment の既定の材質）は、GL で描く時に材質ごとに鍵を 1 回求める
  （木を 1 回たどる。前の名前の比べで木を比べていたのと同じ程度）。CPU の描き出しは鍵を読まないので払わない。気になるなら材質は読み込みで 1 回作って World や Resources に持つ
- templates/ の 4 本は engine 0.76.0 を固定しているので、`Vec2.sin` などはまだ替えていない（`Num` が無い）。0.77.0 を出した後、templates を 0.77.0 に上げる時に
  `refactor rewrite` で `Num` へ替える（それまで `make new-game` で作ったゲームは `num-from-vec2` の知らせが出る）
- lint-forbid の `notice` は新しい `bin/fge-go` が読む。古い `fge-go` は `notice` を知らずに止めるので、forbid.json と一緒に配り直す（`make sync-agents`）
