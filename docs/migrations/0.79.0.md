# engine 0.78.0 → 0.79.0 の手当て

3D の色を線形の量で計算する（`plans/engine-round8-linear-color.md`）。**3D の場面の絵は全部変わる。2D の絵は 1 画素も変わらない**
（gl-parity の 2D の行と CPU の絵・テンプレの実機の絵〔gl-capture の 2D の 8 場面〕・テンプレの gallery が 0.78 と同じ）。

## 戻し方（0.83 まで。0.84.0 で消える）

ゲームのフォルダの `project.json` に `"scene3dLinearColor": false` と書くと、3D も 0.78 と同じ式（画素の値のまま光を足し掛けする）で描く。
CPU の絵は 0.78 とバイトまで同じに戻る（bench と night_apartment で確かめた）。GL はシェーダーの字が変わったので GPU によっては ±1 ずれうる
（手元の Apple M4 Pro では gl-parity の行・GL の絵・実機の部屋の絵が 0.78 とバイトまで同じだった）。

- JVM の中で 1 回だけ読む。旗を変えたら起動し直す（`make run` の窓・常駐の描き出し・Studio から走らせたゲームも）
- 偽を読むと起動の時に 1 行知らせる。描き出しのキャッシュの鍵も偽の時だけ、3D の場面を含むコマだけ変わる（2D だけのコマの鍵は変わらない）
- **0.80.0 で消える**。それまでに下の合わせ直しを済ませる

## 振る舞いが変わる物

書く値（材質の Spec・`withTint`・頂点の色・光の `color`・`ambient`・かすみ・空・絵）の意味は今までどおり画面の値（sRGB の値）。
描き手が 3D の中だけ線形の量へ戻して光を足し掛けし、色を作った直後に画面の値へ戻す。詳しくは `docs/scene3d.md` の「3D の色」。

測った変わり方（同じ値のまま 0.79 で描いた時。明るさは画素の平均の Y・0〜255）:

| 場面 | 0.78 | 0.79 | 何が効いたか |
|---|---|---|---|
| bench/scene3d の部屋（暗い ambient 0.16 + hemisphere 0.25 + 暖色の松明 4 本） | 84.5 | 69.9 | 暗い ambient が線形で 0.02 まで沈む・暖色の光の緑と青が下がる |
| night_apartment（7 場面のうち 3D の 6 場面） | 35〜84 | 34〜78 | 自販機の前（vending）が −6・ほかは −1 前後。lightmap の面はほとんど変わらない |
| gl-parity の空（skyGradient3d） | 122 | 140 | 空の混ぜが明るい方へ寄る |
| gl-parity のスポットの床（spotShadow） | 84 | 98 | 光の届く端が広く明るくなる |
| lightmap だけの面・白い環境光だけの面（lightmapBaked3d・depthRed など） | — | ±1 | ほとんど変わらない |

## ゲームで直す物（合わせ直しの目安）

- 暗い `ambient`（0.1〜0.2）は線形では約 1/7 に沈む。0.78 の暗さに近づけるなら、ambient を少し上げるか `hemisphere` で足す
  （`hemisphere` は線形の量なので、同じ値の ambient より明るく効く）
- 点光源・スポットの `intensity` と `range` は線形の量のまま掛かり、画面では約 1/2.2 乗で効く。光の届く端が広く明るくなるので、下げる方から試す。
  暖色の光の `color`（1.0, 0.72, 0.42 など）は緑と青が線形で大きく下がるので、色味が濃く・暗く見える
- かすみと空の混ぜは明るい方へ寄る。`toonSteps` の段は線形の光で切るので、段の明るさの並びが変わる
- スポットの影の `strength` も光の量に掛かるので、影が薄く見える方へ変わる
- `Spec` の emission・`withTint`・頂点の色・光の color に 1 を超える値（光る看板・ヒットの白飛ばし）を書いた所は、線形へ戻すと 1 次より強く伸びる
  （2.0 → 約 4.95）。明るさは `Scene3d.withEmissionIntensity(k, m)`（線形の倍率）へ移す
- glb の emissive: `KHR_materials_emissive_strength`（Blender の強さ 40）は `emissionIntensity` として線形の倍率で効く（0.78 の明るすぎが直る）。
  spec の名前に入るのは `emissiveFactor` だけになった（`gltf:tex:Nearest:etNearest(2.0,2.0,2.0)` だった物は `etNearest(1.0,1.0,1.0)` など）。
  名前で材質を選んでいた所は直す。glb の材質の emission を `Scene3d.withEmission` で差し替えると `emissionIntensity`（40 など）は残るので、
  戻すなら `Scene3d.withEmissionIntensity(1.0, ..)` も当てる。`Scene3d.materialFieldsOf` の欄から材質を組み直す所（night_apartment の `Stage.renamed`）は、
  `emissionIntensity` を `Scene3d.withEmissionIntensity` で写さないと強さが 1 に戻る
- HDR の Pass では出口が 1 を超える値を切らないが、sRGB の曲線で縮める（線形の 40 → 画面の値 約 4.85。0.78 は 40 のまま）。ブルームのしきい値とトーンマップを合わせ直す
- lightmap の露出は `intensity` に入れたまま（線形の倍率なので正しい）。`exposureStops` へは移さない
- 材質の絵の段（mip）は色の絵として線形の量で平均する。mask・ノイズの絵を材質に貼った所は、遠くの段の値が少し変わる
- 合わせ直しが要るのは Scene3d を使うゲーム（night_apartment: look.json・lights.json・lightmap の intensity・emission／fps3d_lab: look.json 4 本・RoomView の定数）

## 足した物（使わなければ 0.78 と同じ値）

- `Scene3d.withEmissionIntensity(k, m)` と `MaterialFields.emissionIntensity`（既定 1）。`Scene3d.withoutEmission` は 1 に戻す
- `Texture3d.srgbToLinearColor`・`Texture3d.TextureUse`・`Texture3d.mipSpaceOf`・`Texture3d.mipAverageOf`・表の版の変換 `Texture3d.colorLut` / `srgbToLinearLut` / `linearToSrgbLut`
- `Mip.Average`（`SrgbCurve` / `Raw`）。`Mip.build` は第 1 引数に平均の仕方を取る（engine の外の呼び手は無い）
- engine の中だけの API（0.84.0 で消える）: `ProjectLoader.scene3dLinearColorOf`・`GameEngine.loadScene3dLinearColor`・`LightModel3d.ScalarInput.LinearColor`・
  `SoftRaster3d.drawScene` / `drawSceneHdr` の `linear`（`RenderPaint.create` の cfg の `scene3dLinearColor` と `Render3d.fresh` の第 2 引数は、0.80.0 で `Render3d.makeRenderer` へ移った）
- `SoftRaster3d.drawScene` / `drawSceneHdr` の絵の引数は `(名前, Texture3d.ColorSpace) → 段の列` になった（鍵の色空間は `SoftRaster.mipKeySpace`）。
  `Render3d.Material.resolveTextureAs` は `Texture3d.TextureUse` を取る
