# engine 0.67.0 → 0.68.0 の手当て

シェーダー面の濃さを Spec の外（uniform `uAlpha`）へ出し、`Render.fade` がシェーダー面にも効くようにした。
濃さを Spec の定数に書くと、濃さが変わるたびに別のシェーダーとして作り直す（移動中に毎コマ数回の
GLSL のコンパイルとリンク）。あわせて、同じ名前で作り直した古いシェーダーを GPU から消すようにした。
DEBUG で遊ぶと、重いコマの前後を `debug/perf/hitches/` へ書き出す（[performance.md](../performance.md) §11）。

## ゲームで直す物

**ほとんどのゲームは無い。** 次に当たるゲームだけ直す:

1. **`GameEngine.Game` を自前の handler で受けている所**は、op を 2 つ足す:
   `def setDiagnosticsEnabled(_on, k) = k()` と `def consumeDiagnostics(_, k) = k(FrameDiagnostics.empty())`。
2. **`ShaderEffect.ShaderRenderCmd` か `Render.Item.Shader` を record の字面で組んでいる所**は、`alpha = 1.0` を足す
   （`Render.shaderFill` / `shaderFillMasked` で作っている所と、`{ zIndex = … | x }` のような書き換えは直さなくてよい）。

## 直すと速くなる物

- **時間で濃さが変わるシェーダー面を、Spec の alpha の式へ濃さの定数を書き込んで作り直している所**は、
  Spec は固定のまま `Render.overItem(Render.fade(k), Render.shaderFill(...))` にする。
  ヒッチの記録（`hitch.md`）に同じ名前のシェーダーが「中身が違う」理由で毎コマ並ぶなら、これに当たる。

## 変わったこと

- DEBUG で起動すると、予算（16.67ms）を超えたコマとシェーダーを作ったコマを拾い、前後のコマの表と推定原因を
  `debug/perf/hitches/<起動時刻>/f<コマ>/hitch.md` へ書く。`make status` にも出る。
- `POST /perf?path=<flow>&last=N` で、同じ手を流して最後の N コマだけを本物の GL で塗り、前後を数で比べられる。
- `FLIX_GE_MUTE=1` で音を消して起動できる。
