# engine 0.52.0 → 0.52.1 の手当て

自動生成の一覧は [0.52.1.auto.md](0.52.1.auto.md)（直す物 0 件）。

headless-run の jar の作り直しの直し（jarfix）。ゲームで直す物は無い。

1. **版を上げた直後に jar を 2 回作らない**: 0.52.0 までは、jar.manifest に作り始めの指紋を書いていた。版を上げた直後の 1 回目は、
   jar を作っている間に flix が lib へ新しい版の fpkg と toml を落とすので、次の呼び出しで指紋がずれて 1 から作り直していた
   （依頼主の Mac・internet_dungeon で再現: 0.52.0 の headless-run は 2 回続けて流すと 2 回とも作る）。
   今は、作り終えた後に jar を作った写し（build/headless/proj: 作り始めに写した src・flix.toml・ゲームの lib）から指紋を取る。
   作っている最中に保存した src は、今までどおり次の回に「jar と違う」と気づく。ゲームに lib が無ければ作ってから繋ぐ。
2. **lib に残る古い版を指紋に入れない**: lib/github/<持ち主>/<名前>/ の下は、flix.toml か packages.lock に名前のある版の
   フォルダの中だけを見る（版を上げた後に 0.35〜0.51 が 13 個残っていた。消す・取り直すだけで作り直さない）。
3. **jar を作った秒数**: 作り終えたら「[headless-run] jar を作った（N 秒）」を出し、N（秒の整数と改行 1 つ）を
   build/headless/last-build-seconds に残す（Studio が「jar を作っています」の見込みに前回の秒数を出す）。鍵 build/headless/.lock/pid の形は同じ。

指紋の決め方が変わるので、0.52.1 に上げた後の最初の描き出しで 1 回だけ jar を作り直す。

確かめ（internet_dungeon・lib から 0.52.0 を消して版を上げた直後を作り、古い版 3 つを置いた）: 1 回目は 87 秒で作り、
2 回目は作らない。Studio 相当（JAVA・HEADLESS_JAVA_OPTS=-Xmx1g）と端末相当を交互に 4 回流しても作らない。
古い版のフォルダ・版のフォルダの外のファイルを足し引きしても `--status` は fresh のまま。
