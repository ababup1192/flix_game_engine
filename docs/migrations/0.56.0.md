# engine 0.55.1 → 0.56.0 の手当て（下書き・版はまだ出していない）

自動生成の一覧（0.56.0.auto.md）は版を出す時に作る。Flix の pub は変わらない（Go の道具と `mk/game.mk` と
`bin/lint-rules/hooks.json` だけ）。

minor を上げるのは、**`make check` の既定の道が変わる**ため（下の 1）。

## 1. `make check` は flixlint の常駐へ（repl の常駐を消した・C-3）

- **何が変わるか**: `make check` は `bin/fge checkd` を通り、check を flixlint の常駐（lint・`bin/fge refactor` の索引と同じ JVM）に
  頼む。変わったソースだけを渡し、答えの版（src/・test/ の .flix と flix.toml・packages.lock の中身から作る値）をディスクと
  比べて使う。internet_dungeon で 1 行変えた後の `make check` は中央値 15.15 秒（repl の常駐）→ 5.11 秒。
  0.55 で `CHECKD_BACKEND=server` で選べた道が既定になり、repl の常駐（とファイルの監視の待ち・repl のヒープと RSS の予算・
  pid で落とす歯止め）は無くなった。
- **常駐が使えない時**: `hooks.json` に `checkd.server` が無い・`CHECKD_BACKEND=cli`・`CHECKD=0 make check` は素の `flix check`。
  常駐が答えない・壊れている時は 1 回だけ起こし直し、それでも駄目なら黙って素の check に落ちる。
- **`make test` はいつも素の `flix test`**（`-Djava.awt.headless=true`）。`CHECKD=1` の test の分かれ道は消した
  （テストはゲームのコードを動かすので常駐に入れない。測りと決めは flixlint の `docs/design/checkd-freshness.md` の C-T）。
- **止め方**: `bin/fge checkd --stop [dir]` は記録の常駐に kind stop を頼む（lint・refactor の索引も同じ常駐なので一緒に止まる）。
  `make checkd-stop`（`--stop-all`）は記録の全部。
- **hooks.json**: repl だけの欄（`pingTimeoutSec`・`heapMinMB`・`idleSec`・`idleEnvVar`・`maxChecks`・`settleSec`・
  `warmTimeoutSec`・`convTimeoutSec`・`rssLimit` の `minMB`／`maxMB`／`fallbackMB`／`floorMB`・`skipDirs`・`depSuffixes`）を
  消した。0.55 の hooks.json のままでも読める（知らない欄は読まない）ので、sync-agents の前後どちらでも動く。
- **Flix の版**: 常駐と `make check` が使う flix.jar は flix.toml の版（0.78.0）の物。PATH の flix が古い（devbox の 0.77 など）と
  素の check は「Please upgrade to Flix 0.78.0」で落ちる（常駐の道は jar を自分で選ぶ。下の 2 の refactor と同じ）。

## 追随の手順

1. **flix.toml の engine の版を 0.56.0 にし、`make sync-agents`**（`mk/game.mk`・`bin/lint-rules/hooks.json`・`bin/fge-go` を受け取る）。
2. `make check` を 2 回流す。1 回目は常駐を起こす（internet_dungeon の master の写しで 10 秒）、2 回目は 1 秒ほど。
   `~/.cache/flix-checkd/<ハッシュ>/daemon.log` の最後の行が `check via=server` なら常駐の道。
3. ゲームの Makefile・CI で `CHECKD=1 make test` を使っていたら `make test` にする（同じ物になった）。
4. `hooks.json` の `checkd.server` は flixlint 0.8.5（shim の jar は初回の `make check` が取る）。ゲームの submodule の flixlint は
   上げなくてよい（check の常駐は hooks.json の版の shim を使う。lint の版はゲームが決める）。

## 2. `bin/fge refactor` に足した物

- **`rename --def Mod.f --to g`**: 宣言・使う所（`Mod.f` も `f` も）・use の中の名前の、書いた名前の最後の区切りだけを替える。
  use の別名とそれを書いた所は替えない。同じ mod に g があれば止める。.flix のコメント・文字列に字で残る所は場所を並べる。
- **`safe-delete --def Mod.f`**: 参照をテストから・同じ mod の中から・外の mod からに数え分け、同じ mod の中と外から 0 の時だけ
  remove-dead に回す。そうでなければ使い手の内訳を並べて止める。
- **`change-signature --propagate [--stop-at A.f,B.g] [--depth N]`**: `--args '@res, w'` の `@res` を束ねていない呼ぶ所は、
  囲む def にも同じ引数を足して上へ広げる（葉と同じ先頭か末尾・既定の深さ 8）。型の値をもう持つ def（同じ型の引数 `r`・
  欄に持つ `env#res`）へは広げずにその式を書く。止める所は `--stop-at`・main・@Test・引数の無い def・戻り値が App の def。
  - **`--args '@res=<式>'`**: 本体の中のその式を res に替え、止めた所には fix の代わりに式を書く（`--propagate` 無しでも使える）。
  - **先頭に足すだけの時は、パイプ・部分適用・関数として渡す所にも書く**: `x |> f(a)` → `x |> f(res, a)`・`List.map(f, xs)` →
    `List.map(f(res), xs)`（Flix の関数は前から部分適用できる）。前はどれも人へ回していた。
  - 報告: 上へ広げた def を深さの順に・止めた def を訳の種類ごとに・型の値を持つ def と書く式。
- **`move-fields --labels a,b --receiver World --into-case E.C`**（2 段）: 写す段は payload（`case C(CUi)` の alias か
  `case C({ … })`）の型と組み立てに欄を足す（値は `--value-of` か World の組み立ての式。別の mod では mod を付けて書く）。
  口の中身を payload を読む形に人が直した後、`--finish` で直の読み書きが 0 なら World の型と組み立てからまとめて消す。
- **flix.jar を flix.toml の版に合わせる**: 見つけた jar（設定・FLIX_JAR・常駐の jar・engine の bin/flix.jar・PATH の flix）の版が
  違えば、nix の store と Studio の engines から同じ版の jar を探して使い、`--apply` の後の make check にも FLIX_JAR で渡す。
  見つからなければ、索引が落ちた時に「使っている flix は X（パス）・要るのは Y。FLIX_JAR=… を前に置く」を出す
  （前は「flixlint が古い」と読める訳だった）。
- 細かい物: `--params` の型の名前が引けなければ警告・`remove-field` が止まった時も組み立ての数を 1 行・`use-engine` で fpkg が
  無い時の案内・`remove-field --case` は flixlint の新しい case の受け手（`via=case`）も数える。

## 直した不具合

- **型の別名を変えた後、常駐の `make check` が触っていないファイルで落ちた**（worldshape・0.55 の `CHECKD_BACKEND=server` でも同じ）:
  `Res` のような record の別名に欄を足すと、それを受ける def を呼ぶ触っていないファイルごとに「Extra label <欄>」が出た
  （素の `flix check` は通り、`bin/fge checkd --stop .` で直った）。常駐は変わったファイルだけをコンパイラに渡し、Flix 0.78 の
  増分の compile が別名を引数の型にだけ使うファイルを型付けし直さないため。flixlint 0.8.5 の常駐は、変わったファイルの別名の
  宣言が前と違えばコンパイラのキャッシュを捨ててから渡す（`hooks.json` の `checkd.server` を 0.8.5 にした）。

- **change-signature が Unit の値 `()` を引数へ替えた**（worldshape の E2-1）: `type alias Res = Unit` で `resOf(w)` の本体が `()` の時、
  `--args` に `ViewEnv.resOf(w)` を書くと、本体の中の値の `()` まで新しい引数の名前に替わった。名前を含まない式（`()`・数・
  true／false）は本体から引数へ移す対象にしない。
- **change-signature が別の lambda の名前を使った**（worldshape の E2-2）: 呼ぶ所の局所の名前が束ねてあるかを、囲む def の頭から
  呼ぶ所までの字で見ていたので、前にある `(res, w) -> …` の res を、後ろの `Resources.read((_, w) -> f(w))` の中でも使えると
  見て `f(res, w)` と書いた。lambda の引数は、呼ぶ所がその lambda の本体の中にある時だけ束ねていると見る。呼ぶ所を囲む lambda の
  引数に `_` がある時は、その `_` に値が来ることが多いが道具はどの `_` かを決めず、「_ を res に替えてから流し直す」で人へ回す
  （--propagate もそこからは上へ広げない）。
- **`--prefer-local` が `_` で始まる名前を選んだ**: Flix は `_res` を使うと「Hidden variable symbol」で止めるので、`_` の名前は
  候補にも、`--propagate` の「型の値を持つ引数」にもしない。

## 新しく使える物

上の 2 の道具だけ（Flix のコードから呼ぶ物は無い）。
