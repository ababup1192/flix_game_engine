## 1. refactor が instance の中の呼び出しを数える（flixlint 0.8.8・索引の adds に inst）

- **何が変わるか**: flixlint の索引（`--spans`）が、ソースに書いた `instance` の def と、その本体の中の呼び出し・参照を出す。
  前は instance の def が本体ごと抜けていて、instance の中からしか呼ばれない def が `usages` で「src 0」、
  `usages --unused` で「テストからだけ」に見え、`remove-dead --with-tests` がテストごと消して壊す道があった
  （internet_dungeon の `Save.parse`）。
- **instance の def の名前**: `<instance の在る mod>.<def の名前>`（`Save.fromJson`）。同じ mod に同じ名前の def が在る時だけ
  コンパイラの番号付きの名前（`Save.fromJson$4521`）になる。`with Eq` などで作られる instance の def は入らない。
- **止まるようになった物**
  - usages・refs・remove-dead・safe-delete・make-private・rename・move・change-signature・remove-param は、索引の頭の行に
    `adds=inst` が無い（flixlint 0.8.7 以前の）索引では、作る前に「flixlint を 0.8.8 以上へ上げる」で止める。
  - rename・change-signature（`--propagate` を含む）・remove-param・retarget-field は instance の def を書き換えない
    （名前と引数は trait の sig が決める）。`--propagate` は instance の def で広げるのを止め、訳を出す。
- **hooks.json**: check の常駐（`checkd.server`）の flixlint を 0.8.8 へ上げた（`shimSha256` も）。上げ忘れは go test
  （`TestHooksPinReachesMinFlixlint`）で止まる。
