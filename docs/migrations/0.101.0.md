# engine 0.100.1 → 0.101.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## 画面全体の後がけを値の束で言う（`App.withPostStack`・`PostStack`）

3D の場面のトーンマップ・ブルーム・ビネット・奥行きのぼかし・FXAA を、Pass を手で並べずに値の束 1 つで言えるようになった。
今の手書きの後がけ（`PostView` と `App.withPassPlan`）はそのまま動く。移すかはそのゲームを触る時に決める（強制しない）。

| 何が | どう |
|---|---|
| 口 | `App.withPostStack(w -> PostStack.preset(PostStack.Preset.DuskOutdoor) \|> PostStack.withExposure(-0.3))`。View は場面を返すだけ |
| 掛かる範囲 | View（と視差レイヤ）が返す絵の全部。`App.withHudView` とデバッグの重ねには掛からない。会話の窓・メニュー・字幕を View に描いているゲームは、移す時にそれを `App.withHudView` へ移す |
| Doc | `assets/post.json`（schema は engine の `docs/post.schema.json`・`editor.resources[]` から指す）を `PostStack.loadOr(出発点, "assets/post.json")` で読む。preset が出発点で、書いた欄だけが上書き |
| 今の見え方のまま移す | `withViewTransform(PostStack.ViewTransform.AcesNarkowicz({ whitePoint = 4.0, saturationAfter = 彩度 }))`・奥行きのぼかしは `DepthOfField.DepthBand({ focusDistance = 目から主人公まで, range = 帯の半分, band, soft, blur })`・読む点と縮みは `Quality.Fixed({ bloomTaps, bloomScale, blurTaps })`（縮みは design の解像度に対して）。lamplighter の後がけはこの形で CPU・WebGPU・GL とも 0 px で移せた |
| 奥行きの絵 | PostStack が View の絵の中の 3D の場面から作る（同じ場面を `Scene3d.Output.Depth` で 2 回組まない）。3D の場面が 2 つ以上なら一番大きい物から作って 1 回知らせる |
| Pass の名前 | `ps_` で始まる（`ps_scene`・`ps_depth`・`ps_soft`・`ps_bright`・`ps_bloomA`・`ps_bloomB`・`ps_post`）。`App.withPassPlan` の Pass と名前が重なると後がけを掛けずに 1 行知らせる |
| 描き出し | App を使うゲームは `App.buildFrame(app, design, ctx, world, view)` が実機と同じ計画と絵を返す（`Render.passSpecsOf` に計画を渡す）。App を通さない並びは `PostStack.build` |
| 毎コマ動かす数 | 露出・ブルームの強さ・ビネットの強さ・彩度は Param で渡るので、毎コマ変えても描き手は program を作り直さない |

## view transform を Blender にそろえる（Standard・KhronosNeutral）

| 何が | どう |
|---|---|
| `PostStack.ViewTransform.Standard`・`KhronosNeutral` | 場面の Pass の値（画面の値）を読む所で線形へ戻し、ブルーム・色の仕上げ・ビネット・露出を線形の値に掛けてから、曲線と sRGB の曲線で表示の値にする（Blender の Color Management と同じ順と式）。帯の絵（明るさ 2^-8〜2^4 × 色相 12 × 彩度 3）で Blender 5.2.3 と 2/255 以内（`TestPostStackBlender`） |
| `AcesNarkowicz` | 今までどおり画面の値のまま掛ける（今の見え方を残す互換・Blender の門の外） |
| 奥行きのぼかし（Standard・KhronosNeutral） | 線形へ戻した場面の Pass（`ps_linear`・窓の画素）を 1 枚足してからぼかす |
| `AgX` | 自前の式（Rec.2020 の inset・log2 で 16.5 stop・S 字の曲線・outset）。Look は Base だけ。Blender 5.2.3 の AgX と、灰色は 2/255 以内・全部の 83〜89% が 2/255 以内・最大 18/255（彩度 1 の原色の緑と青） |
| Filmic | 入れていない（Blender の Filmic は LUT で作られ、自前で組む元になる公開の式が無い） |
| ShaderDoc の `math1` | `log2` を足した（AgX が明るさを stop にする） |

## ビルボードの太陽の影・アトラスの mip の上限（HD-2D の下準備）

どれも足しただけで、既定の絵は変わらない（直す所は無い）。使い方は `docs/scene3d.md` の「ビルボードの影」「ドット絵のアトラスを貼る」「ビルボードを画素にそろえる」。

| 物 | 何に使う |
|---|---|
| `Scene3d.withCastShadows(true, b)` | ビルボードを太陽の影の地図に描く（絵の形の影が太陽の向きに伸びる） |
| `Scene3d.withReceiveShadows(true, b)` | ビルボード（lit）が太陽の影を受ける（建物の影に入ると暗くなる） |
| `Scene3d.billboardShadowRightOf`・`billboardShadowPointOf`・`billboardShadowOffsetOf`・`shadowCastingBillboardsOf` | 描き手 3 つ（GL・WebGPU・CPU）が同じ式で読む部品 |
| `Scene3d.withMaxMipLevels(n, 材質)`・`Scene3d.atlasMipLevelsFor(タイルの px)`・`materialMipLevelsOf` | アトラスを貼った材質が遠くで隣のタイルを混ぜないように mip のレベルの数を止める |

`Scene3d.BillboardFields` に欄 `castShadows`・`receiveShadows`、`Scene3d.MaterialFields` に欄 `maxMipLevels` が増えた。
`Scene3d.billboard` / `Scene3d.material` から作っていれば直す所は無い（どちらも閉じた型で、ゲームが欄を全部書いて作る口は無い。欄の名前で分解して読んでいる所だけ、新しい欄を足す）。

## スポットの影が近い所で消えていたのを直した

スポットの影の地図の目の near が 1 に決め打ちだったので、1 = 1 m の部屋で光から 1 m 以内の物（卓上の灯りの周り）は影を落とさず、そこの面は影を受けなかった。
near を `min(1, max(2, range) / 100)` にした（`Scene3d.shadowCamera`）。`bias` は今までと同じ値のまま、描き手が near に合わせて縮めて引く
（`Scene3d.spotShadowDepthBiasOf`。world で表す長さが near 1 の時とそろう）ので、書いた `bias` は直さなくてよい。range が 100 以上のスポットの絵は変わらない。
range の短いスポットでも、光から 1 m より遠い所の影は今までと同じ絵（CPU の固定の 2 場面はバイトまで同じ）で、1 m 以内の物の影が新しく出る。

## engine の束を中身のハッシュ付きの置き場に置く（`build/fpkg-store`・同じ版でも `engine-upgrade` が入れ替える）

engine の作業場で組んだ束（engine_full と、ブラウザ版の engine_full_web）は、`build/fpkg-store/<名前>-<版>-<ハッシュ 16 字>/` の
不変のエントリ（content-addressed store。pnpm の store・Nix の store と同じ考え方）に入るようになった。`current/<名前>` が今の物を指す。
作り直しは新しいエントリを足して `current` と lib の symlink を rename で替えるだけなので、別のゲームの build・export-web の途中で束が書き換わらない。

| 何が | どう |
|---|---|
| 入れる口 | `make sync-engine-full`（package.fpkg と flix.toml）・`make sync-engine-full-web`（package.fpkg・flix.toml・GL と web と tools の jar）。どちらも中身（型検査・build-pkg・置く・張る・掃除）を置き場の鍵（`build/.fpkg-store.lock`）の内側で流すので、同じ作業場で 2 本重ねると後の方は待つ。zip が最後まで読めない束は置かない |
| lock だけ古い | lib の束は新しいのに packages.lock の sha だけ古いゲームも、`make engine-upgrade` がそろえる（束は替えない） |
| 配った版 | Studio の同梱の engine から `engine-upgrade` する時は中身で入れ替えない（`--no-content-swap`。use-engine で入れた作業場の束を同梱の束へ戻さない） |
| templates・bench の lib | `lib/github/ababup1192/flix_game_engine/<版>/` の fpkg と toml は置き場のエントリへの相対 symlink。packages.lock は消さずに、その版の節の sha をエントリにそろえる |
| ゲームの lib | 今までどおり写し（engine の外にあるので symlink にしない）。`make engine-upgrade` は**版が同じでも中身のハッシュが違えば入れ替え**、「v… のまま engine の束の中身が新しくなっていたので入れ替えます」と 1 行言い、packages.lock のその版の節の sha もそろえる（節が無ければ触らない。flix が足す）。check が赤く当たる非互換も無ければ、前の束と前の lock へ戻す |
| `bin/fge export-web` | 置き場の `current/engine_full_web` を最初に 1 回だけ辿り、そのエントリから束も jar も読む（置き場が無い engine だけ前の `build/engine_full_web` を読み、そう 1 行言う） |
| `bin/fge use-engine` | 置き場の今の束と同じエントリの toml を写す（置き場の無い古い版のタグは前の `engine_full/artifact`） |
| 掃除 | `make fpkg-store-gc`（sync の終わりにも走る）。消すのは、`current` と templates・bench の lib のどれからも指されていないエントリのうち、名前ごとに新しい方から 5 個より後ろで、最後に入れてから 1 日より経った物（`FPKG_STORE_KEEP`・`FPKG_STORE_MIN_AGE_MIN` で替える）。`DRY=1` で消す物を見るだけ |
| worktree | `make worktree-seed` が main の置き場を clone（写し）で張る。symlink で張られた置き場を見たら `bin/fpkg-store.sh` が自分の実体に置き換えてから書く（main の build へ書き込まない）。`artifact/package.fpkg` が symlink なら build-pkg の前に外す |

### 移り方

| 順 | どこで | 何を |
|---|---|---|
| 1 | engine の作業場 | `make sync-engine-full`（ブラウザ版を使うなら `make sync-engine-full-web` も）。置き場が作られ、templates・bench の lib が張り替わる。`make status` の「fpkg … 直に指す lib」の行が消える |

| 3 | worktree | 作り直すか、`rm -rf build/fpkg-store` の後に `make worktree-seed`（無い物だけ張る）。張らずに sync を流しても、その worktree の中に置き場が作られる |

## ノベル（sound-novel-starter）は縦が基本になった

テンプレートの design が縦の 540×1170 になり、PC（デスクトップ版・PC のブラウザ）でも同じ縦の画面を真ん中に出す。絵・組み・通し（flow）は 1 つ。
横の組み（`Layout.Fit.Regular`・`Fit.Small`）はコードに残してあるので、.flix を写しただけでは見え方は変わらない（design が横のままなら横のまま）。
縦へ移るゲームは次の順で直す（書き方の正はテンプレートの `AGENTS.local.md` の「縦が基本」）。

| 順 | 何を | どう |
|---|---|---|
| 1 | .flix を写す | テンプレートの `src/View.flix`（幅に入らない字を縮める `View.fittedSize`）・`src/E2e.flix`（右の列を押し始めた所を返事に数える）と、ゲームが写しているテンプレートの .flix を写す |
| 2 | design とウィンドウ | `project.json` の `designWidth` / `designHeight` を 540 / 1170、`windowWidth` / `windowHeight` を 360 / 780 に。`web.portraitDesign`（幅 540・`minHeight` 960）は残す |
| 3 | 背景の写真 | 縦の構図（9:19.5 前後）で作り直す。画像生成に縦長（1024×1536 など）で頼み、大事な物は横の真ん中 70%・縦の 15〜85% に。仕上げは `ffmpeg -i in.png -vf "scale=-2:1560,crop=720:1560" -q:v 2 assets/bg/<名前>.jpg`。一枚絵（人の姿の入った物）は、同じ場所の背景を画像の編集で直して姿を足す。作り直すまでの仮は、今の横長の写真から大事な物を真ん中に縦に切る（`ffmpeg -i old.jpg -vf "crop=ih*0.4615:ih:<左の端の x>:0" new.jpg`） |
| 4 | photos の aspect | `assets/novel.backdrops.json` の photos に `"aspect": 横÷縦`（720×1560 は 0.4615）を書く。書かないと 16:9 の横長として真ん中を切る |
| 5 | `<<camera>>` | x・y は画面（＝縦の写真の幅・高さ）が 1。前の値は横の画面の幅が単位だったので、見せたい物の縦の写真の上の位置から決め直す（写真の左から p の所を真ん中にするなら x = p − 0.5）。zoom=z で写真の端が出ないのは ±(1 − 1/z)/2 の中 |
| 6 | flow | 縦用の flow の写しを持っていればそれを正にし、横の flow を消す（無ければ横の flow の点を縦の座標に直す）。点の押しは縦の design（540×1170）の座標。右の列（しおり・ログ・オート）と右上の … は `tap x,y` で押せる（テンプレートの `e2e/bookmark.flow`）。画面の下から測る物（頁・選択肢・セーブの枠）は点でなく役（`confirm`・`next`・`tabNext`）で押す |
| 7 | テープ | Makefile の `TAPE_VIEWS` の既定を `phone` だけに（テンプレートの Makefile を写す） |
| 8 | 基準の絵 | `make render-all` で前後を並べて見てから `make reference-update`（縦の頁は字を積むので描き物の数が増え、値段の門に止まる。見て良ければ `BUDGET=accept`）。`reference/title.png` も縦になる |
| 9 | 比べ | 前の版で `make migrate-baseline`、移した版で `make migrate-new`。画面の大きさが替わるので絵は全部違う。台詞・選択肢・変数・音・待ちの秒がそろっているかを見る |
| 10 | 左右の余り | テンプレートの `src/Game.flix` の `App.withLetterboxView(Resources.view(View.letterbox))` の 1 行と `View.letterbox` を写す（下の「design の外の余りを絵で塗る」） |

## design の外の余りを絵で塗る（`App.withLetterboxView`）

窓の比が design と違う時に出る余り（レターボックス・ピラーボックス）は、今まで黒（GL と WebGPU の画面の pass の黒帯）だった。
`App.withLetterboxView(v)` を足すと、v の絵で塗る。足さないゲームは今までどおり黒（直す所は無い）。

| 何が | どう |
|---|---|
| 口 | `App.withLetterboxView((ctx, w) -> 絵)`。絵は design の大きさの画面に描くつもりで返す（ctx の visible は画面全体）。engine がそれを Pass（名前 ``fge_letterbox`` = `fge_letterbox`）へ描き、縦横比を保って窓いっぱいに広げ（はみ出しは真ん中で切る）、余りの所にだけ見せる |
| 呼ばれる時 | 窓の比が design と 0.5% より違うコマだけ。画面なしの描き出し・flow・テスト（`Display.desktop`）では呼ばれない |
| 描き手 | GL（デスクトップ・ブラウザの WebGL2）と WebGPU（デスクトップ・ブラウザ）の両方。画面の pass の前に、描き先の全面を viewport にした pass（`RenderList.fullTargetPass`）で広げた絵を 1 枚貼り、本編の pass は余りを塗らずに残す（`RenderList.Letterbox.Kept`） |
| 何を渡すか | ぼかした背景だけ。広げるので細部は粗くなる。立ち絵・字・粒を入れると窓の幅いっぱいに大きく出る |
| `Platform.Draw2d` | op `fillLetterbox(texture)` が増えた。自前で `Platform.Draw2d` の handler を書いているゲーム・テストは `def fillLetterbox(_texture, k) = k(())` を足す |
| `RenderList.PassTarget.Screen` | 欄 `letterbox` が `Bool` から enum `RenderList.Letterbox`（`Absent`・`Black`・`Kept`）になった（render_gl の Internal。ゲームからは触らない） |
| `RenderPaint.Frame` | 欄 `letterbox = Option[String]` が増えた（`{ … | RenderPaint.emptyFrame() }` で組んでいれば直す所は無い） |
| 比が少しだけ違う窓 | 比の違いが 0.5% 以内なら絵を描かず、描き手は余りを黒で塗る（1920 幅で片側に数 px の黒い線が出ることがある） |
| `App.withPostStack` と一緒に使う時 | 余りの絵は後がけ（線形化・トーンマップ・ブルーム）を通らない。真ん中と色味を合わせたい時は、余りの絵の側で色を寄せる |
| 窓を引っ張って大きさを変えている間 | design と同じ比の窓から広げると、引っ張っている間は余りが黒く、離した次のコマから塗られる（描き直しは前のコマの頼みを使う） |

## レコードに欄が増えた所（記録を欄を全部書いて組んでいるコードだけ直す）

`Scene3d.BillboardFields`（castShadows・receiveShadows）・`Scene3d.MaterialFields`（maxMipLevels）・`Scene3dCmd`（unitsPerMeter）・`App.Rec`（postStack・screenClear・letterboxView）に欄が増えた。`Scene3d.billboard` などの作る関数と `App.with*` を通している所は直さなくてよい。記録を `{ … }` で全部の欄を書いて組んでいる所だけ、増えた欄を足す（既定は偽・0（上限なし）・1.0・None・project.json の clearColor・None）。
