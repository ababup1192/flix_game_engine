# engine 0.73.0 → 0.74.0 の手当て（下書き）

OBJ と glb から 3D の形を組む所と mip を作る所を書き直し、起動の読み込みを速くした（fps3d_lab で OBJ の組み立てが約 1.7 秒 → 約 0.5 秒）。
起動の読み込みの進み具合を知らせる effect `LoadProgress` を足した。読み込みの間も起動画面が進み、ウィンドウが応答し続ける。
絵は 1 bit も変わらない（gl-parity とテンプレートの絵で確かめた）。

## ゲームで直す物

- **3D の形の中身の hash を字で固定しているテスト**は、期待する字を書き直す。`Mesh3d` の中身の hash
  （`hashOf` などが返す SHA-256 の字）と、それを含む描き物の鍵（`DrawHash`）の字が変わった。
  同じ中身なら同じ字・違う中身なら違う字、という性質は変わらない。テストは字を固定せず、この性質で書くと版を上げても止まらない
- 描き出しのキャッシュ（`RenderCache`）は鍵が変わるので、上げた直後の 1 回だけ描き直す（絵は同じ）
- **`ShaderGen.eqEmission` を呼んでいるゲーム**（自前の描き手で材質を比べている物だけ）は、`ShaderGen.eqMaterial(specA, emissionA, specB, emissionB)` に替える。
  eqEmission は emission の読む絵の名前を比べず、spec と同じ名前を読む emission と別の名前を読む emission を同じと答えていた

## 足した物（使わなければ何も変わらない）

- `App.loadAndLaunch(loadApp)`: Doc を読んで App を組む所ごと渡して launch する。`make debug`（flow を記録する起動）でも Doc を読み直さないので、
  起動が速い（fps3d_lab で約 4.4 秒 → 約 1.9 秒）。main の `run { 組む式 |> App.launch } with …` を `run { App.loadAndLaunch(() -> 組む式) } with …` に替える。
  自前の `reloadOn`（DocTable を使わない一括読み直し）を繋いだゲームは、記録する起動では今までどおり読み直す

- `LoadProgress`: 起動の読み込みを区切って進み具合を知らせる。実機（`LwjglLayer.withProject`）が受けて起動画面を進め、
  ウィンドウのイベントを poll する。使い方は engine の `docs/startup.md`
  - `LoadProgress.mapWithProgress(phase, f, xs)`・`parMapWithProgress(phase, f, xs)`（並列。スレッドは CPU の数まで）・`report(phase, done, total)`
  - **使うゲームは、headless の描き出し・動画・flow・テストの入口に `LoadProgress.runNoop` を張る**（張り忘れは型の誤りで止まる）

## 振る舞いが変わる物（型は同じ）

- 3D の材質で、emission が読む絵の名前だけが違う 2 つの材質を、別の材質として組み分けるようになった（今までは同じ program を使い回し、後の材質の emission が前の材質の絵を読むことがあった）
- 骨つきの物の joint 行列は、中身が前と同じなら GPU へ書き直さない（絵は同じ。同じ pose の部品が多い場面で 1 コマが軽くなる）

- `withStarts` を使うゲームの起動で、Doc を読み直さなくなった（main で読んだ物を使う）。`App.launch` のまま flow を記録する起動
  （`make debug`。`DEBUG` があり `FLOW_RECORD` が 0 でない時）だけは今までどおり読み直す。
  init が Doc の中身を使わずに World を組み、読み直し（`reloadOn` / `watchFile` の関数）で初めて Doc を入れているゲームは、起動の World が変わる
- flow の記録で、start の行の直後に `expect fp=`（起動の World の指紋）を書くようになった（`withStarts` と `withFingerprint` を繋いだゲーム）。
  再生の始まりの World が記録と違うと、その行で理由つきで止まる。前に記録した .flow はそのまま再生できる
- 実機の起動で、画面の垂直同期を戻す時期が「ゲームの本体を呼ぶ前」から「ループが初めて回った所」に移った（読み込み中の起動画面の 1 枚ごとに 1 コマ待たないため）
- 実機の起動で、最初のコマより前に回したマウスのホイールは捨てる
