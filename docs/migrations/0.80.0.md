# engine 0.79.0 → 0.80.0 の手当て

## 2D の描き手から 3D の描き手を外した（render_gl の中だけ）

**絵は 1 画素も変わらない**（gl-parity の行・CPU と GL の絵・3D の部屋・テンプレの実機の絵が 0.79 とバイトまで同じ）。
`LwjglLayer.withProject` と `GlOffscreen` で走らせるゲーム・テンプレは直す所が無い。

- **自前の描き手で `RenderPaint.create` を呼んでいる所**だけ: cfg の `scene3dTextureBudget` と `scene3dLinearColor` の 2 つを
  `scene3d = Render3d.makeRenderer(config)` の 1 つにする（予算と色の計算の旗は `makeRenderer` が `config` から読む）。
  3D を描かない描き手は `scene3d = Scene3dRenderer.none()` を渡す
- 3D の描き手のインターフェースは `Scene3dRenderer.Renderer`（`prepare`・`endFrame`・`takeCounts`・`readsTexture` の 4 つの欄）だけになった。
  `Render3d.fresh`・`Render3d.prepareScenes`・`Render3d.drawItem`・`Render3d.endFrame`・`Render3d.takeCounts`・`Render3d.textureBudgetOf` は
  pub でなくなり（型 `Render3d.SceneItem` も）、`Render3d.elapsedSeconds` は消えた。3D の絵の置き場の予算は `makeRenderer` が `EngineConfig` から読むだけで、直に渡す口は無い
- 型の置き場が替わった: `Render3d.Viewport` → `Scene3dRenderer.Viewport`・`Render3d.Dest` → `Scene3dRenderer.Dest`・
  `Render3d.BillboardTexture` → `Scene3dRenderer.RegisteredTexture`（中身は同じ）

## App の中身を App.Internal.* へ分けた（engine_world の中だけ）

**ふるまいは変わらない**（engine_world のテスト・テンプレの `make test`・gl-parity・実機の絵が 0.79 と同じ）。
ゲームが呼ぶ口（`App.make`・`App.with*`・`App.launch`・`App.trace`・`App.traceFrame`・`App.advanceFrame`・`App.frameOf`・
`App.emptyFrame`・`App.tickClocks`・`App.freshStepState`・`App.StepState`・`App.PendingEdges`・`App.composeScene`・`App.visibleOf` など）は
全部 `App` に残したので、ふつうのゲームは直す所が無い。

- ループ・描く所・音とウィンドウへの出力・F8 で止めた画面・ヒッチの記録は `App.Internal.Runner`・`Paint`・`Output`・`Halt`・`Hitch`・`Frame` へ移した。
  **ゲームの src と test で `App.Internal.` を書くと lint-forbid の app-internal が止める**（版を上げると名前も形も黙って変わる）
- 次の名前は `App` から無くなった（`App.Internal.*` の中身になった）: `App.paintOnce`・`App.drawPassPlan`・`App.submitGpuItems`・
  `App.applyHaltLook`・`App.sustainOps`・`App.noteSoundUses`・`App.unloopedOneShots`・`App.SoundUses`・`App.keysAfterJump`・`App.dueOutputs`・
  `App.decideBranch`・`App.decideClose`・`App.Branch`・`App.CloseAnswer`・`App.TileCache`・`App.freshTileCache`・`App.bumpTileGen`・
  `App.tileCacheHit`・`App.tileCacheVaoAt`・`App.tileCacheStore`・`App.heldCursor`・`App.cursorDelta`・`App.fixedSteps`・`App.suppressEdges`・
  `App.mergeEdges`・`App.pendingOf`・`App.applySystems`・`App.changedPaths`
- 代わりの口: 1 コマを実機と同じ道で進めるなら `App.traceFrame`（列なら `App.trace`）、系に渡す Frame を組むなら `App.frameOf` / `App.emptyFrame`。
  代わりの無い物（`paintOnce` でウィンドウなしの GL に 1 枚塗る・`sustainOps` で鳴り続ける音を仕分ける など）を使っていたら、engine に口を足すよう相談する
- engine の 4 パッケージの src の .flix に行数の上限（1,200 行・`make lint-max-lines`・超えた物は `bin/lint-rules/max-lines.json` の除外の一覧）を足した。ゲームの src は見ない

## 機種の effect を役割ごとに分けた（`mod Platform`）

**ふるまいと絵は変わらない**。`LwjglLayer.withProject` と `GlOffscreen` で走らせるゲーム・テンプレは直す所が無い
（どちらも新しい effect を受ける）。`GameEngine.Game`・`ShaderEffect.Shader` は無くなった（古い op を呼ぶ所は型検査で止まる）。

- `GameEngine.Game` の 28 個と `ShaderEffect.Shader` の 3 個の op を、役割ごとの effect に分けた:

  | effect | op |
  |---|---|
  | `Platform.Input` | `isKeyPressed` `getMousePosition` `isMouseButtonPressed` `isGamepadTouched` `gamepadKind` `consumeScrollDelta` `consumeMouseDelta` `isWindowFocused` |
  | `Platform.Window` | `pollEvents` `shouldClose` `setShouldClose` `getViewportRect` `presentFrame` `setCursor` `setCursorVisible` `setMouseCaptured` `setFullscreen` `isFullscreen` `setDebugBadge` |
  | `Platform.FrameClock` | `getDeltaTime` |
  | `Platform.Draw2d` | `renderCommands` `drawSurface` |
  | `Platform.Draw3d` | `drawScene3d` |
  | `Platform.GpuResources` | `initTileBuffer` `updateTileBuffer` `ensureTexture` `ensureGlyphs` `getFontAtlas` `getTextureInfo` `buildProgram` |
  | `Platform.Diagnostics` | `setDiagnosticsEnabled` `consumeDiagnostics` |
  | `Platform.Annotation` | `saveAnnotation` |

  op の名前・引数・意味は同じ（下の swap と poll の 2 つだけ替わった）。`Input` は `PropertyTest.Input` と重なるので、いつも `Platform.Input` と書く
- **swap は `renderCommands` から外した**: `Platform.Draw2d.renderCommands` は塗るだけで、画面へ出すのは `Platform.Window.presentFrame()`
  （1 フレームの終わりに 1 回。画面へ塗ったコマが無ければ何もしない）。App のループは自分で呼ぶので、ふつうのゲームは直す所が無い。
  **自分で `renderCommands` を呼んで窓に出していた所**（bench など）は、その後に `Platform.Window.presentFrame()` を足す
  （`FLIX_GE_FRAME_SHOT` の撮る口も `presentFrame` の swap の直前に移った）
  - F8 で矩形を確定して注釈を撮るコマは、swap が 2 回から 1 回になった（等倍の絵が一瞬だけ画面に出ることが無くなる。
    screenshot.png は今までどおり等倍の絵で、FrameStats と `FLIX_GE_FRAME_SHOT` もこのコマは 1 回ぶん）
- **poll は `shouldClose` から外した**: OS のイベントとゲームパッドを取り込むのは `Platform.Window.pollEvents()`（1 フレームの頭に 1 回）。
  `shouldClose` は問うだけになった。自分でループを回していた所は `shouldClose` の前に `pollEvents` を足す
- **op を直に呼んでいる所**（`GameEngine.Game.isKeyPressed(k)` など）は `Platform.Input.isKeyPressed(k)` のように effect の名前だけ替える。
  関数の型の `\ GameEngine.Game` も、触る effect だけにする（Flix は使わない effect を型に書くと止める）
- `App.launch` / `App.loadAndLaunch` の型は `\ Platform.Services + Platform.Annotation + Fs.FileRead + Fs.FileWrite + IO` になった（下の「実機で走らせる App は純粋な物だけ」）。
  `Platform.Services` は `Input + Window + FrameClock + Rendering + RenderTarget.Target + GameEngine.Audio + Diagnostics` の束で、
  `Platform.Rendering` は `Draw2d + Draw3d + GpuResources`（積む op と出す op を分け合うので、同じ handler の組から張る 3 つ）
- 型に effect の差を書いていた所: `LwjglLayer.withProject` / `withLwjgl`・`GlOffscreen.handle`・`GpuShot.shotOf` の型の effect の列が替わった
  （差に `Platform.Services`・`Platform.Annotation` などが入る。`GlOffscreen.handle` の受け持つ束は `GlOffscreen.HandledEffects`）。自前の bench などで同じ差を型に書いていたら、型を消して推論に任せるか、新しい列に合わせる
- trait `GameEngine.Renderable` の `toDrawables` の型は `\ Platform.GpuResources`（使うのは `getTextureInfo` だけ）。`Sprite.toDrawable`・
  `InputEvent.currentKeys`（`\ Platform.Input`）・`UiRender.renderUi` も同じく細くなった。
  リモートデバッグの `App.RemoteDebug.handleRemote` も `\ GameEngine.Game` が `\ Platform.Window + Platform.GpuResources` になった
  （engine の中の開発の道具が呼ぶ。自前で呼んでいるなら型の effect の列を合わせる）
- `ShaderEffect.runNoop` は消えた。3D を描かない handler の組は `Platform.runNoopDraw3d`（buildProgram と drawSurface は `GpuResources`・`Draw2d` の偽物で受ける）
- `LwjglLayer.mouseDeltaInWindow` は `LwjglInput.mouseDeltaInWindow` へ移った（窓の入力を読む物は `LwjglInput` にまとめた）
- 型 `ShaderEffect.ShaderRenderCmd` は `DrawCmd.SurfaceRenderCmd` へ移した（中身は同じ）。古い名前は 0.84.0 で消える（lint-forbid の shader-render-cmd-alias が知らせる）
- **テストで偽物の handler を書いている所**は、触る effect の分だけ書けばよい（`App.Internal.Paint.drawPassPlan` なら
  `Platform.Draw2d`・`Platform.Draw3d`・`Platform.GpuResources` と `RenderTarget.Target`。28 個を全部書かない）
- **自分で `GameEngine.Game` の handler を書いて App を走らせている所**: handler を effect ごとに分けて書く（op の中身は同じ。
  `renderCommands` の swap は `Window.presentFrame` へ、`shouldClose` の poll は `Window.pollEvents` へ移す）。
  `LwjglLayer` は effect ごとの関数（`LwjglInput.handleInput`・`RenderPaintHandlers.handleGpuResources` など）を重ねているので、それが見本になる。
  分けるまでの間、古い handler に新しい effect を回すなら次の形
  （残りの effect も同じく 1 つずつ。並びは毎コマ多く呼ぶ `GpuResources`・`Input` を内側に）:

  ```flix
  def legacyGame(f: Unit -> a \ ef): a \ (ef - Platform.GpuResources - Platform.Input) + MyGame =
      run f() with handler Platform.GpuResources {
          def getTextureInfo(n, k) = k(MyGame.getTextureInfo(n))
          // ほかの op も同じく、古い op をそのまま呼んで k へ渡す
      } with handler Platform.Input {
          def isKeyPressed(key, k) = k(MyGame.isKeyPressed(key))
      }
  ```

  古い handler が `shouldClose` の中で poll し、`renderCommands` の中で swap しているなら、`Platform.Window` の `pollEvents` と `presentFrame` は
  `k(())` で何もしない（`shouldClose` と `renderCommands` を古い op へ回せば、今までどおり poll と swap が起きる）

## マウスの右と中のボタン（`Frame#mouseButtons`）

- `App.Frame` に `mouseButtons`（いま押しているボタンの集合・左右中）と `mouseClickedButtons`（このフレームで押したボタン）を足した。
  `mouseDown`・`mouseClicked` は左のまま残る（左は両方に同じ値が入る）。右クリックは `Set.memberOf(GameEngine.MouseButton.Right, frame#mouseClickedButtons)`
- **`App.Frame` を字で全部の欄を書いて組んでいるテスト**は止まる。`{ down = … | App.emptyFrame() }` の形に替える（欄が増えても止まらない）。
  右と中も置くなら `App.withMouseButtons(前のボタン, 今のボタン, frame)`（左の分は `mouseDown`・`mouseClicked` にもそろえる）
- `App.PendingEdges` にも `mouseClickedButtons` が足された（字で組んでいる所は同じく足す）
- flow: `mouse=right`・`mouse=left,right` で右と中のボタンを押したフレームを書ける（左だけは今までどおり `mouse`）。
  差分から出ないクリックは `click=right`（無ければ `click=-`）。記録もこの形で書き、`bin/fge flow check` も同じ語を読む
- `Flow.Opt` に `otherButtons`（押している右と中のボタン）と `otherClicks`（差分から出ない右と中のクリック）を足した。
  **`Flow.Opt` を字で全部の欄を書いて組んでいる所**は止まる。`{ mouse = true, … | Flow.noOpt() }` の形に替える（engine の外では見当たらない）

## 実機で走らせる App は純粋な物だけ（系の純粋さの強制）

- `App.launch`・`App.loadAndLaunch` は `App[w, {}]`（系・View・音の導き・終了判定が effect を持たない App）だけを受ける。
  effect を持つ App は画面なしの道（`App.trace`・`App.traceFrame`・flow）とテストで流す。今のテンプレと外のゲームは直す所が無い
- 系の中で IO を測る bench は `App.launchForBench`（ゲームの src で書くと lint-forbid の launch-for-bench が止める）
- ゲームの src（`src/render/` とテストを除く）の `unsafe` と、effect を消す `unchecked_cast(… as _ \ {})` を lint-forbid が止める
  （game-unsafe・game-unchecked-pure）。Math を包むなら `Num.sin`・`Num.cos`・`Num.asin`・`Num.log`・`Num.sqrt`（`Num.asin`・`Num.log` は 0.80.0 で足した）か
  標準の `Float64.pow`・`Float64.exp`。今ある物は forbid.json の exempt に載せてある（internet_dungeon の `src/AssistShow.flix`・`CardPile.flix`・`EndScreen.flix`）
- ゲームの effect を実機で使いたい時に、純粋な handler で消してから launch へ渡す口（計画の `App.handleWith`）はまだ無い。要るゲームが出たら engine に相談する
