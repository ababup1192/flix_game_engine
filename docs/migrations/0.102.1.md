# engine 0.102.0 → 0.102.1 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## Studio の「engine を更新」が exec format error で止まっていたのを直した

ゲームのコードで直す所は無い。

| 何が | どう |
|---|---|
| 公開を CI に移した 0.69.0 から 0.102.0 までの、CI で出した Release の zip | `bin/fge-go` が zip を組んだ CI（linux/amd64）向けの 1 つだけで、mac の Studio の「engine を更新」が取ってきた中身を走らせる所で `exec format error` になっていた。Windows 向けの `bin/fge-go.exe` も入っていなかった |
| 0.102.1 からの zip | 検査の中身 5 種（darwin-arm64・darwin-amd64・linux-amd64・linux-arm64・windows-amd64）を 1 つずつ入れる。`bin/fge-go` は darwin/arm64 向け・`bin/fge-go.exe` は windows/amd64 向けの実物で、残りの 3 種は `bin/dist/`。もう配られている Studio（mac arm64・Windows）の更新もそのまま通る |
| 新しい `fge fetch-engine` | 入っている検査の中身の頭（Mach-O・ELF・PE）を読んで自分の機械に合う 1 つを選び、`bin/fge-go`（Windows は `bin/fge-go.exe`）に置いて他の機械向けを消す。合う物が無い・検査の中身が無い時は、機械の名前と入っている物を言って止まる（例 0.102.0 の zip を mac で入れると「この機械 (darwin/arm64) で走る検査の中身 (fge-go) がありません (入っているのは linux/amd64 向け)」） |
| Studio に同梱する engine（`make stage-engine`・`ci/package-windows.ps1`） | 変わらない（組む機械に合う 1 つだけ） |
