## ゲームで直す物

1. **DEBUG で起動すると命令口がいつも開く。** `DEBUG_HTTP_PORT` が無ければ空いたポートを自分で取り、
   `~/.flix_ge_studio/games.json` に `{dir, pid, port}` を書き置く（閉じる時に消す）。開きたくなければ `DEBUG_HTTP_PORT=off`。
   命令口は 127.0.0.1 だけで待つ（今までと同じ）。
2. **`App.App` を record の字面で組んでいる所**は欄 `shot = None` を足す（`App.make` / `App.game` から足していけば直さなくてよい）。
3. **`App.RemoteDebug.View` を match している所**は `case View.Shot` を足す（リモートの `view=shot`。ゲームが自分で match していなければ直さなくてよい）。

## 新しく使える物

### 1 枚撮る（`App.onShotRequest`・`view=shot`）

```flix
App.game({ … })
    |> App.onShotRequest(SceneRender.shotOf)   // w -> String \ IO: World を 1 枚描いてパスを返す（debug/shot/ の下に）
```

- リモートの `POST /step?view=shot` に `start talk node=clock line=40` を送ると、場面を組んで撮るまでが 1 往復。
  答えは `/render` と同じ形の `ok png=<パス>`（`[shot]` の下の行）。`POST /start?…&view=shot`・`GET /state?view=shot` も同じ。
- 書き先はゲームが決める（雛形 novel-starter は `debug/shot/shot-<pid>.png`。`gallery/` に書くと reference-check が「増えた絵」と言う）。

### 窓なしのゲーム（`App.Headless.serve`）

```flix
// src/E2e.flix（雛形 novel-starter に全文）
pub def serveHeadless(): Unit \ IO =
    run { App.Headless.serve(Game.app(Controls.loadDocs(), NovelKit.spawnAssets())) } with Fs.FileRead.runWithIO
```

- 新しい make の口は作らない。`bin/headless-run E2e.serveHeadless` が jar を 1 回だけ作って流す。
- 待ち受け（`HEADLESS_PORT`。開けたら `[headless] ready port=N pid=P`）か、`FGE_SHOT="talk node=… line=…"` で 1 枚撮って終わる。
- 実機でない扱い: 系を流すだけで、セーブ（`App.addOutput`）・表示中の Doc の名乗り・遊んだ記録は書かない。
  Doc は始まりを組むたびに読み直す（保存した台本がそのまま次の 1 枚に効く）。
- 放っておかれたら自分で終わる（`HEADLESS_IDLE_SECS`・既定 600 秒）。メモリの上限は `HEADLESS_JAVA_OPTS=-Xmx1g`。

### 行から始める（`YarnRunner.startAt`・`Yarn.nodeAtLine`）

- `YarnRunner.startAt(シナリオ, ノード, 行, 今)`: ノードの頭から、.yarn のその行を出している所まで進める
  （台詞は送り、選択肢はその行を中に持つ物を選ぶ。選択肢の行なら直前の問いの台詞で止まる = `choicesFollow` が真）。
- `Yarn.nodeAtLine(ファイル, 行, シナリオ)`: その行を中に持つノード（そのファイルで title: の行が line 以下のいちばん後）。
- 始まりの登録簿の `talk` に `line=` を足す（雛形 novel-starter の `Starts`・`World.openTalkAt`。文字送りは使い切る）。
  Studio と `bin/fge talk` は `talk node=<ノード> line=<行>` を送るので、会話のあるゲームはこの名前と引数で置く。

### 道具（Go）

| 口 | 中身 |
|---|---|
| `bin/fge talk goto <file.yarn>:<行>` | 起動中のゲームをその行へ（`--port` → `DEBUG_HTTP_PORT` → games.json） |
| `bin/fge talk shot <file.yarn>:<行> [--out x.png]` | 窓なしのゲームで 1 枚（`E2e.serveHeadless` を `FGE_SHOT` で） |
| `bin/fge talk where <file.yarn>:<行>` | その行のノードの名前 |
| `bin/fge yarn build|check … --json` | 知らせ（ファイル・行・文）・注意・ノードの一覧・書いたファイル（Studio の会話の画面が読む） |
| `bin/fge videos status [--json]` | `debug/video/` の動画と撮れたか（下） |

VS Code はタスクとキーの割り当てだけ（配らない。手元の `.vscode/tasks.json` に 1 本）:

```json
{ "label": "talk goto", "type": "shell", "command": "bin/fge talk goto ${relativeFile}:${lineNumber}",
  "presentation": { "reveal": "silent" }, "problemMatcher": [] }
```

### 撮れたかの判定（`bin/fge videos status`）

動画の口が `debug/video/<出力名>.video.json` を書くゲーム（internet_dungeon の `bin/video-status.py` の形）なら、
道具が `ok` / `failed`（段 `stage` と `failure`）/ `stuck`（`running` のまま撮っていた make の pid が居ない。更新時刻では見ない）/
`running` / `norecord`（記録を書く前の mp4）に分ける。連番のフォルダの最後の PNG を「最後の画面」、`sfx.txt` を鳴った音として添え、
`debug/compare/report.tsv`（make compare）の動画の行から「基準と違う」を添える。記録に `"flow": "e2e/<名前>.flow"` があれば、
その先頭のコメントを題と一言にする。

```json
{ "state": "running|ok|failed", "make": "<make の口>", "pid": 123, "startedAt": "…", "stage": "frames|mix",
  "failure": "<1 行>", "frames": 958, "fps": 60, "flow": "e2e/<名前>.flow" }
```

### make compare の動画の音

コマが同じでも音の差を言う。先に mp4 の音声の md5 を比べ、違えば連番の `sfx.txt` を名前つきで比べる（`音 -hit@12 +hit@13`）。
