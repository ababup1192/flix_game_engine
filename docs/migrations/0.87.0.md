# engine 0.86.0 → 0.87.0 の手当て

## ゲームで直す物

| 直す所 | 直し方 | 止める物 |
|---|---|---|
| ブラウザ版で Scene3d を描くゲームの `web/WebMain.flix` | `WebLayer.withProject` を `WebLayer.withProject3d` へ替える。2D のゲームは変えなくてよい | 止まらない（`withProject` は 3D を描かず、`export-web` と起動の時に 1 回言う） |
| `WebLayer.withWeb` を直に呼んでいる所（テンプレ・ゲームには無い） | pub でなくなった。入口は `withProject` か `withProject3d` | コンパイル |
| 手書きの格子や距離の地図を持つゲーム | 直さなくても動く。速くしたいなら `SpatialGrid`・`FlowField` へ替える（`docs/performance.md` の「重くなったらこれ」） | 止まらない（lint の `perf-near-scan`・`perf-list-index` が知らせる） |

## 絵とふるまい

- デスクトップの絵は変わらない。3D の GL の呼び出しは `GlContext` を通る形になった。
- 影の無い場面の `uShadowMap` は、1×1 の透明な黒を貼った unit 9 を指す（WebGL2 の feedback loop を避けるため。絵は同じ）。
- 3D の材質のプログラムの上限の下限が 16 から 64 へ上がった。
- ブラウザの `App.withMouseCapture` が本当に効く（pointer lock）。2D のゲームでも、宣言していれば頁で lock が掛かる。
- ブラウザの `LoadProgress.imageDecoder` が `Ok` を返す（前はいつも `Err`）。`Err` を前提に絵を飛ばしていたゲームは、絵が出るようになる。
- 3D の 1 コマの区間で、Mip を作る時間が `Draw` から別の区間 `mip` へ分かれる（/perf の `Draw` の数が読み比べで下がる）。

## 足した物

- `WebLayer.withProject3d`: ブラウザ（WebGL2）でデスクトップと同じ `Scene3d` を描く入口。絵の差は `docs/backend-parity.md`。
- `SpatialGrid`（`build`・`buildBy`・`foldNearIndex`）: 近くの物を引く格子。毎コマ作り、World には置かない。
- `FlowField`（`build`・`empty`・`isEmpty`・`stepsAt`・`downhill`）: 群れで共有する距離の地図。
- lint の `perf-near-scan`・`perf-list-index`（知らせるだけ）。
