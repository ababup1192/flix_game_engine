# engine 0.57.1 → 0.58.0 の手当て

自動生成の一覧は [0.58.0.auto.md](0.58.0.auto.md)（直す物 0 件）。Flix の pub は変わらない（変わったのは Go の `bin/fge refactor` だけ）。

minor を上げるのは、**`bin/fge refactor` の change-signature・remove-param・retarget-field が flixlint 0.8.7 以上を要るようになった**ため（下の 1）。

## 1. 引数を索引で引く（flixlint 0.8.7・索引の adds に param・aparam・alias-fields）

- **何が変わるか**: flixlint の索引が、最上位の def の引数の行（`param`）・呼ぶ所の引数が囲む def のどの引数そのものか（`aparam=`）・
  record の alias の欄（`fields=`）を出す。形の版は 3 のまま、新しい行と欄は頭の行の `adds=` で知らせる。refactor は操作ごとに
  要る adds の表を持ち、索引を作る前（JVM を立てる前）に「flixlint を 0.8.7 以上へ上げる」で止める。
- **新しい口**
  - `bin/fge refactor retarget-field`: 受け手が引数そのものの欄の読みを、別の引数の同じ欄へ読み替える。読む所が 0 になる引数は
    fix で知らせ、`--drop-from` で外す並びと 1 つの計画にする。書き込み・受け手が式や局所の名前の読みは並べるだけ。
  - `change-signature --propagate --retarget <欄> --from <引数>`: 葉の本体の読み替えを、引数を広げる計画の内側の書き換えとして
    合わせる（make check 1 回）。前は「葉の本体が足す引数を使わない」で断られ、dry-run の diff を当てて本体を手で直していた。
- **直した不具合**
  - `--propagate` の「引数で渡せるか」の型の比べが名前の最後の部分だけを見ていて、`ViewEnv.Res` と `Res.Res` を取り違えた。
    今は索引の型（`syn=` で別名を写した先）で比べ、型の名前は葉のファイルのその mod の `use` → 同じ mod → 修飾名の順で引く。
  - 足す引数を使うかの数え方に、呼ぶ所に書く引数が入っておらず、間に挟まる def がある `--propagate` が毎回断られた。
  - 葉から引数を外すと、その引数を渡すだけだった呼び手の引数が空き、make check で全部戻った。今は書く前に fix で止める
    （remove-param も同じ）。
  - 同じ名前で別の型の引数を持つ def へ広げると make check で全部戻った。今は Stops に理由を出して止める。
- **hooks.json**: check の常駐（`checkd.server`）の flixlint を 0.8.7 へ上げた（`shimSha256` も）。上げ忘れは go test
  （`TestHooksPinReachesMinFlixlint`）で止まる。

## 追随の手順

1. **flixlint の submodule を v0.8.7 へ**（`git -C flixlint fetch --tags && git -C flixlint checkout v0.8.7`）。
2. **flix.toml の engine の版を 0.58.0 にし、`make sync-agents`**（`bin/fge-go` と hooks.json を受け取る）。
3. `bin/fge refactor field-sites --label <欄> --receiver <alias>` が前と同じ数を返すかを 1 つ確かめる（索引は adds つきで作り直される）。
