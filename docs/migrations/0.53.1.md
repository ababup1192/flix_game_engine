# engine 0.53.0 → 0.53.1 の手当て

自動生成の一覧は [0.53.1.auto.md](0.53.1.auto.md)（直す物 0 件）。ゲームで直す物は無い。

入ったのは 5 つ。

1. **GPU の動画を速く**（gpuvideo の案 3・案 4）:
   - GL の用意を別の糸で先に始める（`GlOffscreen.prepare` / `prepareInBackground` / `await`。`VideoOut.settingsOf` が入口の頭で始める）。
     シミュレーションの終わりから 1 コマ目まで 1.3〜1.4 s → 0.4〜1.0 s。
   - コマを直に最後の mp4 の ffmpeg へ流す口（`Encoder`。空なら今まで通り frames.mkv）。frames.json に `encoded` が付く。
     internet_dungeon の transition 910 コマ: 中央値 49.7 → 42.2 s・音の重ね 17 s → 0.05 s・frames.mkv（205 MB）を書かない。mp4 の絵と音は前後で同じ。
2. **効果音の一式を、同じ入力・同じプログラムなら合成しない**（sfxspeed・`SfxSynth.renderSetOnce`・`RenderCache.writtenFilesKept` / `noteWrittenFiles`）:
   鍵は入力（Doc のバイト列）・動いている jar の SHA-256・JVM と OS。書いた WAV の SHA-256 を塗りのキャッシュの置き場の files/ に控え、
   控えた全部が今もそのバイト列の時だけ作らない。jar から動いていない時（flix run・flix test）と `FGE_RENDER_CACHE=off` はいつも作る。
   internet_dungeon の reference-check 1 回 約 19.5 s → 約 7 s・WAV と動画の音のバイト列は前と同じ。
3. **jar の作り手がゲームの版のエンジンを自分で用意する**（jarprovision・`bin/fge jar builder run --engine-repo=<clone>`）:
   ゲームが次の版へ上がると、作り手がタグの作業場・fge-go・flix.jar をそろえる（タグがまだ無ければ待つ）。Studio の置き場では用意しない。
4. **塗りのキャッシュの鍵のエンジンの指紋を packages.lock から取る**（renderkey・`RenderCache.lockedEngineDigestOf`）:
   jar を段 1・段 2 から取ってきた lib/ の無い作業場でも、塗りのキャッシュが効く。lock の記録は fpkg の中身の SHA-256 と同じ字なので、
   lib のある作業場の鍵は変わらない。
5. **headless-run が flix を REPL として起こさない**: Studio 同梱の engine では bin/flix が Studio のラッパ（`FLIX_PRINT_JAR` を知らない）に
   置き換わり、jar を分け合う時の `FLIX_PRINT_JAR=1 bin/flix` が REPL になって、Studio から起こした jar 作りが標準入力を待って止まった
   （依頼主の Mac で 8 分）。標準入力を閉じて呼び、返った字が 1 行で `.jar` で終わる実在のファイルの時だけ分け合う。

## 新しく使える物

| 口 | 中身 |
|---|---|
| `SfxSynth.renderSetOnce` | 効果音の一式を、同じ入力・同じプログラムなら作らない（書いた WAV を控えて確かめる） |
| `RenderCache.writtenFilesKept` / `noteWrittenFiles` | 絵でない書き出し（WAV など）の一式が前のままかを鍵で確かめる・控える |

| `bin/fge jar builder run --engine-repo=<clone>` | 作り手が、ゲームの版のエンジンの置き場をそろえる |
