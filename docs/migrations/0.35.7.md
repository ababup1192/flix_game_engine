# engine 0.35.6 → 0.35.7 の手当て

自動生成の一覧は [0.35.7.auto.md](0.35.7.auto.md)（非互換 1 件）。

## なぜ変わったか

Studio は assets/*.json を保存するたびに、走行中のゲームへ全場面の描き出し（POST /render）を頼む。
これまではゲームループ（= 窓のスレッド）がそれを同期で回していたので、描き出しの数分間ゲームの窓が
「応答なし」になっていた（2026-10-15 internet_dungeon）。描き出しを専用のスレッドへ移した。

## 1. RemoteDebug.start が描き出しの実体を受け取るようになった

`/render` はゲームループに渡さず、命令口（HTTP）の側で描き出しのスレッドへ回すので、
命令口を立てる時点で `App.onRenderRequest` の関数が要る。

```flix
// 前
RemoteDebug.start(port)
// 後（描き出しを繋がないなら None）
RemoteDebug.start(port, app#remoteRender)
```

命令口は `App.launch` が立てる物で、ゲームが自分で `RemoteDebug.start` を呼ぶことは普通無いので、
`App.withDebug` と `App.onRenderRequest` を使っているだけなら直す所は無い。

## 2. App.onRenderRequest の関数は別のスレッドで呼ばれる（型は変わらない）

描いている間もゲームは動き続ける。関数の中で GL・音・ゲームと共有する可変の値に触れないこと
（Docs から場面を組み立てて PNG を書くだけの `SceneRender.all` 型の関数なら、そのままでよい）。

## 3. /render の応答（Studio と curl 向け）

- `POST /render`（クエリ無し）: 今までどおり。最大 9 秒待ち、済めば `ok rendered=N ms=M job=J`、
  済まなければ 503。1 行目の末尾に `job=` が増えた。
- `POST /render?async=1`: `ok accepted job=N` をすぐ返す。
- `GET /render`: `ok render requested=Q done=D running=R` と、描き終えた回があれば `[last]` にその回の応答。
  依頼 N は `done >= N` で済み（描いている間に来た依頼は終わった後の 1 回にまとまる）。
