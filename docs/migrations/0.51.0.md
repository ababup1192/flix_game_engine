# engine 0.50.0 → 0.51.0 の手当て

自動生成の一覧は [0.51.0.auto.md](0.51.0.auto.md)（`YarnRunner.Shown.Choices` / `Event.Choices` の中身が変わったのは出ないので、下の「台本の変数と条件」の 3 を見る）。

入ったのは 5 つ。

1. **塗りの高速化**: シェーダー面・頂点色の多角形・合成・フォントの表を速くした。internet_dungeon の reference-check は 243 秒から 47 秒になり、194 枚と雛形 6 本はバイトごと同じ。
2. **描き出しの常駐**: 窓なしのゲームを常駐させる。最初は `HEADLESS_RESIDENT=1` を付けた時だけ使う。設計は [docs/design/render-speed.md](../design/render-speed.md)。
3. **会話の台本（.yarn）の変数と条件**。
4. **lint-hoist**: ループの外に置いた式が、ループの中へ書き写される形を止める。
5. **会話のプレビューの 1 枚撮りは、橋が 60 秒待つ**（今までは 10 秒で「did not answer within 10s」になっていた）。

## ゲームで直す物

### 台本の変数と条件

1. **直さなくても効く所**: 変数も条件も `{式}` も使わない .yarn は、木（dialogue.json）が版 1 のままバイトごと同じに書かれる。組み直しは要らない。
2. `Yarn.Statement` を `case _` なしで match している所は、`Set(name, expr, source)` と `If(branches, source)` の 2 つを足す。
3. **`YarnRunner.Event.Choices` / `Shown.Choices` の中身が `List[Yarn.Line]` から `List[YarnRunner.DialogueOption]`（`{ line, available }`）に変わった**
   （公式と同じく、行末の `<<if>>` が偽の選択肢も `available = false` で並ぶ）。`lines` を受けていた所は `option#line` を読む。
   `Action.Choose(i)` の番号はこの並び（選べない物も数える）で、選べない番号は何も変えない。キーボードのカーソルが
   選べる物だけを数えているなら、番号へ写してから選ぶ（雛形 novel-starter の `World.pickAtCursor`）。
   灰色で見せるか隠すかはゲームが決める（novel-starter は灰色: `UiSlots.Entry` の meta を外し、`labelOff` へ字を移す）。
4. `Yarn.Line` に `parts`、`Yarn.Choice` に `condition` の欄が増えた（読むだけのゲームは直さなくてよい。出来事の Line の `text` は値を差し込んだ後の字）。
   `Yarn.Line` を字面で組んでいる所（テストの台詞など）は `parts = Yarn.Part.Literal(<text と同じ字>) :: Nil` を、`Yarn.Choice` は `condition = None` を足す
   （internet_dungeon の test/TestDocs.flix がこれで止まった）。

### 塗りの高速化

1. **`ShaderEval.compileSpec` を消した。** 面ごとに 1 回 `ShaderEval.compile(spec, texEnv)` で組み、画素ごとに
   `ShaderEval.evalCompiled(compiled, u, v, t)`（`(r, g, b, a)` を返す）を呼ぶ形に替える。
   `evalPixel` / `evalAlpha` / `evalPixelTex` などの画素 1 つの口は、そのまま残っている。
2. ほかは直さなくても効く（`SoftRaster.render*`・`HeadlessRender.renderPng*`・`RenderCache.writeFramePng` を通る絵）。

### 描き出しの常駐（使うゲームだけ。使わなければ今のままで動く）

1. **入口の形を `<名前>Job(req): Int32` にする。** 手本は雛形 6 本の `SceneRender.one` / `all` と `E2e.play` / `vocab`。
   - 中身は `App.Headless.envOf(req)` だけを読み、終了コードを返す。
   - 素の道の入口は 1 行にする: `pub def one(): Unit \ IO = App.Headless.exitWith(oneJob(App.Headless.requestFromProcess()))`。
   - 各モジュールに `pub def jobs(): List[App.Headless.Job]` を置き、中は `App.Headless.job("SceneRender", "one", req -> oneJob(req))` の形にする。
     `E2e.serveHeadless` がそれを `App.Headless.serveJobs(app, jobs)` で束ねる。
   - 動画の入口は `App.Headless.videoJob` で名乗る（GPU で塗る動画は常駐に送らない。今はまだ GPU の道は無い）。
2. **env と終了は入口の頭だけで扱う。** 奥で `System.getenv` を読むと、常駐では要求の値ではなく、常駐を起こした時の値が見える。奥の `System.exit` は、常駐ごと落とす。
   - engine の forbid の `process-env-entry` / `process-exit-entry` がこれを止める。ゲームの src は対象外だが、同じ形を `bin/lint-rules/forbid.local.json` に置くことを勧める。
   - engine の読み口: `ProcessEnv.snapshot()`（env の表）・`ProcessEnv.exitWith(code)`・`Flow.Cli.mainOf(app, env)`・`App.debugOf(env)`・
     `App.RemoteDebug.portOf(env)`・`Flow.Record.pathOf(env)`。今の口は残してあり、新しい口へ委ねている。
3. 取っておく物と要求ごとに作る物を、型で分ける。取っておく物は書体・Doc・アトラス（`ContentCache` で包む）。要求ごとに作る物は `SoftRaster.TextureCache`・`TexWarnLog`・World。
   分けないと、PNG を描き直した次の要求でも古い絵で塗り、知らせは 2 回目から消える。手本は internet_dungeon の `src/render/RenderKit.flix`。

### どのゲームも

1. **`bin/headless-run` は、jar が古いかを中身の指紋（`bin/fge resident manifest`）で決める。** 保存しただけ（touch）では作り直さない。
   直す物は無い。jar を作り直させたい時は、今までどおり `rm -rf build/headless`。
2. **lint-hoist（`bin/fge hoist`・precommit）が、ゲームの .flix にも当たる。**
   - Flix 0.78 は、純粋な let がラムダの中で 1 回だけ使われると、その式をラムダの中へ書き写す。そのため、ループの外に置いた式（関数を返す def・ループのラムダが使う let）は `once`（`onceOutsideLoop`）で包む。
   - どうしても残すなら `bin/lint-rules/hoist.local.json` の exempt に書く。詳しくは docs/performance.md「ループの外に置いた式がループへ戻る」。

## 新しく使える物

### 台本の変数と条件

| 口 | 中身 |
|---|---|
| `<<declare $x = 値>>`・`<<set $x to 式>>`・`<<if>>`〜`<<endif>>`・`-> 字 <<if 式>>`・`{$x}`・`visited("…")`・`visited_count("…")` | 宣言の無い変数・型の違いは build が行番号つきで止める |
| `YarnRunner.startWith(storage, program, node, now)` | 変数と訪れた数を持ち越して始める |
| `YarnRunner.storageOf` / `withStorage` / `valueOf(name, runner)` | ゲームから読む・書く（書いていなければ初めの値） |
| `YarnStorage.empty` / `get` / `set` / `visitCountOf` / `toJson` / `fromJson` | 変数の置き場・セーブの形 `{"variables": {...}, "visits": {...}}` |
| `YarnRunner.startAtWith(storage, program, node, line, now)` | プレビューで変数の値を決めてその行まで流す（`startAt` は初めの値） |
| `YarnStorage.withArgs(args, program, storage)` | 始まりの引数の `$名前=値` を宣言の型で読む（宣言の無い名前・読めない値は Err） |
| `bin/fge talk shot` / `goto <file.yarn>:<行> '$名前=値'…` | 始まり `talk node= line= $名前=値` を組んで撮る・飛ばす（ゲームの始まり `talk` が withArgs を通す） |
| `YarnRunner.DialogueOption` | 出した選択肢 1 つ `{ line, available }` |
| `Yarn.declarationOf` / `variablesOf` / `toText` | 宣言と値の字 |

### 描き出しの常駐（`HEADLESS_RESIDENT=1`）

| 口 | 中身 |
|---|---|
| `HEADLESS_RESIDENT=1 make render SHOT=…` など | 窓なしのゲームをゲームの根に 1 つ常駐させ、`bin/headless-run` の入口をそこで流す。使えない時（無い・jar が古い・塞がっている・env が違う・束に無い）は今の `java -jar` に戻る |
| `bin/fge resident status [--all]` | 立っているか・RSS・残りの寿命・流した数 |
| `bin/fge resident stop` | 畳む（render-all・reference-check・compare の口は、終わったら自分で畳む） |
| `bin/fge resident verify [--touch-doc D] [--touch-png P] -- <make の口>` | ゲームの根の写しで、素の道と常駐を 5 回流して比べる（書いたファイル・終了コード・整えた標準出力） |
| `App.Headless.Request` / `Job` / `JobKind` / `job` / `videoJob` / `serveJobs` / `serveJobsOnly` / `envOf` / `requestFromProcess` / `exitWith` | 常駐が受ける入口の束 |
| `ContentCache.loadOrBuild` / `loadOrBuildWithDirs` | build が読んだファイルの中身・有無・一覧を記録し、同じなら前の値を返すキャッシュ |

- **寿命**: 既定は 180 秒（`HEADLESS_IDLE_SECS`）。会話の要求（Studio・`talk shot`）が来ると 600 秒に延びる（`HEADLESS_TALK_IDLE_SECS`）。動画の入口を流した後は畳む。
- **起動時の env**: 常駐は決まったキーだけで起動する（`HOME PATH JAVA_HOME TMPDIR LANG LC_* JAVA_TOOL_OPTIONS HEADLESS_* FGE_RENDER_CACHE`）。要求の env は、要求ごとに入口へ渡る。
- **速さ**: internet_dungeon の `make render SHOT=title` は、常駐の 2 回目以降が約 0.6 秒（コールドは 3.7 秒）。PNG はバイトごと同じ。

### 会話のプレビューの 1 枚撮り（橋の待ち）

- `POST /step?view=shot` などの 1 枚撮りの要求は、橋が主の糸の答えを 60 秒待つ（ほかの要求は 10 秒のまま）。`wait=<秒>`（1〜600）で、要求ごとに変えられる。時間切れの答えの文面は変えていない。
- internet_dungeon の `start talk node=op_post line=19`（温まった後・Mac mini）は、0.50 の 3.1 秒が 0.51 では 1.9〜2.3 秒になった。
