# engine 0.80.0 → 0.81.0 の手当て

engine（契約層）から機種の物（スレッド・絵のデコード・プロセスの起動し直し・環境変数・確保の量を測る道具）を外へ出し、
開発の道具を 1 つの値 `App.DevTools` にまとめて、ゲームの起動の道から外した。
**絵とふるまいは変わらない**。古い口は 0.84.0 まで残すので、版を上げただけで止まるゲームは少ない
（止まるのは自前の `LoadProgress` の handler を書いている所と、`runNoop` を純粋な関数の中で呼んでいる所だけ）。

## 読み込みの並列とデコードは handler が持つ（`LoadProgress.runTasks`・`imageDecoder`）

- `LoadProgress` に op が 2 つ増えた: `runTasks(phase, tasks)`（仕事の並びを回す・並列にするかは handler が決める）と
  `imageDecoder()`（PNG / JPEG を画素に戻すデコーダー `ImageData.ImageDecoder` を返す）。
  `LoadProgress.parMapWithProgress` は中で `runTasks` を呼ぶだけになった（型は同じ・ゲームは直さなくてよい）
- handler の組: 実機 = `LwjglLayer`（スレッドの pool・javax.imageio）・画面なしとテスト = **`HeadlessLoad.handle`**（同じ・engine_tools）・
  `LoadProgress.runNoop` = 順に回す（知らせは捨てる）。並列の handler は「1 つ終わるたびと 50 ms ごとに知らせる・仕事が例外を投げたら
  残りを止めて同じ例外で抜ける」を守り、`LoadProgress.Conformance` が確かめる
- **自前の `LoadProgress` の handler**（テストで知らせを集める物など）は止まる。op を 2 つ足す:
  ```
  def runTasks(phase, tasks, k) = { LoadProgress.runTasksInOrder(push, phase, tasks); k(()) }   // 順に回す・知らせは push へ
  def imageDecoder(k) = k(ImageData.failingDecoder("このテストは絵を解かない"))
  ```
  仕事を回さないテストなら `def runTasks(_phase, _tasks, _k) = bug!("…")` でもよい。`runTasksInOrder` を使うと handler の型に `IO` が付く
- `LoadProgress.runNoop` の型が `a \ (ef - LoadProgress) + IO` になった（仕事を回すので IO が付く）。**純粋な関数の中で `runNoop` を呼んでいる所**は
  型に `IO` を足す。テストの関数なら `Unit \ {Assert, IO}`
- `runNoop` の下では仕事が**順に**回る（0.80 までは並列）。画面なしの e2e・動画・gallery が遅くなるので、`HeadlessLoad.handle` に替える（下の「ゲームで直す物」）
- `runNoop` の `imageDecoder` は 0.84.0 まで javax.imageio の物を返して 1 行知らせ、0.84.0 からは `bug!` で止まる
  （Err を返すと、絵が読めない時に既定値で続ける読み込みから部品が黙って消えるため）

## 絵はデコーダーを値で受け取って解く（`*Using` の API）

- 古い口には lint-forbid の `engine-jvm-old-calls` が知らせを出す（止めない）。
- 新しい口: `Texture3d.decodeUsing(decoder, bytes)`・`Texture3d.fromImage(image)`・`Gltf.fromGlbTexturedUsing(decoder, limits, bytes)`・
  `Gltf.loadTexturedUsing(decoder, limits, path)`。上限を掛けないなら `limits` に `Gltf.noTextureLimits()`
- 古い `Texture3d.decode`・`Gltf.fromGlbTextured`・`fromGlbTexturedWith`・`loadTextured`・`loadTexturedWith`（中で javax.imageio）は 0.84.0 で消える
- 書き方: 読み込みの関数の頭（本体のスレッド）で `let dec = LoadProgress.imageDecoder();` と受け取り、並列の仕事の関数へ引数で渡す
  （仕事の中から op は呼べない — effect の handler はスレッドをまたがない）

## 起動し直しは `LwjglLayer.ensureMainThread()`

- macOS で `-XstartOnFirstThread` を付けて起動し直す関数を render_gl へ移した（窓を開く GLFW の都合なので GL の層の仕事）。
  ゲームの `Main` の `GameEngine.ensureMainThread()` を **`LwjglLayer.ensureMainThread()`** に替える（ふるまいは同じ）。
  `use fge::{…}` に `LwjglLayer` が無ければ足し、ほかで使っていなければ `GameEngine` を外す
- `GameEngine.ensureMainThread` は 0.84.0 で消える

## `ProcessEnv`・`AllocMeter` は engine_world へ（名前はそのまま）

- `ProcessEnv`（環境変数の表・終了コードで終える）と `AllocMeter`（今のスレッドが確保したバイト数）を engine から engine_world へ移した。
  engine_full を依存にするゲームは直す所が無い（`fge::ProcessEnv.snapshot()` もそのまま届く）
- engine だけを見るパッケージ（render_gl・engine_tools・engine の層のテスト）からは見えなくなった

## 開発の道具は `App.DevTools`（道具なしの起動は `App.launchWithDevTools`）

- リモートデバッグの命令口（`DEBUG_HTTP_PORT`）・ゲームの名簿（`~/.flix_ge_studio/games.json`）・flow の記録（`FLOW_RECORD`）・
  ヒッチの見張り・Doc の保存検知（`watchFile`）・F8 の注釈の書き出し・環境変数の表（`START`）を、App が受け取る 1 つの値 `App.DevTools` にまとめた
  （Bevy の bevy_dev_tools と同じ考え）。`App.launch` と `App.loadAndLaunch` は今までどおりデスクトップの道具（`App.DevTools.desktop(env)`）で走る。
  **形もふるまいも変わらない**ので、`Main` を直す所は無い
- 道具なしで走らせる入口 `App.launchWithDevTools(App.DevTools.none(), app)` を足した（ブラウザ版の入口と、開発の道具を持たない起動）。
  命令口・記録・名簿・見張り・保存検知・注釈のコードへ呼び出しが届かず、`Platform.Annotation` の handler も要らない。
  環境変数を読まないので `START` も効かない（いつも先頭の始まりから）。F8 で止めて囲んでも注釈は書き出さない。
  この入口では `App.debugFromEnv()` も呼ばない（環境変数を読む JVM の API（System.getenv）が残る）。`App.withDebug` は値で渡す
- `App.launchForBench` は開発の道具を持たなくなった（bench の App は `withDebug` を使っていなかったので、ふるまいは同じ）。
  effect の列から `Platform.Annotation` が外れた（張っている handler はそのままでよい）
- `App.onRenderRequest`・`App.onShotRequest` は開発の道具の API なので、`Game.app`（テスト・flow・ブラウザ版と共有）ではなく
  `Main`（と画面なしの入口の `E2e`）で繋ぐ。lint-forbid の `dev-request-outside-main` が 0.81.0 から知らせ、0.84.0 から止める
  （`src/Main.flix`・`src/E2e.flix`・`src/render/`・`test/` は見ない）。テンプレ 4 本は 0.81.0 で `Main` へ移した
- 自前の handler で `Platform.Annotation` を張っていても直す所は無い（デスクトップの道具が今までどおり op を呼ぶ）

## engine/src の import を lint で止める

- lint-forbid に `engine-contract-import`・`engine-contract-jvm-call`・`engine-contract-system` を足した（engine/src だけに効く・コミット時に止まる）。
  `engine-contract-jvm-call` は `Sys.Env`・`ProcessBuilder`・`ProcessHandle`・`spawn`・`Channel.`・`*.runWithIO` も止める。
- engine/src が import してよいのは `java.lang.{Math, Float, Double, Object, Throwable, System}`（System は stderr だけ）・`java.math.*`・
  `java.security.MessageDigest`・`java.nio.ByteBuffer`・`java.lang.ref.WeakReference`
- 例外（古い口と一緒に消す）: `engine/src/GameEngine.flix`（0.84.0 で消える古い `ensureMainThread` と、同じ 0.84.0 で消える `loadScene3dLinearColor`）・
  `engine/src/scene3d/Texture3d.flix`（古い `decode`）

## ゲームで直す物

古い口は 0.84.0 まで残るので、コンパイルでは止まらない。次の版に上げる前に、名指しの所を直す。

### night_apartment

- `src/Main.flix:8` — `GameEngine.ensureMainThread()` → `LwjglLayer.ensureMainThread()`
- `src/Stage.flix` — `Stage.load` の頭で `let dec = LoadProgress.imageDecoder();` と受け取り、`decodePart(dec, d)` へ渡す。
  - `:85` `Texture3d.decode(b)`（lightmap の絵）→ `Texture3d.decodeUsing(dec, b)`
  - `:87` `Gltf.fromGlbTexturedWith(limits, bytes)` → `Gltf.fromGlbTexturedUsing(dec, limits, bytes)`
- `src/People.flix` — `People.load` の頭で受け取り、`:86` の並列の仕事 `raw -> decode(limits, raw)` を `raw -> decode(dec, limits, raw)` にして通し、
  `:95` の `Gltf.fromGlbTexturedWith(limits, b)` → `Gltf.fromGlbTexturedUsing(dec, limits, b)`
- 画面なしとテストの道は `LoadProgress.runNoop` → `HeadlessLoad.handle`（`use fge::HeadlessLoad` を足す）:
  `src/E2e.flix:12,18`・`src/render/VideoRender.flix:43`・`src/render/SceneRender.flix:21`・`test/TestStage.flix:39`・`test/TestKit.flix:55`

### fps3d_lab

- `src/Main.flix:9` — `GameEngine.ensureMainThread()` → `LwjglLayer.ensureMainThread()`
- `src/Controls.flix:62` — `Controls.loadModels` の頭で `let dec = LoadProgress.imageDecoder();` と受け取り、
  `Gltf.fromGlbTextured(bytes)` → `Gltf.fromGlbTexturedUsing(dec, Gltf.noTextureLimits(), bytes)`（上限は今と同じく掛けない）
- `src/ObjMesh.flix:89` — `Gltf.fromGlbTextured(bytes)` は並列の仕事（`Controls.flix:73` の `ObjMesh.build`）の中から呼ばれる。
  `Controls.loadMeshes` の頭で受け取り、`ObjMesh.build(dec, …)` と引数で通して `Gltf.fromGlbTexturedUsing(dec, Gltf.noTextureLimits(), bytes)` に
- 画面なしとテストの道は `LoadProgress.runNoop` → `HeadlessLoad.handle`:
  `src/E2e.flix:12,18`・`src/render/VideoRender.flix:43`・`src/render/SceneRender.flix:27`・`test/TestStarts.flix:5`

### ほかのゲーム

- `Main` の `GameEngine.ensureMainThread()` を `LwjglLayer.ensureMainThread()` へ（テンプレ 4 本は 0.81.0 で替えた）
- `src/Game.flix` などで `App.onRenderRequest(…)`・`App.onShotRequest(…)` を繋いでいたら、その行を `Main` の `App.loadAndLaunch` の中
  （`App.withDebug(App.debugFromEnv())` の隣）へ移す。ウィンドウなしのゲーム（`App.Headless.serveJobs`）が `view=shot` を使うなら、`E2e` の
  `serveJobs` に渡す App にも `App.onShotRequest` を足す（テンプレの sound-novel-starter の `E2e.serveHeadless` と同じ形）
