# engine 0.77.0 → 0.78.0 の手当て

コア設計の仕上げ（`plans/engine-core-polish.md`）の C2 をこの版に入れる。C2 は 3D の光の式を 1 つの元（`LightModel3d` の式の木）から
CPU の描き手と GL のシェーダーの両方へ出す。この版の前半は CPU の側を木から作った物へ替えた。

## C2 前半: 光の式の木と、木から生成した CPU の光の関数

絵は 1 bit も変わらない（gl-parity の全部の行と CPU の絵の SHA・3D の部屋の CPU の絵の SHA・`TestSoftRaster3dPinned` が C0 の基準と同じ。
GL のシェーダーはまだ手書きのまま）。CPU の描く時間は C0 の基準から +10% 以内（bench/scene3d と gl-parity の 3D の場面・並列と 1 スレッドの両方）。

### ゲームで直す物

- `Scene3d.skyColorOf` を消した（engine の外では使われていない）。空の色の式は `LightModel3d.skyModel` に 1 本だけ置き、
  CPU の描き手は生成した `SoftRaster3dLight.skyAt` で、GL は空のシェーダーで回す。空の色を自前で計算していたなら、`Scene3d.skyFieldsOf` と
  `Scene3d.skyCurveOf` から `LightModel3d.skyModel` の doc の式（horizon + (toward − horizon) × min(1, |dir.y|^curve)・toward は dir.y ≥ 0 なら zenith、ほかは ground）で書く
- `SoftRaster3d.wrap` を消した（いつも 0 で、engine の外では使われていない。光の式の木の中だけに置く）

### 振る舞いが変わる物

無い。

### 足した物（使わなければ何も変わらない）

- `LightModel3d`（engine の 3D の部品）: 光の式を書く式の木（`ScalarExpr`・`Vec3Expr`・`Cond`）と、今の式を 1 回だけ書いた
  `lightingModel`・`lightmapLightingModel`・`fogModel`・`skyModel`、コード生成の `LightModel3d.Codegen`（engine の開発用・ゲームは使わない。`toGlsl(名前, 画素ごとの入力の並び, 式)`＝GLSL の関数の字・`generateFlix`＝CPU の光の関数のソース・`generateFlixCases`＝生成器のエッジケースを集めた確かめ用のソース）、
  CPU へ渡す光の並び `packPointLights`・`packSpotLights`
- engine_tools の `SoftRaster3dLight`（`engine_tools/src/gen/SoftRaster3dLight.flix`）: `LightModel3d.Codegen.generateFlix` が書いた CPU の光の関数。手で直さない。
  生成した関数から呼ぶため `SoftRaster3d.shadowFactorAt`（影を落とすスポットの割合）と `SoftRaster3d.SpotShadow`（その型）を pub にした（ゲームは使わない）
- engine の開発の口（ゲームには配らない。書き出す口 `SoftRaster3dLightGen` は engine_tools の test の側に置く）:
  - `make gen-light3d`（木を直したら CPU の光の関数と確かめ用のソース `engine_tools/test/gen/SoftRaster3dLightCases.flix` を作り直す。入っている物と木が食い違うと engine_tools の `TestSoftRaster3dLight` が落ちる）

### 気をつける事

- 光の式を直す所は `LightModel3d` の木だけ（直したら `make gen-light3d`）。`SoftRaster3d` の頭の式の説明は木の外（入力の作り方・光を色に掛ける所）だけになった

## C2 後半: GL のシェーダーも光の式の木から作る・式の行・Render3d の分け方

gl-parity と CPU の絵は 1 bit も変わらない（gl-parity の全部の行の GL と CPU の絵の SHA・差の数が 0.76.0 の基準と同じ。3D の部屋の CPU の絵・`TestSoftRaster3dPinned` も同じ）。
GL の 3D の光・かすみ・空・lightmap の足し方の GLSL は、手で書いた字をやめて `LightModel3d.Codegen.toGlsl` が木から作る。木と手書きの細部の違い
（向きの正規化・range² の下限・影を引く条件・かすみの混ぜ方）は、この機械の 8 bit の絵には出なかった。GL の絵は GPU とドライバの丸めで ±1 が出うるので、
ほかの機械では 3D の場面の GL の絵が変わることがある（gl-parity の差の数の上限の中）。
CPU の描く時間は C0 の基準から +10% 以内（bench/scene3d の並列 36〜41 ms・1 スレッド 146 ms）。
GPU の時間は `FrameDiagnostics.gpuNs` で測る決まりだが、この Mac（macOS 27 の GL）は窓を見せても GL_TIMESTAMP が 0 を返し測れなかった。
代わりに bench/scene3d の窓を windowScale 8 にして fragment を重くし、垂直同期を切った 1 コマの時間の p50 を前後で 3 回ずつ交互に比べた
（前 1.74 ms・後 1.74 ms）。night_apartment は engine が 0.75 系の写しのため測っていない。3D の GL のキャプチャで変わったのは bench/scene3d の 1 コマの 1 画素（±1）だけ。

### ゲームで直す物

- `Texture3d.srgbToLinearGlsl`・`Texture3d.linearToSrgbGlsl` が作る GLSL の関数を `vec3 → vec3` から `float → float` にした（光の式の木が成分ごとに呼ぶため）。
  自前のシェーダーで vec3 を渡していたなら、成分ごとに呼ぶ
- 3D の描き手のシェーダーの字の口（`Render3d.meshVertexSource`・`materialVertexSource`・`materialFragmentSource` など）を `Render3dGlsl` へ移した（engine の中で使う。ゲームは使わない）

### 振る舞いが変わる物

- 法線マップの絵は、タンジェントの長さを見る前にいつも読む（読みの段を選ぶ微分は、画素ごとに分かれる if の中では値が決まらないため）。絵は変わらない

### 足した物（使わなければ何も変わらない）

- `LightModel3d.ScalarExpr.InverseSqrt`（1 / sqrt(x)。GL は `inversesqrt` 1 つ）
- render_gl の `GlOffscreen.drawFloatRows`（今の GL の文脈で、任意の frag を width × 1 の RGBA32F に uniform の組ごとに塗り、GL_FLOAT で読み返す）と
  入力の型 `RowUniform`・`RowTexels`・`RowLevel`・`RowTexture`
- render_gl の `Render3dGlsl`（3D の描き手のシェーダーの字。光は `lightSource`・lightmap の光は `lightmapLightSource`・空は `skyLightSource`・法線マップの式は `applyNormalMapSource`）
- engine_tools の `SoftRaster3d.spotShadowOf`（影を落とすスポット 1 本）・`SoftRaster3d.shadowLitFractionAt`（影の地図の PCF で照らされている割合）・`SoftRaster3d.rowMajorOf`（行列の行優先の 16 個）・
  `SoftRaster3d.applyNormalMap`（法線マップで傾けた法線）。CPU の描き手がこれを呼び、gl-parity の式の行が GL の同じ関数と比べる
- gl-parity の式の行（E 段階・`bench/gl_parity/src/ExprRows.flix`）: 光（lightAt・lightmapLightAt）・霧・空・トゥーンの段・影の地図の PCF・法線マップの TBN・
  lightmap の段つきの読みを、256 組の入力で GL と CPU に同じ値を入れ、8 bit に丸める前の値で比べる。わざと壊した式が上限を超えることも毎回確かめる。
  上限と外す組の根拠は ExprRows の頭
- bench/scene3d の窓（`make -C bench/scene3d run`）が GPU の時間の p50（`FrameDiagnostics.gpuNs`）も出す。macOS の GL は GL_TIMESTAMP が 0 を返すので「測れない」と出る
- `bin/lint-rules/forbid.json` の `light-uniform-in-glsl`: 字の中の GLSL で光の uniform を名前の添字で引く形（`"…uPointPos[i]`）を止める（`Render3dGlsl` と字を作る `LightModel3d.Codegen` は外す。`loc(program, "uPointPos")` は止めない）

### 気をつける事

- 3D の光の式の GLSL を手で書かない。木（`LightModel3d`）を直せば GL と CPU の両方が変わる（CPU は `make gen-light3d` で作り直す。GL は走る時に木から作る）
- 木の外に残る GLSL（影の地図の PCF・法線マップの TBN・lightmap の段つきの読み）を直したら、CPU の側の同じ関数も直し、`make gl-parity` の式の行で確かめる
- `Render3d.flix` を分けた: 影の地図は `Render3d.Shadow`・材質と場面の絵は `Render3d.Material`（`render_gl/src/Render3d/`）・シェーダーの字は `Render3dGlsl`
