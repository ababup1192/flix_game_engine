# engine 0.77.0 → 0.78.0 の手当て

コア設計の仕上げ（`plans/engine-core-polish.md`）の C2 をこの版に入れる。C2 は 3D の光の式を 1 つの元（`LightModel3d` の式の木）から
CPU の描き手と GL のシェーダーの両方へ出す。この版の前半は CPU の側を木から作った物へ替えた。

## C2 前半: 光の式の木と、木から生成した CPU の光の関数

絵は 1 bit も変わらない（gl-parity の全部の行と CPU の絵の SHA・3D の部屋の CPU の絵の SHA・`TestSoftRaster3dPinned` が C0 の基準と同じ。
GL のシェーダーはまだ手書きのまま）。CPU の描く時間は C0 の基準から +10% 以内（bench/scene3d と gl-parity の 3D の場面・並列と 1 スレッドの両方）。

### ゲームで直す物

- `Scene3d.skyColorOf` を消した（engine の外では使われていない）。空の色の式は `LightModel3d.skyModel` に 1 本だけ置き、
  CPU の描き手は生成した `SoftRaster3dLight.skyAt` で、GL は空のシェーダーで回す。空の色を自前で計算していたなら、`Scene3d.skyFieldsOf` と
  `Scene3d.skyCurveOf` から `LightModel3d.skyModel` の doc の式（horizon + (toward − horizon) × min(1, |dir.y|^curve)・toward は dir.y ≥ 0 なら zenith、ほかは ground）で書く
- `SoftRaster3d.wrap` を消した（いつも 0 で、engine の外では使われていない。光の式の木の中だけに置く）

### 振る舞いが変わる物

無い。

### 足した物（使わなければ何も変わらない）

- `LightModel3d`（engine の 3D の部品）: 光の式を書く式の木（`ScalarExpr`・`Vec3Expr`・`Cond`）と、今の式を 1 回だけ書いた
  `lightingModel`・`lightmapLightingModel`・`fogModel`・`skyModel`、コード生成の `LightModel3d.Codegen`（engine の開発用・ゲームは使わない。`toGlsl(名前, 画素ごとの入力の並び, 式)`＝GLSL の関数の字・`generateFlix`＝CPU の光の関数のソース・`generateFlixCases`＝生成器のエッジケースを集めた確かめ用のソース）、
  CPU へ渡す光の並び `packPointLights`・`packSpotLights`
- engine_tools の `SoftRaster3dLight`（`engine_tools/src/gen/SoftRaster3dLight.flix`）: `LightModel3d.Codegen.generateFlix` が書いた CPU の光の関数。手で直さない。
  生成した関数から呼ぶため `SoftRaster3d.shadowFactorAt`（影を落とすスポットの割合）と `SoftRaster3d.SpotShadow`（その型）を pub にした（ゲームは使わない）
- engine の開発の口（ゲームには配らない。書き出す口 `SoftRaster3dLightGen` は engine_tools の test の側に置く）:
  - `make gen-light3d`（木を直したら CPU の光の関数と確かめ用のソース `engine_tools/test/gen/SoftRaster3dLightCases.flix` を作り直す。入っている物と木が食い違うと engine_tools の `TestSoftRaster3dLight` が落ちる）

### 気をつける事

- 光の式を直す所は `LightModel3d` の木だけ（直したら `make gen-light3d`）。`SoftRaster3d` の頭の式の説明は木の外（入力の作り方・光を色に掛ける所）だけになった
