# engine 0.113.x → 0.114.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## glb を読む API を Model3d.loader / load / decode の 1 組にした

`Gltf` の読む関数 10 通り（`load`・`fromGlb`・`fromGlbKeyed`・`loadTexturedUsing`・`fromGlbTexturedUsing`・`loadTexturedPbrUsing`・`fromGlbTexturedPbrUsing`・
`loadTexturedUsingOptions`・`fromGlbTexturedUsingOptions`・`fromGlbTexturedKeyedUsingOptions`）を消した。ゲームは読み込みの頭で `Model3d.loader()` を 1 回作り、
道を渡すだけにする。鍵の有無（ブラウザは道と版から形の鍵を作り、絵を wasm へ運ばない）は `Model3d.decode` が道から決める。
PBR・頂点の色・絵の上限は project.json の任意キー `"gltf"` に書く（`{"pbr": Bool, "vertexColors": Bool, "maxTextureSide": Int, "maxNormalSide": Int}`・無い欄は今までの既定）。

| 前 | 後 |
|---|---|
| `let decoder = LoadProgress.imageDecoder()`（読み込みの頭） | `let loader = Model3d.loader()`（同じ所。並列の仕事・BackgroundLoad の decode へは loader を渡す） |
| `Gltf.load(path)` | `Model3d.load(loader, path)` |
| `Gltf.loadTexturedUsing(decoder, limits, path)` | `Model3d.load(loader, path)`・limits は project.json の `"gltf": { "maxTextureSide": …, "maxNormalSide": … }` |
| `Gltf.loadTexturedPbrUsing(decoder, limits, path)` | `Model3d.load(loader, path)`・project.json に `"gltf": { "pbr": true }` |
| `Gltf.loadTexturedUsingOptions(decoder, { vertexColors = true \| Gltf.defaultLoadOptions() }, path)` | `Model3d.load(loader, path)`・project.json に `"gltf": { "vertexColors": true }` |
| `Gltf.fromGlb(bytes)`・`Gltf.fromGlbTexturedUsing(decoder, limits, bytes)`・`Gltf.fromGlbTexturedUsingOptions(decoder, options, bytes)` | `Model3d.decode(loader, path, bytes)`（path は鍵と Err に使う。BackgroundLoad の read で道とバイトを組にして返す） |
| `Gltf.fromGlbKeyed(key, bytes)`・`Gltf.fromGlbTexturedKeyedUsingOptions(key, decoder, options, bytes)` | `Model3d.decode(loader, path, bytes)`（key は decode が `versionedKey(path)` から作る） |
| `BackgroundLoad.Group[Result[String, Vector[Int8]], Model3d.Model3d]` の read が バイトだけ | `BackgroundLoad.Group[Result[String, (String, Vector[Int8])], Model3d.Model3d]`・read は `Fs.FileRead.readBytes(p) \|> Result.map(b -> (p, b))`・decode は `raw \|> Result.flatMap(pb -> Model3d.decode(loader, fst(pb), snd(pb)))` |

- 1 つの形にだけ違う選択肢（手に持つ物だけ PBR など）が要るゲームは、その所だけ `Gltf.decodeWith(decoder, options, key, bytes)` を使い、
  `bin/lint-rules/forbid.local.json` の exempt に `"<パス>::gltf-old-loaders"` と理由を 1 行書く（`Gltf.decodeWith` は engine のテストと bench が使う APIで、ゲームの src では forbid が知らせる）。
- 絵の無い glb（当たり判定の形など）も `Model3d.load` / `decode` で読む（参照されない絵は解かない）。`Model3d.loader()` は `LoadProgress.imageDecoder` を受け取るので、
  `LoadProgress.runNoop` の下では止まる。絵を読まない読み込みを runNoop で回していたゲームは `HeadlessLoad.handle` で包む。
- `Gltf.fromGlb` が返していた「材質を付けず `gltfMaterial` だけ載せた形」は無くなった（材質を見ないなら `part#material` を読まなければよい）。
- `ProjectLoader.Project` に `gltf` の欄が増えた（`Project` を字で全部の欄を書いて作っている所は `gltf = Gltf.defaultLoadOptions()` を足す）。

## glb を解く仕事が軽くなった（前と同じ値）

`Gltf` の読み方から、番号で引くたびの配列の作り直しと、絵を切るたびの束全体のコピーを消した（M4 Pro の Chrome で primitive 388 の束が 174 → 96 ms）。
返す値は前と同じ（形・材質・絵とも）。

## 後回しの大きな glb の束を export-web が知らせる

`bin/fge export-web` が、`web.deferred` の glb のうち primitive が 200 個を超える束を 1 行知らせる（止めない）。遊んでいる最中に届くと、解くコマがその束 1 つで止まる。
束を分けるか、暗転の間（`LoadProgress.DecodeBudget.Covered`）だけに解く（docs/startup.md の予算の節）。

## retro3d-horror-starter から作ったゲーム: 束を半分に分け、遊んでいる最中は 1 コマに 1 束だけ解く

テンプレートの `tools/glb_bundle.py` は 1 階の小物（props_1f）と 2・3 階（upper）を primitive の数で半分ずつ（`props_1f_a`・`props_1f_b`・`upper_a`・`upper_b`）に作る。
`Controls.decodeBudget` は遊んでいる最中を `Idle(45)`（`Bundles.group` の `costMs` 35）にし、`Covered(40)` はマップとアイテム画面を開いている間だけにした。

| 前 | 後 |
|---|---|
| `tools/glb_bundle.py` の `bundle_plan` が props_1f・upper を 1 つずつ | テンプレートの `bundle_plan`・`halves`・`primitive_count` を写し、`bin/fge task bundles` で作り直す |
| project.json の `web.deferred` に `bundle/props_1f.glb`・`bundle/upper.glb` | `props_1f_a.glb`・`props_1f_b.glb`・`upper_a.glb`・`upper_b.glb` |
| `Bundles.group` の `costMs = 120.0` | `costMs = 35.0` |
| `decodeBudget` が今要る鍵の届いた時に `Covered(40.0)` | マップ・アイテム画面の間だけ `Covered(40.0)`・今要る鍵が届いていれば `Idle(45.0)`・ほかは `Idle(4.0)` |
