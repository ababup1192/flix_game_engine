# engine 0.41.0 → 0.42.0 の手当て

自動生成の一覧は [0.42.0.auto.md](0.42.0.auto.md)。

技法帳の技法を、ドット絵の道具 `bin/fge px` の検査（どれも advice）と低い所の部品へ入れた。絵が自分は何かを宣言すると
当たる検査が決まる仕組み（kind）と、塗りの細かさの軸（fidelity。0.42.0 は仕組みだけ）を足した。Flix の API は変えていない。

1. **legend の印に右から左へ書く字（ヘブライ・アラビアなど）・幅が 1 でない字・結合文字を使っている sprite.json は止まる**
   （`px.sprite.legend-char`。px check・fge sprite・px build）。`bin/fge px relegend --write <sprite.json…>` で、画素はそのまま
   ASCII の字へ振り直す（全部のコマの色キーが同じかを確かめてから書く。描いた PNG はバイトまで同じ）。
2. ほかは何もしなくても今までどおり動く。新しい検査は全部 advice（終了コードに効かない）。
   - kind を書いていない sprite は推した kind で回り、advice `px.decl.kind-missing` に貼れる 1 行が出る（`bin/fge px decl --suggest` で一覧）。
   - lint-sprite の対象外に知らない規則名（`対象外(icon)` など）があれば advice `px.decl.lint-sprite-unknown`（0.43.0 で止める）。
   - 色の門の画風に `fidelity` が無ければ near `px.decl.fidelity-unknown`（0.43.0 で必須）。

## 新しく使える物

### 絵の種類（kind）

- pxsrc の一番外の `"kind"`（既定）と sprite の `"kind"`（上書き）: tile・character・prop・icon・ui・background・vfx。
  定義と当てる検査の束は `bin/fge px kinds`。px build は宣言した kind を sprite.json の sprite に書き出す（手描きの sprite.json は直に書く）。
- kind で当てる検査が決まる（base ∪ kind の add − kind の skip）。担当は検査を切れない（`--skip` は無い）。
  外した物は report の `check.summary.applied` の skipped に出どころと理由つきで出る。kind:tile は端を回して見る（seam・orphan の 3×3）。
- 宣言の検査（advice）: `px.decl.kind-missing`・`kind-unknown`・`kind-mismatch`（推した kind と違う時。`"kind_why"` に 8 字以上で理由）・
  `material-missing`（character・prop・background の大きな部品。材質が無い物は `"material": "none"`）・`fidelity-unknown`・`fidelity-over`・
  `lint-sprite-unknown`。fix.try に宣言を直す疑似の op（`set kind`・`set material`）。

### 塗りの細かさ（fidelity・仕組みだけ）

- 色の門（`*.colorgate.json`）の styles に `fidelity`（0 low-bit 〜 1 hi-bit）・`rampSteps`（[最小, 最大]）・`dither`（none・accent・primary）、
  free の files に `fidelity`。無ければ機種（px.json の styles: gb4 0.1・nes 0.2・snes 0.5・pc98 0.5）・どちらも無ければ不明。
  担当は spec で値を選べない。
- 軸で動く検査（今は black-outline）は px.json の `fidelityRanges` の外で advice へ下がる（0.42.0 は全部 [0, 1)）。
  閾値は数か折れ線 `{"by": "fidelity"|"size", "at": [[x, 値], …]}`（0.42.0 の px.json は数のまま）。

### 技法帳の検査（どれも advice。閾値は bin/lint-rules/px.json・決めた根拠は同じ所の why）

- `px.highlight-reserve.area` / `.inside`（最明色はハイライト専用）・`px.ground-contrast.highlight` / `.chroma`（地はハイライトより暗く・明るい地は低彩度）・
  `px.ramp-hue.step` / `.turn` / `.flat`（色相を同じ向きに回す）・`px.ramp-chroma.peak` / `.bright`（彩度は山の形・高明度で下げる）・
  `px.value-blobs.count` / `.cover`（明暗の骨格）・`px.tile-variant-edge`（変種は中央だけ）・`px.outer-aa`（外周に中間色を置かない）・
  `px.glow.core` / `.dim`（発光の作法: 依頼主の決定の案 C）・`px.exempt-overuse`（Exempt の使い過ぎ）。
- `bin/fge px measure <sprite.json…>`: 技法帳の検査の値の分布（code ごとの数・外れ・p10/p50/p90・悪い順）。閾値を採用済みの絵で決め直す時に。

### 台本の低い所の部品と機械的な op

- 台本: `px.canvas(w, h, ramps=)`（格子の置く・読む・段をずらす・op `pixels` への書き出し）・`px.band(kind, …)`（位置ごとの帯の番号）・
  `px.shape_light(shapes, field)`（形ごとの帯と光の側の縁）・`px.ramp(base, n=5, hue_step=12)`（ramp-order・ramp-hue・ramp-chroma を満たす段の列）。
- op: `pixels`（格子の書き出し）・`tile_wrap_offset`（タイルの 50% ずらし）・`rim_light`（縁の光の置き場）・`panel_seams`（継ぎ目とネジ）・
  `hazard_stripes`（45° の縞）・`courses` の `widths`（煉瓦の大きさのばらつき）。どれも原理を丸ごとやらない（組み方は台本が決める）。
- `bin/fge px relegend`（上）・印は ASCII の表示できる字を先に振る（足りない時だけ決まった並び）。
