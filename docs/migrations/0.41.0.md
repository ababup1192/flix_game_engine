# engine 0.40.0 → 0.41.0 の手当て

自動生成の一覧は [0.41.0.auto.md](0.41.0.auto.md)。

ドット絵と音の検査の返し方を 1 つの形にそろえた（Go の `go/internal/checkres`）。Flix の API は変えていない。

## ゲームで直す物

ありません。何もしなくても今までどおり動く。

- 検査の合否は変わらない（ゲームの作業場の絵 61 本と音 13 本を 0.40.0 と 0.41.0 で流し、gate の外れと書き出した物が同じなのを確かめた）。
  engine の testdata の絵は今までどおりバイトまで同じ。
- `bin/fge px check`（make lint-px・pre-commit の口）の終了コードは今までどおり 0 か 1。
- 人向けの出力は今までの行のまま、`検査: score …・… → next …` の 1 行が足される。

## 新しく使える物

- 1 件ごとの数: code・status（pass / near / fail）・got・want（向きと値）・unit・ratio・gap・where・cause・fix.try（op・arg・now・try・expect）。
  形は engine の `docs/check-results.md`、全部の code は `docs/check-codes.md`（`bin/fge check codes`）。
- まとめ: score（0〜100）・next（次の周でまず直す 1〜3 件）・applied（当てた検査の組。変わらなければ id だけ）・exempt（外した画素の数）。
  `report.json` と `--json` の頭の `check` に入る。
- 終了コード（px build・px snap・snd build・snd snap）: 0 合格・1 gate の外れ・2 lint の fail だけ（near と advice は 0）。
  `px check --strict` も同じ。**px build を make や台本の中で呼んでいて、lint で止めたくない時は 2 を通す**（今までは 0 だった）。
- 周回: `bin/fge px snap` / `bin/fge snd snap` が前の周との code ごとの差と止め時の判定（stop: clear・budget・no-gain・same-next）を出す。
  `--tokens 使った/予算` を渡すと予算でも止める。`bin/fge px diff <spec> rA rB` も code ごとの差を出す。
- `bin/fge px build --only <code>`（調べ物）・`--no-check` は周の外: `debug/px/<名前>/probe/` に書き、last と周の比べを触らない。
  `--explain` で applied と exempt を毎回全文で出す。
- 帯・点・止め時の数は `bin/lint-rules/checkfmt.json`（sync-agents で届く）。

## エンジンの口（エンジンを直す人へ）

### 新しい検査を足す・今の検査を新しい形へ乗り換える（px-vs など）

違反の組み立ては 1 か所にした。直に `violation{…}` / `finding{…}` を書くとテストが止める
（`TestViolationsAreBuiltInOnePlace`・`TestFindingsAreBuiltInOnePlace`）。

1. **表に code を載せる**: px は `go/internal/px/codes.go` の `pxCodes`、snd は `go/internal/snd/codes.go` の `sndCodes` に 1 行
   （Name・Level・Metric・Unit・Op（基準の向き）・Rule（基準の出どころ）・Summary）。code は `px.<検査>[.<規則>][.<測り方>]`。
   1 つの検査で測り方が 2 つあるなら `.sub("…")` で分ける（例 `px.flat-run.repeat` と `px.flat-run.straight`）。
2. **組み立てを置き換える**: 
   ```go
   // 前
   out = append(out, violation{Check: checkX, Level: levelLint, X: p.X, Y: p.Y, HasAt: true,
       Msg: fmt.Sprintf("差 %.3f（%.2f 以上にする）", d, lim)})
   // 後: 測った値（got）と基準（want）を渡す。文は今のままでよい
   out = append(out, newViolation(checkX, levelLint, d, checkres.WantAtLeast(lim),
       fmt.Sprintf("差 %.3f（%.2f 以上にする）", d, lim)).at(p))
   ```
   外れの数を数える検査は got に数・want は `WantAtMost(0)`。基準の向きは表の Op と同じにする（違うと `checkres.New` が panic）。
   snd は `newFinding(check, level, got, want, msg)` に、`f.Sub`・`f.Ms`・`f.Channel`・`f.Tries` を足す。
3. **数の候補（fix.try）**: build で spec が見える物は `go/internal/px/tries.go` の `triesFor` に、検査ごとの case を足す
   （`argNow(call, "引数")` で今の値・既定を引く）。見込めない物は `Expect` を書かない。
4. **確かめる**: `go test ./internal/px ./internal/snd` の TestMain が、テストで組み立てた違反を全部 `result()` に通して、
   code が表にあり、基準の向きが表と同じかを見る。`go test -v` の最後に「テストで出なかった code」が出るので、
   新しい code には外れる例を `codes_fire_test.go` か検査のテストに 1 本足す。`bin/fge check codes --md` で docs を書き直す。

### そのほか

- 共有の形: `go/internal/checkres`（result.go = 1 件と New・codes.go = code の表・summary.go = score / next / applied・
  rounds.go = 周の比べと stop・history.go = rN.check.json）。`checklevel` に当てた検査の組の型（Applied・Skip）。
- `sprite.Finding` と `anim.Note`（`MeasureSequence`）に測った値（Got・Limit・AtMost）を足した。`fge sprite` と `fge anim` の出力は変わらない。
- `px.anim.palette` は px build では回していない（MeasureSequence が palette を外す）ので表に載せない。
- 宣言（kind）で当てる検査を選ぶ仕組みは 0.42.0（checkset-design §8）。0.41.0 は applied・exempt・next の形と、`--only`・`--no-check` の出力先まで。
