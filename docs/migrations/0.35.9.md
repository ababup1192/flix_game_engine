# engine 0.35.8 → 0.35.9 の手当て

自動生成の一覧は [0.35.9.auto.md](0.35.9.auto.md)（非互換 0 件）。コードの API は変わっていない。
変わったのはコミット時の検査で、**z-table がコミットを止めるようになった**。

## なぜ変わったか

- z の数が表の外や何本ものファイルに散る形は、0.35.8 では警告だけだった。internet_dungeon で直しきれたので、
  この版から止める
- 別の画面の z を借りる形と、World に大きな record を包まずに置く形を見る検査を足した。
  どちらも誤検知の出方を見るため、まだ警告だけ

## 1. `bin/fge z-table` がコミットを止める（借用は警告だけ）

`.flix` をステージしたコミットで、そのファイルのパッケージに次があると止まる:

- `ZOrder.flix`（z の表）があるのに、表の外で `def zXxx(): Int32 = 数` と書いた
- 表が無く、z を数で決めるファイルが 2 本以上ある

直し方は [0.35.8.md](0.35.8.md) と同じ（数を 1 ファイルに集めるか、`ZOrder.flix` を表にして段から作る）。
残すなら `bin/lint-rules/z-table.json` の `exempt` へ `"パス::宣言名": "理由"`。

**新しく見るようになった物（警告だけ）**: 同じパッケージの別のモジュールが決めた z の値を
`CardsView.zPickCard()` や `use CardsView.{zPickCard}` で借りている所。その z がどの帯・層の物かは
貸した側にしか書かれておらず、貸した側が数を動かすと借りた側の前後も黙って変わる。
要るなら表から自分で引く。止めるかどうかは `z-table.json` の `borrowWarnOnly` で決まる（今は true）。

## 2. `bin/fge record-wrap` が警告を出す（止めない）

`World.World` の欄に、展開すると 16 欄以上になる record をそのまま置いていると警告する。
大きさは入れ子の record と `List[...]`・`Option[...]` の中の record まで数える
（欄 3 つでも中身が大きければ型検査は同じだけ重い）。
直し方は [docs/flix-conventions.md](../flix-conventions.md)「World が直接持つ大きな record は enum で包む」。
閾値と見る型は `bin/lint-rules/record-wrap.json`。
