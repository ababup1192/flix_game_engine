# engine 0.56.0 → 0.57.0 の手当て

自動生成の一覧は [0.57.0.auto.md](0.57.0.auto.md)（直す物 0 件）。Flix の pub は変わらない（変わったのは Go の `bin/fge refactor` だけ）。

minor を上げるのは、**`bin/fge refactor` が flixlint 0.8.6 以上（索引の形 3）を要るようになった**ため（下の 1）。

## 1. refactor の欄の受け手の判定を索引に寄せた（flixlint 0.8.6・索引の形 3）

- **何が変わるか**: 欄の読み書きの受け手を、Go が字で判定し直すのをやめ、flixlint の索引が出す判定済みの事実 `owner=`
  （alias・case・other・ambiguous・maybe・none）と候補 `cands=` を引く。扱い（数える・並べる・書く）は 1 つの表 `FieldActs` に
  まとめ、remove-field・move-fields --finish・field-sites・usages・field-to-accessor が同じ表を引く。証明できない物は `maybe` で、
  消す操作では数える側（止まる側）へ倒す。
- **flixlint が古い時**: 索引を作る前（JVM を立てる前）に「flixlint を 0.8.6 以上へ上げる」で止まる。古い索引を読む分かれ道は消した。
- **`--flixlint` / `FGE_FLIXLINT` で名指しした flixlint** には `make check` の常駐の shim を渡さない（名指しした版の索引を書かせる）。

## 2. 直した不具合

- `remove-field --receiver` が、欄の組の違う別の record の同じ名前の欄（`r: { keys = …, … }` の `r#keys`）を数えて止まった。
  `--skip file:line` が直の読み書きに効かなかった。
- `change-signature --propagate` が、同じ型の `_res` を持つ def に `res` を足して引数を二重にした（今は `_res` を `res` に替えて使う）。
- `remove-field` が欄を消す時に、record の説明（最初の欄の前）や節の見出しのコメントまで消した。最初の欄を消すと次の欄の説明が
  `{` の直後に来て、Flix 0.78 が「Expected ',' before '='」で止めた（record の型の `{` の直後のコメントは読めない）。

## 追随の手順

1. **flixlint の submodule を v0.8.6 へ**（`git -C flixlint fetch --tags && git -C flixlint checkout v0.8.6`）。
2. **flix.toml の engine の版を 0.57.0 にし、`make sync-agents`**（`bin/fge-go` を受け取る）。
3. `bin/fge refactor field-sites --label <欄> --receiver <alias>` が前と同じ数を返すかを 1 つ確かめる（索引は形 3 で作り直される）。
