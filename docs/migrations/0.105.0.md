# engine 0.104.0 → 0.105.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## ブラウザ版の wasm に作業フォルダのパスが残らなくなる

ゲームのコードで直す所は無い。書き出し直すだけで効く（`docs/web-export.md` の「作業フォルダとホームのパスを wasm に残さない」）。

| 何が | どう |
|---|---|
| 置き換え | ゲームの .flix の位置が、作業フォルダの絶対パス（`/Users/<名前>/.../build/web-export/project/src/A.flix`）から `game/src/A.flix` になる。`--work` を渡しても同じ |
| 止まる | jar と wasm（`classes.wasm`・`classes.names`）にホームや作業フォルダのパスの形が残っていれば、書き出し先に何も置かずに exit 1。出るのは件数と場所だけで、字は `--show-leaks` の時だけ手元に出る |
| 前に出した物 | 0.104.0 までの書き出しの `classes.wasm` には `/Users/<名前>/...` が残っている。公開済みの物は書き出し直して置き直すと消える（gh-pages の過去のコミットには残る） |
| `--work /tmp/...` | パスを避けるために作業フォルダを /tmp へ移していたなら、もう要らない（そのままでもよい） |

## schema と制作の元ファイルを既定で配らない（`web.keep`）

| 何が | どう |
|---|---|
| 外す物 | assets/ の下の `*.schema.json` と `.blend` `.blend1` `.psd` `.kra` `.aseprite` `.ase` `.xcf`。書き出しの表に `外した` の 1 行 |
| 戻す | ゲームが動く時に読むなら project.json の `web.keep: [glob]` |
| `web.omit` | `"assets/*.schema.json"` の行は重なっても誤りにならない。消してよい |
| `.md`・`.txt` | 外さない。起動に入る量を知らせるだけ |
| 古い engine | `web.keep` を書いた project.json は 0.104.0 以前の `bin/fge` でも止まらない（知らない鍵として読まれず、schema も配られる）。テンプレートの project.schema.json には `keep` の欄が増えた |

## ブラウザ版で音の長さを読める（`GameEngine.Audio.audioSeconds`）

ブラウザ版の `GameEngine.Audio.audioSeconds` が、`web.deferred` でまだ届いていない音（取れなかった音も）に 0 でなく
書き出しが `bundle.json` の `sounds[].seconds` に書いた元の長さを返す。書き出し直せば変わる。

| 何が | どう |
|---|---|
| WAV を `Fs.FileRead.readBytes` で読んで長さを出すゲーム | ブラウザでは音が Fs の表に無く、必ず失敗している（`<<audio se X wait=true>>` が待たずに進む）。実機は `GameEngine.Audio.audioSeconds(name)` に替える（[audio.md](../audio.md) の「音の長さをゲームのコードで使う」） |
| sound-novel-starter から作ったゲーム | `src/SoundLength.flix`・`src/Controls.flix`（`loadRuntimeRes`）・`src/Main.flix`・`web/WebMain.flix` をテンプレートに合わせる。実機の起動は `Controls.loadRuntimeRes()`、ウィンドウなし（描き出し・flow・テスト）は今までどおり `Controls.loadRes()` / `loadResIn` |
| 長さの表を別に生成して手当てしたゲーム | そのままでも動く。表をやめて `audioSeconds` に替えるなら、表を作る手順ごと外せる |

## 写真寄りの png を既定で lossy の WebP にする（`web.compress.losslessImages`）

ゲームのコードで直す所は無い。書き出し直すと反映される（`docs/web-export.md` の「写真寄りの絵は既定で lossy」）。

| 何が | どう |
|---|---|
| 変わる絵 | `lossyImages` に書いていない png のうち、lossless の WebP で 48 KB 以上・不透明な画素で 1,024 色を超える物が、engine を上げた後の最初の書き出しから画質 90 の lossy になる。ドット絵・字・単色の UI は色数で外れ、法線・マスク・LUT など名前がデータの形の物と ShaderDoc が読むテクスチャも外れる |
| 知らせ | 前の書き出しと同じ `--out` に書き出すと `★ 前の書き出しでは lossless だった絵 N 枚を既定で lossy にした` が 1 回出る。表には毎回、枚数と色数の少なかった数枚の名前 |
| 見る | `bin/fge web-image-diff <ゲーム>` で元と後を並べた PNG を見る（画素の差の門はブラウザの絵を見ない） |
| 崩したくない物 | project.json の `web.compress.losslessImages: [{ "glob": "...", "why": "..." }]`。`why` は必須・当たる png の無い glob は誤り |
| 今の `lossyImages` | そのまま有効（既定の判定より先）。消しても配る絵の変わらない glob は知らせが出る（消さなくてもよい） |
| 古い engine | `web.compress` の読み手は知らない鍵で止まる（`exportweb_compress.go` の `DisallowUnknownFields`）。`losslessImages` を書いた project.json を 0.104.0 以前の `bin/fge export-web` で書き出すと止まる。engine を上げてから書く。テンプレートの project.schema.json には `losslessImages` の欄が増えた |

## ブラウザ版の書き出しが後回しの候補を出す（`--apply-deferred`）

ゲームのコードで直す所は無い。0.105.0 の engine で書き出し直すと、終わりの表の後ろに「後回しの候補」が出る（`docs/web-export.md` の「後回しの候補を出す」）。

| 何が | どう |
|---|---|
| 候補 | 最後のブラウザの確かめで、タイトルの 120 コマに使わなかった起動の素材。大きい順に、貼れる `"deferred"`・`"deferredFonts"` と、貼った時の 4G の秒 |
| 書き込む | `bin/fge export-web <ゲーム> --apply-deferred` で project.json の列の後ろへ足す。既定は出すだけ |
| 外す物 | 押した時だけ鳴る音とタイトル直後の場面の物も候補に出る。外すか、ゲームが `downloads#missing()` で待つ |
| 知らせ | 後回しの絵と音を、タイトルの間に届く前に描こうとした・鳴らそうとした時は 1 行で知らせる（止めない） |
| 書き出しの時間 | 確かめの既定の頁を 120 コマまで回すので、⑨ が数秒延びる |
| 古い engine | 0.104.0 以前の engine の頁は記録を持たないので候補は出ない（`--apply-deferred` は止まる） |

## ブラウザ版で、届いていない後回しの素材を engine が待つ（`web.deferredPolicy`・`web.splash`）

後回し（`web.deferred`・`web.deferredFonts`）にした物を届く前に使った時、今までは絵が描かれず（背景なら黒いコマ）、ゲームが手で暗転して待っていた。
0.105.0 から、App のループが届いていない絵を描くコマを出さずに待つ。押してから 1.5 秒の間に当たった時は押す前の場面へ戻して待ち、届いたら押した入力を渡し直す（押し直さずに始まる）。
デスクトップ・テスト・flow・描き出しは何も変わらない（届いていない名前がいつも空）。中身は [startup.md](../startup.md) の「届く前に使ったコマを engine が出さない」と「押した後のロゴ」。

| 何が | どう |
|---|---|
| ゲームのコードの直し | `App.launch`・`App.launchWithDevTools`・`App.launchForBench`・`App.loadAndLaunch` の効果に `LoadProgress` が足された。Main を `WebLayer.withProject`・`LwjglLayer.withProject` の中で呼んでいれば直さずに通る。外で呼んでいれば `LoadProgress.runNoop` で包む |
| 自前の `LoadProgress.AssetDownloads` | テストで組んでいる record は欄が増えた（`missingGen`・`policyOf`・`getCodeLoadState`・`isSplashShowing`・`setLoadWait`）。`{ missing = ... \| LoadProgress.localDownloads() }` の形へ |
| 既定の扱い | 絵は待つ・後回しのフォントは届くまで先頭のフォントで出す（今まで通り）・一発の効果音は鳴らさず進む（今まで通り）・ループの音は待たず、届いたら鳴る（今まで通り）・20 秒届かなければ諦めて描かずに進む。前より待ちが増えるのは「届く前の絵を描くコマ」だけで、そこは前は黒いコマが出ていた |
| 扱いを替える | `"web": { "deferredPolicy": [{ "match": "<後回しの道の glob か font:名前>", "onMissing": "wait\|placeholder\|skip", "group": "<組>" }] }`（先の行が勝つ）。待たずに描かずに進むのは `placeholder`、`wait=true` で鳴らす効果音を待つのは `wait`、押した時に同じ組の残りも一緒に待つのは `group` |
| 押した時の待ちの見え方 | 押す前の場面のまま、押した点から波紋・0.5 秒を超えたら右下に輪。替えるのは `App.withLoadingIndicator`（`Custom`・`Hidden`）。選んだ行を光らせるなら `App.withLoadWait` で `LoadWait#pressed` を World へ写す（sound-novel-starter の `World.withLoadWait`・`View.title` が見本） |
| 待ちの間の World | 既定は戻した World を入力なしで進め続ける（タイトルの演出と BGM が動く）。止めるなら `App.withLoadWaitStyle(w -> App.LoadWaitStyle.Freeze)` |
| 待ちをやめるキー | 既定は Backspace とパッドの B。ゲームの戻るのキーに替えるなら `App.withLoadWaitCancelKeys(キーの列)` |
| 暗転を挟む切り替え | 暗転の途中で当たると「暗転を見せる → 押す前の場面へ戻る → 待つ」に見える。避けたい場面は `App.withLoadGate(w -> 次の場面で使う名前)` で、押したコマのうちに待ちへ入れる |
| 押した後のロゴ | 待つ物（`web.splash.waitFor` の group・既定は `deferredPolicy` に最初に出てくる group）が残る時だけ、押した直後に engine のロゴを最短 1.2 秒・上限 3 秒出す。group の無いゲームは出ない。消すのは `"splash": { "afterTap": "none" }`・絵と音を替えるのは `"custom"` |
| 撮る頁 | `?capture=<n>` で画素を比べる頁は `&deferred=all` を付ける（後回しが全部届いてから main を呼ぶ） |
| 確かめ | 書き出しの表の「押してから動くまで（開いてすぐ押した時・4G）」の見積もりと、⑨ の続きの `?net=4g` のタイトルの知らせ。手で開く時も `?net=4g` で 4G の届き方になる |
| Studio | テンプレートの project.schema.json の web に `deferred`・`deferredFonts`・`deferredPolicy`・`splash` の欄が増えた（hd2d・game・rpg・tidepool は `deferred` と `deferredFonts` も増えた） |

### 手書きの待ちの置き替え方

ノベルの系統（sound-novel-starter から作ったゲーム）は、テンプレートと同じ差分を当てる。暗転してから待つ演出を残したいなら外さずに残してよい（engine の待ちとゲームの待ちは並んで動く。ゲームが自分で待っている間は届いていない物を描かないので、engine の待ちに当たらない）。

1. 外す: `WorldRead.holdIfMissing`・`startHold`・`stepHold`・`resumeHold`・`pendingNames`・`World.Hold`・`HoldPhase`・`isHolding`・`holdPhaseOf`・`View.holdLayer`・`holdAlphaOf`・`zHold`・`zHoldMark`・`Read#gaveUp`・`Controls.noteGaveUp`、Doc の `holdFadeSeconds`・`holdGiveUpSeconds`・`holdMarkSeconds`、撮り物の `hold`（`bin/fge refactor usages <名前> --callers` で使う所を全部洗う）
2. **本画面は届いていない絵も描く物の列に入れる**（`ViewStage.specOf`・`Cast` が届いていない名前を外していると、engine は名前を見つけられず待たない）。サムネのように待たせたくない所だけ外す（テンプレートは `View.Env#skipTextures`）
3. 見え方が変わる: 暗転して待つ → 押す前の場面のまま待って、波紋と 0.5 秒で輪。オート・`<<wait>>`・スキップのように押さずに進む所で当たると、前の場面のまま文字送りの途中で止まって待つ（今までは束の頭で暗転して待った）
4. 押した時の待ちで入力を渡し直すので、「待っている間はタイトルのカーソルを動かさない」のような手当ては要らない（engine が待つ間の入力を捨てる）

ゲームが独自に待つ判定を残すなら `BackgroundLoad.readinessOfNames(names, missing, gaveUp, waited, limit)`（IO の無い関数・答えは `Ready`・`Waiting`・`GaveUp`）。
