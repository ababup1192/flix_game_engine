# engine 0.118.x → 0.119.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## デカールの板も SSAO を受ける

`Decal3d.buildInstances` で作った半透明の板（血・汚れ・弾痕）も、SSAO（`PostStack.withAmbientOcclusion`）の暗さを受けるようになった。
デカールを使わないゲーム、SSAO を掛けないゲームは何もしない（絵も wasm も変わらない）。

- SSAO を掛ける場面にデカールを貼ったゲームのブラウザ版は、材質の版の鍵 `+ab` が増える。
  PC で `make run` してその場面を一度通し、`web/shader-variants.json` に記録してから書き出す。
- `Decal3d.Internal`・`Scene3d.Internal` はゲームから呼ばない（lint-forbid の `app-internal` が止める）。

## 型に増えた欄

- `Scene3d.MaterialFields` に欄 `screenAoOnBlend`（既定 false・デカールの板だけが立てる）。材質は `Scene3d.material(..)` などの関数で作るので、
  ゲームは何もしない。

## glb の KHR_texture_transform を頂点の uv に書き込む（旗なし・いつも）

材質の絵が全部同じ `KHR_texture_transform` で、実際に読む uv が TEXCOORD_0 なら、読み込みの時に uv へ焼き込むようになった（今までは読み飛ばして 1 行知らせていた）。
project.json の旗は無く、既定で効く。

- transform を書いた glb を置いていたゲームは、絵のずれ・回り・繰り返しの数が Blender の見た目どおりに変わる。今までの「ずれた絵」に合わせて
  uv や絵を手で直していたなら、その直しを外す
- 回転や負の倍率のある transform を書き込んだ形は、ファイルの `TANGENT` を使わずに uv からタンジェントを求め直す（法線マップの傾く向きが合う）
- 絵ごとに違う transform・TEXCOORD_1 を読む transform は今までどおり読み飛ばして知らせる
- 書き出したゲームの絵（gallery・reference）は、transform を書いた glb を使う場面だけ変わる。変わったら `make reference-update` で基準を取り直す

## glb の材質の AO の絵（occlusionTexture）を読める

project.json の `"gltf"` に `"occlusion": true` を書くと（`"pbr": true` と一緒に）、metallic・roughness の付く材質が occlusionTexture を読み、
環境の光と映り込みに掛ける。書かなければ何も変わらない（絵もシェーダーも wasm の記録も同じ）。

- 入れたゲームのブラウザ版は、材質の版の鍵 `+occ` が増える。PC で `make run` してその場面を一度通し、`web/shader-variants.json` に記録してから書き出す
- AO 入りでベイクした lightmap と重ねると 2 回効く。その時は入れない

## 型に増えた欄

- `Gltf.LoadOptions` に欄 `occlusion`（既定 false）。`{ … | Gltf.defaultLoadOptions() }` の形で作っていれば何もしない。欄を全部書いたレコードを作っているなら `occlusion = false` を足す
- `Model3d.GltfMaterial` に欄 `occlusionTexture`・`occlusionStrength`、`Scene3d.MaterialFields` に欄 `occlusion`（どちらも読むだけの欄。ゲームは作らない）
- `ShaderGen.compile3d` と `ShaderGen.Wgsl.compile3d` に引数 `materialOcclusion: Bool`（engine の中と bench だけが呼ぶ。ゲームは呼ばない）
