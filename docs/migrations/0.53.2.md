# engine 0.53.1 → 0.53.2 の手当て

自動生成の一覧は [0.53.2.auto.md](0.53.2.auto.md)（直す物 0 件）。ゲームで直す物は無い。
追随は flix.toml の版を 0.53.2 にして依存を取り直すだけ（`bin/fge video-entries --check` が 0.53.1 で NG だったゲームは、それで OK に戻る）。

入ったのは不具合の直し 3 つ（internet_dungeon の F8 チケット f28700 と、ゲームの担当の報告から）。

1. **F8 と /halt で止めた画面に入るとき、十字のカーソルを見せる**:
   止める入口は十字へ替えるだけで、見せる指示を出していなかった。`App.withCursor` で矢印を隠しているゲーム
   （`visible = false`）では、止めた画面でカーソルが消えて囲う所が分からなかった。F8 と /halt の入口を
   `App.RemoteDebug.enterHaltMarkers` の 1 本にそろえ、そこで見せる。抜けるときは形だけ戻し、見せるか隠すかは
   動き出した拍に App が withCursor の宣言を当て直す（ゲームの設定に戻る）。
2. **F8 の止めた画面と注釈のスクショで、テクスチャ 1 枚を読むだけのシェーダー面は元の絵を貼る**:
   止めた画面とスクショはシェーダーを走らせず、面を代表色 1 色で塗る。`Shade.Rgb` の代表色は中間の灰なので、
   テクスチャを読んで灰色にする面（ポストのサムネ）が灰色の箱に見えた。面の式がテクスチャ 1 枚だけを読み、
   読む位置が `shift` だけで決まるなら、読む範囲をそのまま貼る（灰色化・明るさなどの色の計算は落ちる）。
   ほかの面は今までどおり代表色。どの面がどちらになるか・全部を本物で描かない理由は
   [shader-doc.md](../shader-doc.md) の「F8 の止めた画面と注釈のスクショでの見え方」。
3. **render-lint の video-entries が、`$(call video-mix-env,…)` を動画の口と取り違えない**:
   名前が `video` で始まる別のマクロ（`define video` / `define flow-video` の中で呼ぶ物）の行まで拾い、
   「入口を読めない行」として `--check` が止めていた（0.53.1 のゲームの master でも NG）。マクロ名の直後が
   区切り（空白・カンマ・閉じかっこ）の行だけを拾う。ゲームの Makefile の書き方は make として正しく、直す物は無い。
