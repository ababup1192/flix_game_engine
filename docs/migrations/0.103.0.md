# engine 0.102.1 → 0.103.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## ブラウザ版の読み込みが軽くなる

ゲームのコードで直す所は無い。書き出し直すだけで効く。

| 何が | どう |
|---|---|
| wasm | 書き出しが関数名の区画を外し（`classes.names` に分けて、止まった時だけ頁が取る）、brotli にした `classes.wasm.br` を一緒に置く。頁は小さな解き手（`brotli-decode.js`）で解き、読めない時は gzip の wasm へ戻る |
| 字のアトラス | 距離場を 1/2 に縮めて置く（字の形は変わらない） |
| 押せる時 | 「タッチして開始」は wasm まで届いてから出る。進みの棒にも wasm が入る |
| 後回し | 速い回線で押す前に届いた後回しの素材は、押した後にまとめて解かず、ゲームが始まってから少しずつ解く |
| 後回しのフォント | `project.json` の `web.deferredFonts`（フォントの名前の列）に書いたフォントは、タイトルの後に取る。届くまでは先頭のフォントで描き、`downloads#missing()` にその名前が並ぶので、読み始めの所でそこを待てる |

## make tape は engine の mk/tape.mk から

テンプレートから作ったゲームの Makefile は、tape のレシピの写しを持っている。写しのままでも動くが、次の 3 つは効かない。

| 何が | どう |
|---|---|
| 撮り直さない | 撮り終えた flow は `debug/tape/<名前>/.shot` に指紋を残し、同じなら撮らない（`TAPE_FRESH=1` で撮り直す） |
| 書き出しの失敗 | 裏の書き出しが止まったら、録画の待ちの間にすぐ知らせる |
| 公開だけ | `make tape-publish FLOWS=…` |

直し方: Makefile の `flow-mp4`・`TAPE_*`・`tape-*`・`tape:` を消し、`include …/mk/game.mk` の次の行に `include …/mk/tape.mk` を書く。ゲームだけの後処理は `TAPE_AFTER_EXPORT` に書く（例: `templates/sound-novel-starter/Makefile`）。

## flow

| 何が | どう |
|---|---|
| 返事の確かめ | 「押したが受け付けられなかった」は、離したフレームの後に確かめる。離した時に決まる押し方（タップと払いを離した時に分ける画面）でも `ready off` が要らなくなる。通っている flow のフレーム数は変わらない |
| `Flow.Outcome` | `notes`（知らせの列）が増えた。読むだけのコードは直さなくてよい。レコードを自分で組んでいる所があれば `notes = Nil` を足す |
| `bin/fge flow check` | `run` で入れる部品の `fps`・`ready` が親と違うと止める（部品を単独で流すと別の設定で走るため）。部品のファイルにも同じ行を書く |

## 上げる時に止まりにくくなった

ゲームのコードで直す所は無い。engine が作業コピーなら、`make engine-upgrade` と `bin/fge export-web` は、engine の束（engine_full・engine_full_web）が古いと自分で作り直して続ける。engine の src に未コミットの差がある時と、main に入っていない枝の時は止まる（その枝を使うなら `FGE_ANY_BRANCH=1`）。
