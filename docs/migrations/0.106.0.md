# engine 0.105.0 → 0.106.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## ブラウザ版の起動の予算が止まる門になる（`web.startupBudget`・`bin/fge web-check`）

書き出しの最後に「遊べるまで（すぐ押した時・4G）」を予算と比べ、超えたら止まる（`docs/web-export.md` の「起動の予算」）。
数字は起動の秒に、押した後の待ちのうちロゴで覆えない分を足した物。押した後は、書き出しの確かめ ⑨'' が `?net=4g` の頁で「タッチして開始」とタイトルの決定を押して測った値と、
押した後のロゴが待つ group の見積もり（group が無ければ 0 秒）の大きい方。測れなかった時（Chrome が無い・`--no-browser-check`・上限まで待ってもコマが進まない）は見積もりだけで決めて ★ で知らせる。
group の無いゲームはロゴが出ないので、測った待ちがそのまま足される（すぐ要る物を後回しへ回しても門は通らない）。

| 何が | どう |
|---|---|
| 予算を書いていないゲーム | 移行の間は、手元の `bin/fge export-web` は止めずに ★ で知らせる。手元も止まるのは、今止まる 3 本（血鱗・インターネットダンジョン・片手間迷宮）が予算内か why 付きで通った次の版から。**公開の側（`bin/fge web-check`・`make web-pages-stage`・テープの play/）は今から既定 16 秒で止める** |
| 予算を書いたゲーム・web/ を持つテンプレート（rpg-starter・sound-novel-starter・hd2d-starter）から作ったゲーム | 超えたら止まり、書き出し先が消える。作業中に開くだけなら `--draft`（web-check が拒む draft のマーカーが付く） |
| 16 秒を超えるゲーム | 先に「次に打つ手」（押した後の待ち・後回しの候補・brotli）を試す。それでも要るなら `"startupBudget": { "seconds": <秒>, "why": "<理由>" }`。why は bundle.json に写るので公開される |
| タイトルの既定の行が「はじめから」でないゲーム | `startupBudget.startKeys` にタイトルで押すキーを書く（書かないと押した後を測れず「待ちの記録が無い」と出る） |
| 後回しの絵を `placeholder` にしている `deferredPolicy` の行 | `"why"` が要る（予算を書いたゲームでは無いと止まる・書いていないゲームは ★） |
| 4G のタイトルで後回しの物を待って止まる | 門が赤になる。タイトルで使う物は `web.deferred` から外す |
| 手で gh-pages の根・site/・別のリポの play/ に写す | 写す前に `bin/fge web-check <書き出したフォルダ>` |
| テープ | `make tape` の書き出しは `--draft`。門が赤なら `bin/fge tape --play` が play/ に置かず、前に置いた play/ も消す（頁は「はじめから遊ぶ」を出さない） |
| 書き出した後に元の wav を消す手順 | そのままでよい（web-check は頁が取らない控えが無いのを止めない）。ほかのファイルを書き出しの後に替えると `sums.json` と合わず止まる |
| 古い engine | `deferredPolicy` の行の `why` は、0.105.0 以前の `bin/fge` が知らない鍵で止まる。engine を上げてから書く。`startupBudget` は古い engine では読まれない（止まらない・効かない） |
| 0.105.0 の束でも、遊べるまでが 16 秒を超えるゲーム（血鱗など）のテープの play/ | 予算を書いていなければ、次の `bin/fge tape` で web-check が赤になり消える。why 付きの予算を書いて書き出し直せば戻る |
| bundle.json の無い play/（手で置いた物） | 消さない。頁に「はじめから遊ぶ」も付けない |
| 前に書き出した束（sums.json の無い古い物）が残るテープの play/ | 次の `bin/fge tape` で web-check が赤になり消える（書き出し直せば戻る） |
| テンプレートの project.schema.json | `startupBudget`（seconds・why・startKeys）と `deferredPolicy` の行の `why` が増えた |

## 2D のゲームのブラウザ版から 3D の描き手と後がけを外す

ゲームのコードで直す所は無い。書き出し直すだけで、3D も後がけ（`App.withPostStack`）も使わないゲームの wasm が小さくなる。

| 何が | どう |
|---|---|
| `WebLayer.withProject`（2D の入口） | WebGPU の頁でも 3D の描き手を持たない（WebGL2 の頁と同じ）。Scene3d の場面は描かず、初回に 1 回 `web/WebMain.flix を WebLayer.withProject3d へ替える` と知らせる。0.105.0 までは WebGPU の頁だけ描けていた |
| Scene3d を描くのに `withProject` のままのゲーム | `web/WebMain.flix` の `WebLayer.withProject(".")` を `WebLayer.withProject3d(".")` へ替える（テンプレートの hd2d-starter・bench の hd2d_town と scene3d は前から withProject3d） |
| `App.withPostStack` | 振る舞いは同じ。呼ばないゲームには後がけの組み立てが入らない |
| `RenderPaint.Internal.WebGpuPaint.create` を直に呼ぶ物（bench など） | 設定に `scene3d` が増えた。3D を描くなら `Render3d.WebGpuRenderer.makeScenes`、描かないなら `(_, _, _) -> checked_ecast(Render3d.WebGpuRenderer.none())` |

## 後回しのフォントを取る位置を選べる（`web.deferred` の `"font:<名前>"`）

後回しのフォント（`web.deferredFonts`）のアトラスは列の頭で取っていた。後回しのフォントは既定で待たない（届くまで先頭のフォントで出す）ので、
最初の場面で使わないフォントが頭にあると、押した後のロゴが待つ素材より先に回線を使ってしまう。

| 何が | どう |
|---|---|
| `web.deferred` に何も足さないゲーム | 今まで通り頭で取る。ただし `deferredPolicy` で group を付けたフォントは、その group の最初の素材の前で取る（見積もりでは group の最後が届く秒は変わらず、間の素材が早く届く） |
| 押した後の待ちがフォントで延びているゲーム | `web.deferred` の列に `"font:<名前>"` を書くと、その位置で取る（例 BGM の glob の後ろ）。名前は `deferredFonts` にも書く（無いと止まる）。同じ名前の行を 2 本書くと止まる |
| 古い engine | `"font:<名前>"` の行は 0.105.0 以前の `bin/fge` では glob として読まれ、当たる素材が無いと止まる。engine を上げてから書く |
| テンプレートの project.schema.json | `deferred` の説明に `font:<名前>` が増えた |

## 頁が読む URL の鍵を始まりの引数に混ぜない

`backend`・`net`・`deferred`・`sw`・`usedAssets`・`webgpuFail` を、ブラウザ版の始まり（`App.DevTools.browser`）が外すようになった。0.105.0 までは `?backend=webgl2&talk=X` で `backend` が始まりの名前に読まれ、`?talk=X&net=4g` では `net` が始まりの引数に混ざっていた。ゲームのコードで直す所は無い（この 6 つの名前を始まりの名前や引数に使っていたゲームは、別の名前へ替える）。
