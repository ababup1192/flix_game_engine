# engine 0.103.0 → 0.104.0 の手当て

（手書きの節。版を上げる時に変わった所を足す。）

## ブラウザ版の 2 回目からの起動が速くなる

ゲームのコードで直す所は無い。書き出し直すだけで効く（`docs/web-export.md` の「起動の始まりと 2 回目からの起動」）。

| 何が | どう |
|---|---|
| preload | `index.html` の head が、起動の最初に要る物（`bundle.json`・wasm・解き手・2 本の js）を版を確かめた所で先に取らせる |
| Service Worker | 書き出しの根に `sw.js` と `sums.json`（1 本ずつの中身の sha256。版はこの表の sha256 の頭 12 字）が増え、頁は「タッチして開始」を出した後に登録する。2 回目からは置き場の `max-age` が切れていても、ネットへ行くのは `version.txt` と `sw.js` の更新の確かめだけ |
| 止める | project.json の `web.serviceWorker: false` で書き出し直して置く。自分を外す `sw.js` が出て、登録済みの人も次に開いた時に外れる。利用者の側で登録とキャッシュを外して作り直させるのは頁の URL に `?sw=0` |
| 置き場 | 書き出しのフォルダを丸ごと置く形はそのまま。`sw.js` と `sums.json` を外して置かない（`sw.js` を消しても登録済みの人からは外れない。外すのは上の `web.serviceWorker: false`。`sums.json` が無いと Service Worker は何もキャッシュへ入れない） |

## 書き出しが brotli を PATH の外からも探す

ゲームのコードで直す所は無い。`bin/fge export-web` は brotli を PATH・engine の devbox・Homebrew・nix の profile と store から探す。どこにも無い時は、wasm を gzip で配ることと 4G で何秒遅くなるかを、書き出しの途中と最後のまとめに ★ で出す。
