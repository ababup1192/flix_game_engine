# engine 0.75.0 → 0.76.0 の手当て（下書き）

一人称で歩いて調べるゲームのための小さな口を足した（`plans/engine-round10-3d-kit.md` の段 1）。
マウスを窓にキャプチャして動いた量を受け取る・GPU の時間を測って画面に出す・スポットライトの内側の角・場面の絵の枚数の上限。
使わないゲームの絵は 1 bit も変わらない（gl-parity の既存の全部の行で GL と CPU の絵がバイト一致・テンプレートの絵が前の版とバイト一致・描き出しの鍵の固定値がそのまま）。

## ゲームで直す物

- **`Scene3d.SpotLight` を字で全部の欄を書いているゲーム**は `innerFovY = None` を足すか、`Scene3d.spotLight(position, target, fovY)` を `{ color = .., intensity = .., range = .. | Scene3d.spotLight(p, t, fov) }` の形に替える（替えると、この先欄が増えても止まらない）。`None` は今と同じ縁
- **`SoftRaster3d.spotInnerRatio()` を呼んでいる所**は `Scene3d.spotInnerRatio()` に（GL と CPU の 2 か所にあった同じ値を 1 つにした。縁の cos は `Scene3d.spotConeOf`）
- **`GameEngine.EngineConfig` を自分で組んでいるゲーム**（project.json を `ProjectLoader` で読まない物）は `scene3dTextureBudgetCount` の欄を足す（既定は `GameEngine.defaultScene3dTextureBudgetCount()` = 64）
- **自前の描き手で `RenderPaint.create` / `Render3d.fresh` を呼んでいるゲーム**だけ: `create` の cfg の `scene3dTextureBudgetMB` を `scene3dTextureBudget = Render3d.textureBudgetOf(config)`（`{ megabytes, count }`）に、`Render3d.fresh` も同じ `Render3d.TextureBudget` を渡す（キーが増えても通り道の欄は 1 つのまま）
- **`GameEngine.Game` の handler を自分で書いているテスト**は 3 つの op を足す: `def consumeMouseDelta(k) = k(Vec2.zero())`・`def setMouseCaptured(_captured, k) = k(())`・`def isWindowFocused(k) = k(true)`
- **`FrameDiagnostics.Diagnostics` を字で組んでいる所**は `gpuNs`・`gpuPasses`・`scene3dCounts` を足すか、`{ submitNs = .. | FrameDiagnostics.empty() }` の形に
- **`App.Frame` / `App.PendingEdges` を字で組んでいる所**は `mouseDelta`（と Frame は `windowFocused`・`diagnostics`）を足す（`App.frameOf` で組んでいれば止まらない）
- **`App.CursorLook.HaltLook` を開いて match している所**は 3 つ目の `Capture` を足す

## 振る舞いが変わる物（絵は同じ）

- `App.withFixedStep` のサブステップ: `frame#mouseDelta` はホイールと同じ量の扱い（2 回目以降のサブステップは 0・0 回のフレームの分は次へ足す）
- `App.frameOf`・flow の `at=`・`PropertyTest` は、前のフレームとの cursor の差を `mouseDelta` に入れる（画面なしでも視点が回る）。実機はキャプチャしても出るバックエンドの量
- `fovY` が 0 のスポット（円錐が無い）は、内と外の cos が同じになる所で内側に 1e-6 を足すので、真ん中の 1 点の照らし方が変わりうる（前は smoothstep の両端が同じで値が決まらなかった。`fovY` が 0 より大きいスポットは変わらない）
- flow の記録は、マウスの動いた量が位置の差から出ない時（キャプチャ中）だけ `look=dx,dy` を書く。flow の手順にも `look=` を書ける（`bin/fge flow check` も読む）
- ヒッチの記録（DEBUG の起動）の診断は、App が 1 コマに 1 回だけ引き取ってゲームの `frame#diagnostics` と分ける（今までどおりの数が出る）

## 足した物（使わなければ何も変わらない）

- マウスのキャプチャ: `App.withMouseCapture(w -> Bool)`・`frame#mouseDelta`・`frame#windowFocused`・`GameEngine.Game.setMouseCaptured` / `consumeMouseDelta` / `isWindowFocused`（engine の `docs/modules/input.md` の「一人称の視点」）
- GPU の時間: `App.withDiagnostics()`・`frame#diagnostics`・`FrameDiagnostics.gpuNs` / `gpuPasses` / `scene3dCounts` / `Scene3dCounts` / `summaryLines`（`docs/performance.md` の §11）
- スポットの内側の角: `Scene3d.SpotLight.innerFovY`・`Scene3d.spotLight(p, t, fovY)`・`Scene3d.spotConeOf`・`Scene3d.spotInnerRatio`（`docs/scene3d.md`）
- 場面の絵の枚数の上限: project.json の任意キー `scene3dTextureBudgetCount`（既定 64）・`GameEngine.defaultScene3dTextureBudgetCount()`
- 3D の口の案内: `docs/scene3d.md`

## 段 2: glTF のノード・glb の emissive・視錐台の外の間引き（`plans/engine-round10-3d-kit.md` の段 2）

段 1 と同じ版で出すか、次の版に分けるかは後で決める（分けるなら、この節を次の版の移行メモへ移す）。
emissive の付いた glb を `loadTextured` で読むゲームのほかは、絵は 1 bit も変わらない（gl-parity の既存の全部の行で GL と CPU の絵が
段 2 の前とバイト一致・テンプレートの絵が前の版とバイト一致・emissive の無い glb の場面の描き出しの鍵が段 2 の前の字のまま）。

### 絵が変わる物

- **emissive（`emissiveFactor` が 0 でない材質）の付いた glb を `Gltf.loadTextured` で読むゲームは、その物が光り始める**（glTF の決まりどおり）。
  baseColorTexture の無い emissive だけの材質（炎など）も頂点の色の材質 + emission になって光る
  - 止めたい時は `part#material |> Option.map(Scene3d.withoutEmission)`
  - 値は `emissiveFactor × KHR_materials_emissive_strength` で線形の量。Blender の書き出しの強さ 40 は、今の式（色の値をそのまま足す）では
    白く飛ぶ。色の線形化（段 5）で正しい明るさになる。それまで明るすぎる物は止めるか、自前の emission に差し替える
  - workspace で当たる glb: horror_apartment の `back_lot`・`bld_back`・`bld_props`・`neighbors`・`room_203`・`room_205`・`site_props`・
    `stairs`・`street`（どれも emissiveTexture × 強さ 40）・fps3d_lab の `flame.glb`（絵なし・(1, 0.62, 0.18)）。
    night_apartment は emission を自前で付け直しているので、その材質は今の絵のまま（付け直していない材質は光る）
  - emission の付く材質の spec の名前は `gltf:tex:<絵の読み方>:<emissive>` / `gltf:vc:<emissive>` に替わる（emission の無い材質は今の名前のまま）

### ゲームで直す物

- **`Model3d.Model3d` を字で全部の欄を書いた所**は `nodes = Nil` を、**`Model3d.ModelPart` を字で全部の欄を書いた所**は `node = None, gltfMaterial = None` を足す
  （engine・テンプレート・workspace のゲームには無い）
- **mesh を持つノードの無い glb が `Err` になるのを当てにしていた所**: 今は Ok（形は頂点 0・parts は空・印の点は `nodes`）
- **emission を差し替えた glb の材質の spec の名前を、材質を組み直して替えていた所**（night_apartment の `Stage.renamed`）は
  `Scene3d.withSpecName("night:emissive:<部品>", m)` の 1 行にできる。名前を替えないと、engine の付けた名前のまま木だけが変わり、GL が毎コマ組み直す
- **`Render3d.materialKey` を呼んでいる所**（テストだけのはず）: 鍵に emission の有無（`+em`）が入った

### 振る舞いが変わる物（絵は同じ）

- GL と CPU の描き手が、視錐台の外の置いた物とビルボードを描かない。影の地図は光の視錐台で間引く。`FrameDiagnostics.scene3dCounts#drawn` は描いた数になる（前は置いた数と同じ）
- 間引いた物の形・絵は今のコマで使った物として GPU に残る（振り向いても上げ直さない）
- `Gltf.loadTextured` が emissive の絵（emissive の付く材質の emissiveTexture だけ）も decode する。上限は `TextureLimits#baseColor`。
  texCoord が 0 でない emissiveTexture（光らせない絵）は decode しない（baseColor・normal の扱いは前のまま）
- 間引きが効いているかは、実機で振り向いても「新しい形（Mesh3d）が … コマ続けて GPU へ上がっている」の知らせが鳴らないこと・F3 の `drawn` が減ることで見る
- `emissiveFactor` が 3 つの数でない材質は (0, 0, 0) として読んで 1 行知らせる
- 画面の絵を落とす `FLIX_GE_FRAME_SHOT` の枚数の上限が 32 → 64（gl-parity の行が 32 を超えた）

### 足した物（使わなければ何も変わらない）

- glTF のノード: `Model3d.Model3d#nodes`・`Model3d.ModelNode`・`Model3d.Bounds`・`ModelPart#node`・`Model3d.findNode` / `nodesByName` / `nodesWithPrefix` /
  `partsOfNode` / `partsByNode` / `nodeOrigin` / `partLocalToNode`
- glTF の材質の情報: `ModelPart#gltfMaterial`・`Model3d.GltfMaterial`・`Model3d.AlphaMode`
- 材質: `Scene3d.withoutEmission`・`Scene3d.withSpecName`
- 視錐台: `Camera3d.frustum`・`Frustum.Frustum` / `ofClipMatrix` / `intersectsBox` / `intersectsSphere` / `containsPoint`・
  `Scene3d.aspectOf` / `frustumOf` / `shadowFrustumOf` / `isOutsideFrustum` / `isOutsideFrustumFields` / `isBillboardOutsideFrustum` / `worldBoundsOf`
- 箱: `Mesh3d.Bounds`（`Mesh3d.bounds` の戻りの型に名前を付けた。字の形は同じなので呼ぶ所は止まらない）・`Mesh3d.cornersOf`
- 口の案内: `docs/scene3d.md` の「glb のノードを名前で引く」「glb の emissive」「描く量」

### 自前で歩きと当たり判定を書いているゲーム（night_apartment など）が置き換える時

- 箱: 焼き込んだ頂点と法線から箱の向きを推し量る処理は `Model3d.nodesWithPrefix("COL_", collision) |> CollisionShape3d.boxesOfNodes` に
  （向きと大きさはノードの行列と局所の境界からそのまま）。斜めの手すりを縦の箱の列に分けるような、書き出しの形の事情の処理はゲームに残す
- 歩き: 押し出し・床探し・落ちる・区切りは `CharacterBody3d.moveAndSlide` に。向き・足音・頭の上下は体の外（ゲーム）に残す。
  傾いた箱を全部床として扱っていたなら `floorMaxAngleDeg = 90.0`（既定は 45°）
- 地面の平面は大きな薄い箱、歩ける範囲は外側の厚い箱（1 m 以上・頭より高く）として `CollisionWorld3d.build` に入れる
  （自前で「範囲に収めてから押し出す」順にしていた所は、範囲の端の数 cm で止まり方が変わりうる）
- 扉の板は `moving` に毎コマ渡す。回す前と後の食い込みは `CollisionShape3d.penetration(板, CharacterBody3d.capsuleOf(s, body))`
- 体の球の並べ方は「間は半径以下」（自前で直径ごとに並べていたなら、球が増えて壁の角の当たりが少し細かくなる）
- 調べる・E で扉: 足元からの距離と向きの内積をやめ、`Camera3d.forwardRay` → `Ray3d.pickNearest`（壁の箱も的に入れて遮る）

## 段 4: 空のグラデーション・半透明と両面・MSAA（`plans/engine-round10-3d-kit.md` の段 4）

段 1〜3 と同じ版で出すか、次の版に分けるかは後で決める（分けるなら、この節を次の版の移行メモへ移す）。
glb の `alphaMode` が BLEND / MASK の材質のほかは、絵は 1 bit も変わらない（gl-parity の既存の全部の行で GL と CPU の絵が段 4 の前と
バイト一致・テンプレートの絵が前と同じ顔ぶれで一致・材質の 3D の GLSL の字が前と同じ（`TestRender3dGlslPinned`）・
空も半透明も両面も使わない場面の描き出しの鍵が前の字のまま）。

### 絵が変わる物

- **`alphaMode: "BLEND"` の材質を持つ glb を `Gltf.loadTextured` で読むと、その材質が半透明になる**（`Scene3d.withAlphaBlend(true)`）。
  **`"MASK"` は α 0.5 で抜く**（`withCutout(true)`。`alphaCutoff` が 0.5 でなければ材質ごとに 1 行知らせ、0.5 で抜く）。材質の無い（頂点の色で描く）物は変わらない
  - 半透明になった物は影を落とさず、Output.Depth（ピントの Pass）に描かれなくなる。不透明の物とビルボードの後に、遠い物から重なる
  - 前の絵に戻すなら `part#material |> Option.map(Scene3d.withAlphaBlend(false))`（MASK は `withCutout(false)`）
  - workspace で当たる glb: night_apartment の `alpha_net.glb`（`GM_net`）・`alpha_chainlink.glb`（`GM_chainlink`）。どちらも BLEND。
    night_apartment は `withCutout(true)` を重ねているので、α 0.5 未満を捨てた上で、残った画素が絵の α で透ける（前は α ≥ 0.5 の画素が不透明）
- `doubleSided` は当てない（Blender の書き出しは全部の材質を真にするので）。両面にしたい物はゲームが `part#gltfMaterial#doubleSided` と
  材質の名前を見て `Scene3d.withDoubleSided(true, ..)` を当てる

### ゲームで直す物

- **`RenderTarget.TargetSpec` を字で全部の欄を書いて `RenderTarget.Target.beginTarget` を呼んでいる所**は `samples = 1` を足す
  （engine・テンプレート・workspace のゲームには無い。gl_parity の harness だけ直した）
- **`RenderTarget.Descriptor` を字で全部の欄を書いた所**は `samples = 1` を足すか、`{ scale = .. | RenderTarget.defaultDescriptor() }` の形に（engine・テンプレート・workspace には無い）
- **`Scene3d.Scene3dCmd` を字で全部の欄を書いた所**は `sky = None` を足す（`{ .. | Scene3d.scene(..) }` の形なら止まらない。engine・workspace には無い）
- **`Scene3d.MaterialFields` を開いて全部の欄を match している所**は `blend`・`doubleSided` を足す（engine の DrawHash だけ）
- **材質を `Scene3d.material({ name = 名前 | f#spec })` で組み直して spec の名前を替えている所**（night_apartment の `Stage.renamed`）は、
  組み直すと半透明・両面の印が落ちる。`Scene3d.withSpecName(名前, m)` の 1 行にする
- **`Render3d.VertexKind` を使っている所**（テストだけのはず）: `Render3d.ProgramKind` に名前を替え、`blend`・`doubleSided`・`coverage` の欄を足した。
  `Render3d.materialFragmentSource` の 2 つ目の引数は `ProgramKind` そのもの（`skinned` は読まない）。鍵（`materialKey`）は 3 つが真の時だけ `+bl`・`+ds`・`+cov` が付く
- **自前の描き手で `Render3d.prepareScenes` を呼んでいる所**: 描き先は `Render3d.Dest`（`{ framebuffer, format, samples }`）に、
  `Render3d.SceneItem` に `multisampled` の欄が増えた

### 振る舞いが変わる物（絵は同じ）

- GL の不透明の材質の物を描く順は前と同じ（プログラムの番号で並べる）。並べるのは呼び手（`drawScene`）になり、半透明の物はその列から外れる
- `RenderTargetGl.Entry` に `samples`・`msaa` の欄が増え、`bind` は標本を持つ描き先を bind する（無ければ前と同じ FBO）

### 足した物（使わなければ何も変わらない）

- 空: `Scene3d.Sky3d`・`Scene3d.SkyFields`・`Scene3dCmd#sky`・`gradientSky` / `withSkyCurve` / `skyFieldsOf` / `skyCurveOf` / `skyColorOf` /
  `SkyBasis` / `skyBasisOf` / `skyDirectionOf` / `skyWarning`
- 半透明と両面: `Scene3d.withAlphaBlend` / `withDoubleSided`・`MaterialFields#blend` / `#doubleSided`・`Scene3d.blendOrderOf` / `drawCenterOf` / `isBlendedFields`
- MSAA: `RenderTarget.Descriptor#samples`・`RenderTarget.withMsaa` / `samplesOf` / `samplesAtMost`・`TargetSpec#samples`
  （GL の側: `RenderTargetGl.createWithSamples` / `isMsaaFallback` / `drawFramebuffer` / `drawSamples` / `resolve`）
- 口の案内: `docs/scene3d.md` の「空（グラデーション）」「半透明と両面」「細い物の欠けを抑える（MSAA）」
