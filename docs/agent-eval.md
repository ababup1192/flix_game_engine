# agent-eval — 文書で道具の選び方が伝わるかを測る

何も教えていない `claude -p` にお題（依頼の言葉だけ）を渡し、答えに出た道具を正規表現で採点する。
お題は `agent-eval/engine.json`（エンジン共通・配られる）とゲーム固有の `agent-eval/<名前>.json`。
形と採点の決まりは `bin/fge agent-eval --help`。

| 口 | いつ | 時間と費用の目安（0.35.21・18 題） |
|---|---|---|
| `make agent-eval ONLY=<お題>` | 早見表の行とお題を足したとき | 1 本 30〜90 秒 |
| `make agent-eval [REPEAT=3]` | 文書を整理した前後 | 1 回分 約 6 分・$6 |
| `make agent-eval-release` | エンジンのリリースの後（ゲームを追随させてから） | 3 回分 約 20 分・$18・入力 1300 万 tok |
| `make agent-eval-compare A= B=` | 2 回の記録を並べる（何回か流した記録は平均で比べる） | すぐ |

heavy の鍵は取らない。claude -p は返事を待つ間ほとんど CPU を使わないので、鍵を取るとほかの作業場の
check・test・リリースを止めるだけになる。同時に走る claude -p の本数は、いくつの作業場から流しても
マシン全体で 3 本まで（`/tmp/fge-agent-eval.slots/<番号>.lock` のファイルロックで数え、持ち主が死ねば OS が外す・`FGE_AGENT_EVAL_SLOTS` で変える。
Windows はファイルロックが無いので数えず、`--jobs` だけで抑える）。
`bin/fge heavy make agent-eval` と包まない。

費用は claude の `total_cost_usd`（API の値段に換算した額）。サブスクリプションで流す分は、この額の代わりに利用枠を使う。

## 版ごとの記録（agent-eval/history/）

`make agent-eval-release` は全部のお題を 3 回流し、`agent-eval/history/<版>.json`（コミットする）に
お題ごとの点・トークン・ターン・秒の 3 回分と、合計の費用を残す。1 つ前の版の記録と並べた表を出し、
次の物を「下がった」と知らせる（`make status` の 1 行にも出る）。

- 平均点が 15 点以上下がった（2 語のお題で 3 回に 1 回外すと 17 点。1 語のぶれだけでは鳴りにくい）
- 入力トークンの平均が 1.5 倍を超えた（1 本ごとの幅は 2〜3 倍あるので、平均で見る）

`make release` のゲートには入れない。claude を 50 本以上呼ぶので遅く、点にもぶれがある。止める物ではなく知らせる物。
下がったお題が出たら、`debug/agent-eval/v<版>/<お題>.<回>.jsonl` の答えを読み、
原因を「早見表の書き方」「お題の文」「採点の誤り」に分ける。採点の誤りなら正規表現か打ち消しの読み方を直し、
claude を呼ばずに付け直す（回数は記録から読む。日付と走った時間は前の記録を引き継ぐ）:

```
bin/fge agent-eval --tasks agent-eval/engine.json --tasks agent-eval/<ゲーム>.json \
  --label v<版> --rescore --history agent-eval/history --version <版>
```

同じ版の記録が既にあると `make agent-eval-release` は止まる（`use-engine` で開発中のエンジンを向けると、
番号がまだ前の版のままのため）。わざと測り直すなら `OVERWRITE=1`。
失敗した回（10 分の打ち切りなど）は平均に入れず、表と status に「失敗 n 回」と出す。

## ぶれの大きさ（0.35.21 で 3 回ずつ流した結果）

- 点: 18 題のうち 16 題は 3 回とも 100 点。外れた 3 回はどれも採点の誤りで、答えは正しかった
  （「使えない」を打ち消しと読まなかった・読んだファイルの一覧に grep した語が並んだ）。直した後は 18 題とも 3 回 100 点。
- 入力トークン: 同じお題でも 1 本ごとに 2〜3 倍の幅がある（例: hud-timer 135k〜396k）。1 回の値で前後を比べない。
- ターン: 幅は ±3 ほど。

0.35.22 で `make agent-eval-release` を初めて通したときは、「下がった」が 3 題出た。外れた 8 回を読むと、
8 回とも答えは正しく、採点の誤りだった（「〜していないか」「手で掛けない」などの打ち消しの読み落とし・
「判断のために読んだファイル」の鍵・お題の正規表現がゲームに実在する名前に当たる）。0.35.25 で直し、
付け直すと 20 題とも 3 回 100 点。**下がったと出たら、直す前に必ず答えを読む**（今のところ、外れの多くは採点の側にある）。

## 本命の採点（0.35.28 から）

答えの JSON に `"choice"`（この依頼で実際に使う物・使う順に最大 4 つ）・`"others"`（関係はあるが今回は使わない物）・
`"read"`（読んだファイル）を書かせ、期待の語と減点の語は **choice の先頭 4 つだけ**に当てる。
others や read にいくつ並べても点にならない（依頼主の決定・2026-10-16）。choice が無い答えは 0 点で「choice が読めない」と出る。

0.35.27 までは答え全体に当てていた（loose）。答えは本命のほかに関係しそうな道具も並べるので、1 本の答えで
ほかのお題の期待の語まで満たすことが多く（0.35.21 では 1 本あたり 37 個のうち平均 6 個）、「本命を選んだか」を見分けられなかった。

継ぎ目: 0.35.28 からの記録（`"scoring": "strict"`）は、同じ答えを答え全体で数えた点（`loosePoints`）と、
ほかのお題の語がいくつ当たったか（`crossLoose` 答え全体・`crossStrict` choice）も持つ。前の版が loose の記録なら、
比べる表と「下がった」は loose の点どうしで出す（採点を替えただけで鳴らないように）。どのお題の点が採点でどう変わったかは、
`make agent-eval-release` の出力の「答え全体 → 本命」の表。0.35.27 までの記録を付け直すときは `--rescore --loose`。

## 点が見ていない物（読むときの注意）

- 減点の語は、同じ行に `unless` の語も出たらその行を数えない（道具の説明の行で減点しないため。例: use-engine-temp の
  「use-engine が local.mk を書き換える」）。打ち消しの「〜していないか」「X を消す」「呼ぶと鳴る」「手で掛けない」は、
  当たった語の後ろの同じ節の中だけで見る（「ずらして揺れを消す」のような、古い書き方を選んだ行の減点まで消さないため）。
- 書いたコードの出来は見ない。書かせて確かめるのは手で（`make check`・`bin/fge forbid`・lint z-table）。
