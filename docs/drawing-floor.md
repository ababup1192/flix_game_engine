# 絵の下限

`RawDraw.box` を並べただけの画面は未完成として扱う。次の 5 性質をすべて満たすこと。
**どの画風で満たすかは自由**。下は手の一例で、選択肢の全部ではない。

名前空間（`RawDraw` = 図形プリミティブ）は「気軽に使うと足かせになる」摩擦を作る仕切り。
満たすべき造形の下限は本書が定め、実際に絵が良いかどうかは `/critique-render` の目視が決める。

| 満たす性質 | 手の例 |
|---|---|
| 面に階調か質感がある | `ShaderDoc` + `Render.shaderFill` / `Render.vgrad`・`gradPolygon` / `Render.lightAt`・`darkAt`（放射の明かり・翳り）/ `Material`（粒・きらめき・染み）/ `Render.striped`・`checker` / `PxShade` のディザ |
| 主役が背景から分離して読める | `PxShade`（ふち光・接地影）/ `Render.lightAt`・`darkAt` / `Render.glowAt` / `Render.outline` / 明度差・色相差 |
| 層が分かれている（奥・主役・手前） | `ZStack` の木（奥→手前に積む・`topLayer`）+ `SortingLayer` の表 / 見下ろしは `ZStack.zIndex(Depth.orderAt(y), …)` / `Transition` の覆い / `Pass`（光マップを別の紙に集めて Multiply で本編に掛ける） |
| 時間が流れている | `Fx`・`FxDoc`（粒）/ `Sway`（揺れ）/ `Anim`（コマ替え）/ `Curve`（sine・tri・arch01・pieces・dampedSpring）/ `Scatter` / `Daylight` |
| 形が物として読める（シルエットだけで何か分かる / 部品同士の接続が破綻していない — 入り口・持ち手・関節 / 接地している / 比率が対象らしい） | シルエットの描き出し（`HeadlessRender.silhouettePng` — 対象を黒・背景を白で描き出して、形だけを取り出して目視する） |

記号・幾何が画風なら 5 つ目は「記号として一意に読める」で判定する（接地・関節は具象物の場合の言い換え）。

光と影で色そのものを分けたいときは `Color.warm` / `Color.cool`。

## 画風を先に決める・5 性質の中身（AGENTS.md から移した本文）

画面を作る前に **`.claude/skills/visual-dict` を引く**（頼まれてからではなく、View を書く前に
毎回）。engine の `docs/module-index.md` の「絵の逆引き」と `docs/shader-doc.md` も同じ入口。

**まず画風を決める。** どんな絵にするかはゲームごとに毎回決め直す物で、既定は無い
（テンプレの見た目・他のゲームの見た目をそのまま持ってこない）。決めたら
`AGENTS.local.md` に 2〜3 行で書く — 何を見て育った絵か・色は何色でいくか・
何をしないか。以下の下限は**その画風を実現する手数を尽くしたか**を測るだけで、
どんな絵にするかには口を出さない。

上の表の 5 性質を言葉で言うと次のとおり。実現の手は何でもよく、挙げる部品はあくまで例。

- **面に階調か質感があること**。`RawDraw.box` を並べただけの画面は未完成 — 単色のベタは
  「ここは平らであるべき」と決めた後の選択であって、既定ではない。
  （手の例: `ShaderDoc` の面 / `Render.vgrad`・`gradPolygon` / `Material` の質感
  （グレイン・きらめき）/ `Render.striped`・`checker` / ドット絵のディザ。**1px の細い面を
  積んだ疑似グラデーションだけは禁止** — 生成時間に直撃するし、上の部品で正しく描ける。
  使える部品は engine のバージョンで決まるので visual-dict の **[新]** 印を見る）
- **主役と背景が分離して読めること**。主役の輪郭が背景に溶けていない。
  （手の例: `PxShade.shadeDoc` のリムライト（ふち光）・接地影 / 明度差 / 縁取り /
  `Render.glowAt` / 背景側をぼかす・沈める。**明度差だけで足りるならそれでよい**）
- **層が分かれていること**（少なくとも 奥・主役・手前）。奥行きの表現が要らないゲームでも、
  情報の優先順位は絵に出す。
- **時間が流れていること**。完全に止まった画面を出さない。
  （手の例: `Fx`・`FxDoc` のパーティクル / `Sway` の揺れ / 明滅 / パレットサイクル /
  待機アニメのコマ送り。静けさが画風なら、揺れを極小にするのは正解 — ゼロにしないだけ）
  動く値は `EcsTween.Easing` か `Curve` を通す（値を飛ばさない）。
- **形が物として読めること**。シルエットだけで何か分かる・部品同士の接続が破綻していない
  （入り口・持ち手・関節）・接地している・比率が対象らしい。
  （手の例: `HeadlessRender.silhouettePng` で形だけを描き出して目視する。
  人を置くなら `.claude/skills/figure-drawing` の順序で決める。
  記号・幾何が画風なら「記号として一意に読める」で判定する）

**画風は違っていい・違うほうがよい。** 暗い背景に光る物、明るい紙のような淡い絵、
白地に太い線、色数を絞ったドット絵、単色 2 色だけ — どれも上の 5 つを満たせる。
「暗背景 + 加算グロー + パーティクル + ビネット」は visual-dict に載っている**一例**であって、
毎回それを出すのは手抜きと同じ（同じ顔のゲームが並ぶ）。

満たせない事情があるなら **`AGENTS.local.md` に理由を書いて例外にする**。黙って落とさない。

## 部品を選ぶ前に辞書を引く

box と circle だけで組み始めたら、それは辞書を引かなかった証拠。
`RawDraw.star` / `ellipse` / `sector` / `ngon`、`Render.vgrad` / `gradPolygon` / `striped` /
`checker` / `turned` / `clipped`、`PxShade`、`Material`、`Scatter`、`Mirror`、`Daylight` は
**すでに実装もテストもある**。「無いから手組み」の前に必ず一覧を見る。

- 技法 → 部品の翻訳表: `.claude/skills/visual-dict/reference.md`
- 採用ゼロ〜1 の部品一覧: `.claude/skills/visual-dict/unused-parts.md`
- 画風の決め方と手順: `.claude/skills/visual-dict/SKILL.md`
- シェーダーの語彙（Field / Shade の全 kind）: `docs/shader-doc.md`
- 逆引き全体: `docs/module-index.md`

## この画面の画風

同じゲームの `AGENTS.local.md` の画風の節が正（色 3 つ・やらないこと 1 つ）。
場面ごとに画風を変えるゲームでは、そこが指す `docs/style-<slug>.md` が正。
どちらも無ければ**先に書いてから**描き始める。

画風はゲームごとに決め直す物で、既定は無い。**テンプレどうしで画風をそろえない** —
揃えると「この画風が正解」という手本になってしまう。

## ドット絵（`*.sprite.json`）

**画素を 1 つ置く前に `.claude/skills/retro-pixel/SKILL.md` を読む**（色の予算・タイルと材質・
キャラの等身・ディザの当て方・繰り返し出る癖の禁止）。読まずに打った絵はここで差し戻す。

`legend` に書いた意味色キーは、`*.theme.json` のトップレベル・`paletteFile` の指す色票・
sprite Doc 直下の `palette` のどれかに**実体が無いと Studio が仮色で塗る**
（編集画面と実機で配色が食い違う）。

### ドット絵の打ち方（sprite.json の作法。AGENTS.md から移した本文）

下の 3 つは retro-pixel の要約ではなく、別の足場。ここに書くのは「どう打つか」の作法だけ。
何を描くか・どんな色でいくかは画風の仕事で、ゲームごとに毎回決め直す（既定の作風は無い）。

キャラの**歩き 4 方向**は手打ちの前に `.claude/skills/carve-sprite` を見る — 3 面図の立ち絵
1 枚から、止まった絵を 1 画素も変えずに 4 方向 3 コマを機械で彫り出せる。

- **形より先にパレットを決める**。素材ごとに「暗→明の 3〜4 色」を選んでから、
  その色だけで形を打つ。影と輪郭にはパレットの一番暗い色を使う — 迷って #000000 に
  逃げない（黒い輪郭を画風として選ぶなら `AGENTS.local.md` に書いて選ぶ）。
- **大きい物は大きい 1 枚で描く**。建物・大道具をタイルのマス目で刻んで組み立てると
  マス目の切れ目が絵に出る。数マスにまたがる 1 枚絵にして、隠れ（キャラが後ろに回る）は
  描画順（`ZStack.zIndex(Depth.orderAt(足元の y), …)`）で作る。
- **地面タイルは縁・角まで一式で作る**（いわゆるオートタイル）。芝⇔石畳⇔水のような
  境目は中央 1 枚で済ませず、縁 4 方・角 4 隅のバリエーションまで最初からデザインする。
  どの縁を貼るかは隣のマスを見てコードが選ぶ仕事で、rows の文字は増やさない。

パレットの色相・色数・ディザの量・輪郭の有無や太さは画風の自由。上の 3 つは
どの作風でも効く足場であって、同じ見た目を作るための型ではない。

## 画素の格子に乗せない絵（シェーダーの面・なめらかな輪郭・高解像度）

**面を `ShaderDoc` で塗る前・なめらかな輪郭で絵を組む前に
`.claude/skills/smooth-render/SKILL.md` を読む**（エッジの硬さの使い分け・面積と彩度・
質感の重ね方・なめらかな面に出る縞（banding）の消し方）。
ドット絵の作法（色数の切り詰め・ディザ・タイル）をここへ持ち込むと品質が落ちる。
`Field` / `Shade` の語彙そのものは `docs/shader-doc.md` が正。

## 良し悪しを決めるのは人（必ず確認を取る）

**下限を満たしたことと、絵が良いことは別。** いけてるかどうかを判定できるのは、
実際に画面を見る人だけ。エージェントが「良い絵になりました」と締めない。

- 絵・背景・見た目を作った / 変えたら、**生成して人に見せて確認を取る**
  （直した場面 1 枚だけなら `make render SHOT=<場面名>`・全部なら `make render-all`。
  直した物は `make diff DIR=<game>` で左=前・右=後）
- **ファイル名や層の一覧を並べるだけにしない** — 人が絵を探す羽目になる
- 直す所が複数見えたら、目立つ順に**候補を 3 つまで**出して番号で選んでもらう。
  自分で選んで手を広げない（一度に直すのは 1 つだけ）
- **壊れている物だけは聴かずに先に直す** — 落ちる・黒い穴・スナップショットの退行は好みの問題ではない

描き出した絵を自分で批評してから見せる手順は `.claude/skills/critique-render/SKILL.md`。

## 絵の周回（描いた後の直し方。AGENTS.md の 3 行の元の本文）

局所の欠陥（拡大して見つけた物）を潰し続ける周回は、費用を積むだけで絵が良く
ならない — 悪化すらする。効くのは**作りを変えた周**と**原因を特定して直した周**だけで、
どちらに当たるかを判定できるのは絵を見る依頼主だけ（実測: 2026-08-15 の style_lab）。

- **周回は r2 で必ず止める。** r2 を描き出したら r1 と r2 の PNG（実寸）を並べて依頼主へ出し、
  「①どちらが良いか ②続けるか、終わりか ③続けるなら直す所を 1 つ」だけを聞く。
  返事が来るまで r3 を描き出さない。②が「終わり」なら①で選ばれた周をそのまま提出する。
- r3 以降も 1 周ごとに①を聞き、**前の周のほうが良ければその周は捨てて前の PNG へ戻す**
  （周ごとの PNG は捨てずに `debug/history/` へ残す。作り直しは最大 5 周。
  拡大で見つけた欠陥は、実寸で読める物だけ直す）。
- **呼び出す側への注意**: prompt に「N 周まで・直せなければ報告へ書く」と書くと
  この決まりを上書きして殺す。進め方の指示はこの節を指すだけにする。

## 機械で確かめる（人に見せる前の下ごしらえ）

下限を満たしているかだけは、どの OS・どのエージェントでも機械が見られる。
**これが通っても「絵が良い」ことにはならない。**

```
bin/fge view [ファイル...]   # 矩形と円だけになっていないか
bin/fge palette              # 意味色キーが色票から解けるか
bin/fge sprite [ファイル...] # ドット絵の画素の並び(浮き・階段・細長さ・色数)
bin/fge anim [ファイル...]   # コマ間の飛び・体積・接地と 4 方向のそろい
```

`make lint-view` / `make lint-palette` / `make lint-sprite` / `make lint-anim` でも同じ。
lint-sprite の意図的な例外は、スプライトに理由付きで
`"lint-sprite": "対象外(orphan) — 火の粉は浮かせたい"` と書く(黙って除外はしない)。

### シルエット生成（造形が怪しいときの材料づくり）

「形が物として読める」が怪しいときは、対象を黒・背景を白だけにして生成すると、
色や質感に紛れていた形の破綻（浮き・つながらない接続・崩れた比率）が浮き上がる。
既存の描き出しの配管（`docs/headless-render-recipe.md` の cfg と描画コマンド列）にそのまま流せる:

```flix
// 既定は「主役の z-index の範囲だけ」= world の範囲(ゲームの絵)。UI・HUD は形の検査の対象外。
HeadlessRender.silhouettePng(cfg, HeadlessRender.SilhouetteScope.WorldBand, drawables, polygons, "scene_sil")
```

`SilhouetteScope.All`（全アイテム黒）も選べるが、画面全体が 1 つの塊に融けて個々の形は
見えなくなるので、**用途は画面全体の重心確認に限る**。
形の良し悪しを決めるのは目視のまま — 機械がやるのは「見やすい材料を出す」まで。
