# critique-render — 描き出して批評する

引数（任意）: 対象（絵 / 音 / 両方）、注目したい場面。

## 手順

1. ゲームの設計原則を読む（共通部はこのファイル群と AGENTS.md、
   ゲーム固有の原則 — 文字なし等 — は **AGENTS.local.md** を参照）。
2. 描き出しを実行する:
   - 絵: `make gallery-prologue`（debug/ に全場面 + all.png）や `make render SHOT=<場面名>`
     （素の `make render` は使い方を出して失敗する。全部いるときだけ `make render-all`）
   - 音: `make gallery-sounds`（assets/sfx/*.wav を debug/sounds/ に集め、debug/sounds.png を描く。
     BGM の WAV（assets/music/ か assets/bgm/）があるときだけ debug/music.png も描く）
     音どうしの聞こえ方（BGM と効果音の音量差・効果音の間だけ BGM を下げる・籠もらせる・連打の間引き）は
     WAV を作り直さず mixer.json（`App.withMixer` + `AudioMixer`）で直す。混ぜた後の音を聴くなら
     `AudioMixdown` で実機と同じ規則の WAV に書き出す（engine の docs/audio.md）
3. 出力を読む。all.png・各場面 PNG は Read で目視、音は sounds.png（1 音 1 段の波形と
   スペクトログラム。名前・長さ(ms)・サンプルレート・ピーク振幅つき）を Read で目視し、
   debug/sounds/*.wav を聴く。BGM があれば music.png も同じ見方で見る。ループ GIF（コマ 0 に
   戻る演出）が対象にあれば、目視の前に `make lint-loop`（または
   `bin/fge loop <framesディレクトリ>`）で継ぎ目を機械検査する。
   fade・wipe など戻らない演出は対象外。造形が怪しい絵（何の形か読めない・接続や
   接地が変）は、シルエットの描き出し（`HeadlessRender.silhouettePng` — 対象を黒・背景を白）で
   形だけを取り出して確かめる（docs/drawing-floor.md）。
4. 設計原則に照らして批評する。観点の例:
   - 原則違反（禁止事項に触れていないか）
   - **絵の下限**（AGENTS.md の「絵の下限」節の 5 つの性質。満たさない場面は場面名を挙げる）
     - 面に階調か質感があるか（単色の矩形を並べただけで終わっていないか）
     - 主役が背景から分離して読めるか（輪郭が溶けていないか）
     - 層が分かれているか（奥・主役・手前）
     - 時間が流れている気配があるか（粒・揺れ・明滅・コマ替えの痕跡）
     - 形が物として読めるか（シルエット・接続・接地・比率）
     - **画風そのものは批評しない** — AGENTS.local.md に宣言された画風を前提に、
       「その画風を実現しきれているか」だけを見る。別の画風を勧めない
   - **照合先をもう 1 つ開く（絵の作りで二択）** — 下限 5 性質をすり抜ける失敗は、
     どちらか片方にだけ載っている。
     - **画素の格子に乗る絵**（ドット絵・タイル地形・`*.sprite.json`）→
       `.claude/skills/retro-pixel/SKILL.md`。塊にしか読めない茂み・光源と食い違う明暗
       （幹が葉より明るい）・ベタの角丸長方形・階調でなく一様なノイズになったディザ・
       **色数の乏しい予算（AGENTS.local.md の画風の節の「色の予算」が「ディザ必須」の段。
       行そのものが無いなら、それも欠陥として報告する）なのに広い面がベタ 3 色のまま
       ＝ディザが 1 枚も入っていない**（見落としの筆頭。実寸で空・地面・大きい影を見る）
     - **格子に乗らない絵**（シェーダーの面・なめらかな輪郭・高解像度）→
       `.claude/skills/smooth-render/SKILL.md`。広い面だけ彩度が浮く・エッジの硬さが
       全部同じ・なめらかな面に出る縞（banding）・ムラが 1 種類だけでエアブラシに見える
   - 場面ごとの読み取りやすさ（何が起きているか一目で分かるか）
   - 色・音の一貫性（季節・時間帯・テーマとのなじみ）
   - 前回の生成からの意図しない変化
5. レポートを返す: 良い点 / 問題点（該当ファイル名つき）/ 直す案の順。
   修正はしない — 批評だけ返し、直すかどうかは呼び出し側が決める。
