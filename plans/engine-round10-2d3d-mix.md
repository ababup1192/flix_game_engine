# 段 I: 2D と 3D を混ぜる（rev0・下書き）

2026-11-02 の相談で、段 F〜H（HDR・線形化・lightmap）の後は「3D の質感をさらに上げる（SSAO・TAA・光の数）」より
**「2D と 3D を混ぜる」**を先にする、と決めた。ドット絵と 3D を同じ画面で混ぜられる 2D 寄りのエンジンは少なく、
このエンジンの強み（2D の部品・ShaderDoc・画面なしで確かめる仕組み）がそのまま効く。3D の質感だけを伸ばすと Godot と同じ土俵になる。
この下書きは範囲と論点の置き場で、段 H の後に詰めてレビューに回す。

## ねらい（作れるようにしたい物）

1. **横から見た 2D のゲームに、Blender で作って骨で動かすキャラ**（なめらかに動くアクション・格闘・横スクロール）。背景はドット絵か 2D の絵、キャラだけ 3D。
2. **HD-2D**（ドット絵のキャラと、3D の背景・被写界深度・光）。hd2d_lab（ワークスペースの試作。ゲーム側の自前の Camera3d で組んでいる）をエンジンの Scene3d で描けるようにする。
3. **見下ろしの 2D の中の 3D の小物**（宝箱・扉・回る物）を、2D の z の並びの中に差し込む。

## 決めたいこと（論点）

### I1. 正射影のカメラ
- `Camera3d` は今は透視（fovY）だけ。`projection = Perspective({ fovY }) | Orthographic({ height })` を足す（Unity の Projection / Godot の Camera3D.projection と同じ分け方）。
  height = 画面の縦に写る world の高さ。2D の design px と 1:1 にそろえる口（`orthographicForDesign(design, pxPerUnit)`）があると、ドット絵と大きさが合わせやすい。
- 影の地図（スポット）・billboard・霧・深度の Pass が正射影でも合うか。CPU（SoftRaster3d）も同じ式。gl-parity に 1〜2 行。

### I2. 2D の並び（z）の中に 3D を差し込む
- 今の `Render.scene3d` は 1 つの描き物で、2D の ZStack / SortingLayer の 1 つの層として置ける。キャラ 1 体ずつを別の Scene3d にすると、描く回数と深度の取り直しが増える。
- 論点: 1 つの Scene3d の中の 3D の物を、2D の z（手前・奥）に分けて差し込む口が要るか（例: 3D の層を「2D の背景の後・前景の前」に置くだけで足りるか）。
- 2D の sprite と 3D の物が奥行きで前後する場面（HD-2D の木の陰にキャラが入る）は、2D の sprite を 3D の billboard として同じ Scene3d に入れるのが筋（billboard はもうある）。ドット絵の最近傍・画素の格子にそろえる（snap）を billboard に足す。

### I3. ドット絵との画素の合わせ方
- 3D を低い解像度の Pass（Design 解像度）で描き、最近傍で拡大してドット絵と画素の大きさをそろえる（Resolution.Design の Scene3d はもうある）。
- 縁取り（アウトライン）・色の段（トゥーンの toonSteps はもうある）・パレットへ寄せる後処理で、3D のキャラをドット絵に馴染ませる。ShaderDoc の Pass の後処理で組めるか。

### I4. 2D のゲームから 3D のキャラを動かす口
- 骨のアニメーション（段 D の AnimationClip3d / Pose3d）を、2D のゲームの状態（歩く・走る・攻撃）から切り替える・混ぜる（クロスフェード）口。今は 1 本のクリップの再生まで。
- 当たり判定は 2D のまま（3D の形からは取らない）。

## 作る物（試作）
- 横から見た画面の小さな試作（ドット絵の背景 + Blender の骨のキャラ 1 体が歩く・跳ぶ・攻撃する）。新しいゲームとして作る（`/style-interview` から）。
- hd2d_lab を Scene3d へ寄せる（エンジンの口で足りない所を洗い出す）。

## 段取り（案）
