## 重さ（M4 Pro・窓 1920×1080・MSAA 4・垂直同期なし・600 コマの中央値 / p95・ms）

窓は `make debug` で起こし、`POST /start` で構図を替え、World に貯めた 600 コマ（`World.statsLine`）を `GET /state` で読んだ。
「送る」= 描き手が GPU へ命令を送る CPU 時間（3D の split + draw を含む）。「残り」= 間隔 − 送る − swap。
**WebGPU の窓は swap を測らないので、残りは GPU を待つ時間を含む**（hitch.md の「組み立て 82 ms」は大半がこれ。View を組む時間ではない）。
GL の窓では残り = 更新 + 組み立て（View）+ その他 で、1.4〜1.8 ms。更新（World.step）は hitch.md の行で 0.25〜0.4 ms。

- GL の p95 が中央値の 2 倍なのは、16 コマに 1 回の GPU の時間の query のコマ（docs/performance.md §11 の注意どおり）。GL の GPU の時間（同じ版の前の回）: 昼 10.6〜11.9 ms・夜の点光源の影 2 本 24〜26 ms
- **人の物差し「PC の CPU が 4 ms 以下か 8 ms 超か」への答え**: staticGroup に入れた WebGPU の窓は、送る 1.7〜1.9 ms + 更新 0.3 ms + View（GL で測った残りから 1.1〜1.5 ms と推測）= **約 3.5〜4 ms（4 ms の線の上）**。
  同じ物を GL の窓で描くと送るが 7〜8 ms（区画の版）・19 ms（物ごとの版）で **8 ms 超**。staticGroup を使わない（instances）と WebGPU でも送るが 11〜13 ms で **8 ms 超**、点光源の影 2 本を足すと 33 ms
- 60 fps の線: 昼と夜（影なし）は (2)〜(5) の全部が 85〜105 fps（GPU が律速。間隔 9.3〜11.5 ms の大半が GPU 待ち）。点光源の影 2 本の夜は 34〜46 fps で割る
- **持ち越しは効いている**: staticGroup にすると split が 5.7 → 0.2 ms・draw が 7.5 → 1.4 ms（(1) と (2) の差）。ただし**持ち越した集まりは視錐台で間引かれない**（描いた物 1,591/1,591・draw call 3,170 = 色 1,591 + 太陽の影 1,579。instances の (1) は 806〜1,370 に間引かれる）。
  GPU は見えない物まで毎コマ塗るので、(2) の間隔は CPU がほぼ空いているのに 9.5〜11.4 ms。点光源の影は docs/scene3d.md のとおり、灯り 1 本 × 面 6 つごとに集まりの全部を描く（20,528 draw）
- **法線マップの材質は static batching でつながらない**（docs/scene3d.md の決まり）。Bistro はほぼ全部の材質が法線マップを持つので、物ごとの glb は draw call が 1,591 + 影 1,579 のまま。区画で束ねる（素材の側）と 479 + 477

## 差の表（見た目と技術を分けて言う）

見た目の採点（基準の絵を 100 として、甘くしない）: **昼 60 点・夜 45 点**。形・絵・太陽の影・空の映り込みは並べて同じ物と分かるが、
陰の中が明るく平たい（AO と間接光が無い）・壁の色が環境の色を拾わない・夜は灯りの溜まりが 8 本分しか出ない、で「Blender どおり」には遠い。
技術の採点: 283 万三角形・材質 132 を 1080p で 85〜105 fps（昼）出せたのは良い。ただし GPU が見えない物まで塗っている（間引きが効いていない）ので余力は見かけより小さい。

### (a) 表現で足りない物

| 物 | 分け | 何が起きているか |
|---|---|---|
| AO（SSAO・occlusionTexture） | **engine に無い** | 軒下・路地・植木の根元が明るいまま。ORM の R（AO）は読まない（docs/scene3d.md の「やらない事」）。lightmap のベイクは口があるが、283 万三角形の Bistro の第 2 uv（LightMapUV）にベイクするのは素材の側の大仕事 |
| 間接光・GI（環境マップからの拡散） | **engine に無い** | ambient は 1 色、hemisphere は白い 1 つの数。HDR の空の青（上 0.54/0.63/0.79）と地面の照り返しの橙（下 0.32/0.24/0.16）を両方は出せない。陰の壁が Blender は橙に、engine は灰色に寄る（ambient を橙に寄せて半分だけ合わせた） |
| 反射（SSR・反射プローブ） | **engine に無い** | 映り込みは無限に遠いパノラマ 1 枚だけ。窓ガラス・濡れた石畳に周りの建物は映らない |
| HDR の太陽（空の絵の中の明るい点） | ある が使い方の問題 | 環境マップは 8 bit で 1 を超える所を切る。HDR の中の太陽の分（上半球の平均 1.36 のうち約 0.8）は捨てた。太陽の光は FBX の太陽 1 つだけ |
| 点光源 8 本の上限 | **engine に無い**（選び方はある） | 夜の通りの灯り 52 本のうち 8 本しか照らさない。遠くの街灯の足元の光の溜まりが出ない。ベイクなら出せる |
| 点光源の影の重さ | **engine に無い**（間引き） | 持ち越した集まりを灯りの面ごとに全部描く（20,528 draw・GPU 25 ms）。動かない灯りの影の地図を作り置く口も無い |
| 太陽の影の段（カスケード） | **engine に無い** | 1 段・4096・120 m。上からの構図は影がぼやけ、遠くの影は粗い |
| 半透明の並べ方 | ある（物単位） | 物の中の三角形は並べない。Bistro は BLEND が 1 材質だけなので今回は問題にならなかった |
| 葉の α | ある が素材の変換の問題 | MASK（0.5 固定）で抜く。MSAA の alpha to coverage は GPU の窓だけ・CPU の描き出しは縁が固い。Blender の葉は ROUND の抜きで同じ形 |
| 異方性・クリアコート・透過（glass の透け） | **engine に無い** | Bistro の窓ガラスの材質は BaseColor の α が 1 で、元から不透明として描かれる（Blender も同じ） |
| 発光で周りを照らす | **engine に無い**（Blender の EEVEE も照らさない） | 夜の看板・吊り電球は自分が光るだけ。両方とも点光源を置いて合わせた |
| トーンマップ | ある（AgX） | PostStack の AgX で Blender と同じ曲線。ブルームは Blender に無いので切った |
| 動画で見えた差 | 使い方の問題（推測）と engine の確かめが要る所 | 並べた動画の 12 秒あたりで、Blender は建物の影が石畳に落ちているのに engine は日向のまま。陰の壁も engine は橙に寄りすぎ（ambient を地面の照り返しの色にした副作用）。影の落ち方は casterReach・distance・カメラの近くの影の範囲を調べていない |
| 通り道の当たり | 素材の側 | 動画のカメラは当たり判定なしで流すので、スクーターと植え込みを 1 回ずつ抜ける |
| 環境マップの向き | ある が使い方の問題 | Blender の正距円筒と engine の正距円筒は左右が鏡で、u の向きも逆。2 回直して合った（`render_ref.py` の `write_panorama`） |
| タンジェント | 素材の変換の問題 | Blender の書き出しの TANGENT に長さ 0 の頂点があり、engine が part ごとに uv から求め直す（読み込みの時間に効く・見た目は同じ） |
| 絵の大きさ | 素材の変換の問題 | 元の 2048 を 1024（ORM・発光は 512）に縮めた。960×540 の比べでは差は見えない |

### (b) 重さの壁

1. **GPU が見えない物を塗る**（持ち越した staticGroup が視錐台で間引かれない）: 1080p・MSAA 4 で 9〜12 ms。昼は 60 fps に収まるが余力は 5〜7 ms
2. **点光源の影**: 2 本で draw 20,528・GPU 25 ms・CPU の影の区間 8.8 ms（GL）。これだけで 60 fps を割る
3. **instances のままの CPU**: split 5.7 + draw 7.5 ms（1,591 物）。staticGroup で 0.2 + 1.4 ms に落ちる
4. **GL の描き手の送る時間**: 同じ場面で WebGPU の 4〜10 倍（区画の版 1.9 → 8.1 ms・物ごと 1.8 → 19.5 ms）
5. **法線マップの物が static batching でつながらない**: draw call が物の数のまま（素材の側で区画ごとに束ねて 1/3 にした）
6. 読み込み: 220 MB の glb で 10 秒（絵 405 枚の解読とタンジェント）

### (c) 60 fps のための engine の手の候補（実時間の見積もりは推測）

| 手 | 効く所 | 見積もり（推測） |
|---|---|---|
| 持ち越した staticGroup を、物（つないだ単位）の境界で視錐台と光の視錐台で間引く（描く命令は持ち越したまま、描く範囲だけ毎コマ選ぶ） | (b)1・2。物ごとの版で GPU の塗りが 2〜4 割減る見込み・点光源の影は灯りの届く範囲だけになる | 3〜5 時間 |
| 法線マップの材質も static batching でつなぐ（タンジェントを頂点に持つ形どうし） | (b)5。draw 1,591 → 材質の数（約 130）+ 影 | 3〜5 時間 |
| 動かない灯りの点光源の影の地図を作り置く（灯りと集まりが替わった時だけ描き直す） | (b)2。夜の点光源の影 2 本で GPU 25 ms → 10 ms 前後 | 4〜6 時間 |
| SSAO を PostStack の欄に足す（奥行きの絵は HeightFog と共有） | 見た目 (a) AO。GPU +1〜2 ms | 6〜10 時間 |
| 環境マップから拡散の光（放射照度・SH 9 個）を作る | 見た目 (a) 間接光。陰の色が空と地面を拾う | 3〜5 時間 |
| 太陽の影を 2〜3 段のカスケードに | 見た目 (a) 影の段 | 4〜8 時間 |
| 点光源を 8 本より多く（タイルかクラスタで選ぶ） | 見た目 (a) 夜の灯り | 1〜2 日 |
| GL の描き手の送る時間を WebGPU に寄せる（または窓は WebGPU を既定のまま・GL は逃げ道と割り切る） | (b)4 | 調べるだけで 2〜3 時間 |

engine の拡張は相談の決まりなので、どれも手を付けていない。
