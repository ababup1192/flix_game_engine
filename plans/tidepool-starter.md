# tidepool-starter「潮だまり」— パズルのテンプレートの設計

依頼主が見本帳（5 案）から選んだ案 B。見本は `/home/user/puzzle-lab/tidepool`（止まった 1 局面の絵・規則は一部）。
これを **遊べるテンプレート** `templates/tidepool-starter` に作り直す。

## 1. 何を作るか（1 行）

1 手ごとに潮が満ち引きする磯で、岩を押して水路を作り変え、ヤドカリを新しい巻き貝まで引っ越しさせる。

テトリスの手本（tetris-starter）と並ぶ「パズル」の手本。落ち物ではない、**ターン制・取り消し前提・先読みつき**の
モダンなパズルの骨格を、読んで学べる量で見せるのがテンプレートとしての役目。

## 2. 規則（ここが芯。全部 `World` 側の純粋な関数・テストする）

### 2.1 盤

- W×H のマス（面ごとに Doc で決める。8×6 まで）。マスごとに **地面の高さ** `h ∈ {0,1,2,3}`。
- 盤の外は全部「外海」。外海の水位は **潮位** `L`。
- マスの上に乗る物（1 マスに高々 1 つ）: **小石**（押せる・水を通さない）/ **流木**（水に浮く・浮いているときだけ押せる）。
- **巻き貝**（ゴール）が 1 マス。**ヤドカリ**の初めの位置が 1 マス。

### 2.2 潮

- 潮位は手数 `t` で決まる: `L = cycle[t mod len(cycle)]`。`cycle` は rules の既定（`[0,1,2,3,2,1]`）、面に書けば面が勝つ。
- **手**（t を 1 進める物）: ヤドカリが 1 マス動く / 押す / その場で待つ。動けなかった手・押せなかった手は手に数えない。

### 2.3 水（テストの中心）

マス c の **抜け口の高さ** `d(c)` = c から盤の外へ出る全部の道のうち、「道の上の一番高い所」が一番低い道のその高さ。
道の上の高さは地面の高さ `h`（c 自身を含む）、小石のあるマスは通れない（∞）。道は盤の縁のマスから外へ出た所で終わる
（外そのものの高さは数えない）。だから縁のマスの `d` はそのマスの `h`。盤の縁から始める優先度付きの幅優先 1 回で全マス出る。

1 手ごとの水位の更新（前の水位 `w'`、新しい潮位 `L`、小石は手の後の位置）:

1. **残る水** `r(x) = min(w'(x), d(x))`（小石のマスは除く）。抜け口より上の分はあふれて抜ける。
   **水源になるのは `r(x) > h(x)` のマスだけ**（乾いたマスは水源ではない。`r ≥ h` なので、これを外すと乾いた岩が
   「水位 = 地面の高さ」の水源になり、隣のくぼみを満たしてしまう）。
2. **広げる**: 水は高い方から、地面がそれより低い隣のマスへ同じ高さで広がる（小石のマスへは広がらない）。
   外海も水源で、地面が潮位より低い縁のマス（`L > h`）へだけ潮位 `L` で入る。高い水位から順に取り出す優先度付きの幅優先 1 回で全マス出る。
   `w(c) = max(h(c), c へ届いた一番高い水位)`。小石のマスは `w = h`。
3. `w(c) > h(c)` のとき c は **沈んでいる**。深さ = `w − h`。

性質（テストで止める）:

- 1 つの池（つながった沈んだマスの塊）の水位は 1 つ（池の中に乾いた穴ができない）。
- 外海とつながる（`L > d(c)`）マスは潮位まで沈む。つながらない池は、前の水が抜け口の高さまで残る（**せき止めた水は引き潮でも残る**）。
- 小石を退けて抜け口が下がると、池はその高さまで抜ける。
- 堤（高さ 3 か小石）で囲った内側は、満ち潮でも乾いたまま（逆向きのせき止め）。

水の量は保存しない（流した水が別の所を沈める、はやらない）。量の保存は同時解決の順番が要り、
先読みと規則を 1 本の関数でそろえる良さが消えるため。

**面の初めの水**: 乾いた盤（`w = h`）から、何も動かさずに cycle を 1 周回した後の水を初めの水にする
（奥のくぼみに一度入った水は抜けないので、乾いた盤のままだと最初の満ち潮の前後で別の盤になるため）。

### 2.4 立つ高さとヤドカリ

- マスの **立つ高さ** `s(c)`: 浮いた流木があれば水面 `w(c)`、無ければ地面 `h(c)`。
  → 流木に乗ったまま潮が満ちると持ち上がる（**流木がエレベーター**。満ち潮で高い岩へ移れる）。
- 4 方向に 1 マス。行ける条件: 盤の中・小石が無い・沈んでいない（浮いた流木の上は可）・`|s(行き先) − s(今)| ≤ 1`。
- **手の後に自分のマスが沈んでいて、流木の上でもなければ「流された」**（失敗。取り消しで戻る。先読みが朱の輪で前もって知らせる）。
- 巻き貝のマスに入ったら面クリア。

### 2.5 押す（進む先に物があるときの表。上から当てはめる）

| 進む先 | 条件 | 結果 |
|---|---|---|
| 小石 | 押し先が盤の中・物が無い・`h(押し先) ≤ h(小石のマス)`（落とすのは可・登らせない）。沈んだマスへも押せる | 小石が 1 マス進み、ヤドカリも小石のいたマスへ進む（倉庫番と同じ。ただし 2.4 の行ける条件も満たすこと） |
| 小石 | 押せない | 動かない（手に数えない） |
| 浮いた流木 | 押し先が沈んでいて物が無い | 流木だけ 1 マス進む。**ヤドカリはその場に残る**（流木のいたマスは水なので） |
| 浮いた流木 | 押せない | 乗る（2.4 の行ける条件で判定。行けなければ動かない） |
| 着地した流木 | — | 地面と同じ（立つ高さ `h`）。押せない |

### 2.6 1 手の順番（同時解決はしない。この順で 1 回だけ）

1. ヤドカリの手（動く・押す・待つ）を盤に当てる。
2. t を 1 進め、`L` を出す。
3. 水を 2.3 で更新（小石の位置は 1 の後の物）。
4. 流木の浮き沈みを水から決める（`w > h` なら浮く・立つ高さは水面）。
5. ヤドカリの判定: 巻き貝なら面クリア / 沈んだマスで流木の上でないなら流された。

### 2.7 先読み（Into the Breach 式）

- 「何もしないで 1 手待ったら」を **同じ 1 手の関数**（`World.step(待つ)`）で出す。今と比べて沈むマス・現れるマスを盤に重ねる。
- ヤドカリのマスが次の手で沈むなら朱の破線の輪。
- 押した後の水は押す前には出さない（手ごとに分岐させると盤が読めなくなる）。先読みは「待った場合」1 本だけ。

### 2.8 取り消し・やり直し

- 取り消し（Z）: エンジンの `Worldline`（過去・今・先の zipper、cap は rules の Doc・既定 512）で 1 手戻す。流された後も取り消しで戻れる。
- やり直し（R）: 面の初めへ。取り消しの履歴は残す（R の前へ Z で戻れる）。

### 2.9 上の目標

- 面ごとに **最少手数**（`par`）を Doc に持つ。クリア時の手数で貝殻 3 / 2 / 1 個（par / par＋幅 以下 / それ以上。幅は rules の Doc）。
- `par` が正しいことは 8 節のテストと `make solve` で止める（人の書き間違いを残さない）。

## 3. 面（levels）

`assets/tidepool.levels.json` に、面ごとに **2 枚の格子**で書く: `heights`（`0`〜`3` の数字）と `props`
（`.` 何も無い / `o` 小石 / `=` 流木 / `@` ヤドカリ / `*` 巻き貝）。ほかに `cycle`（任意）・`par`・
`solution`（解き方の手の列 `UDLRW`）。盤は 8×6 まで・押せる物は 4 つまで（解く道具の状態数を抑える）。

言葉なしで規則が分かる 6 面:

| # | 教える物 | 中身 |
|---|---|---|
| 1 | 歩く・沈むと通れない | 引き潮の間に渡る 1 本道。HUD のキーの絵に「待つ」も出ておく |
| 2 | 待つ | 道の途中で一度待たないと流される（先読みの朱の輪で気づく） |
| 3 | 流木がエレベーター | 満ち潮で浮いた流木に乗って高い岩へ上がる。乗るのは流木が低い時に縁から（立つ高さの差 1 以内）。押せない流木へ進むと乗る、の向きは先読みの矢印で見せる |
| 4 | 小石を押す・逆向きのせき止め | 小石で堤を閉じ、満ち潮でも内側の道を乾かしておく |
| 5 | **せき止める（中盤でひっくり返る）** | 小石で潮だまりを閉じ、引き潮でも高い水を残して流木を浮かせたまま渡る |
| 6 | 組み合わせ | 3〜5 から 2 つ（今は 3 と 4）。外海につながった水では流木が毎周すべての高さを通るので、エレベーター（3）とせき止め（5）を 1 本の流木で同時に要る面は 8×6 に収まらない |

詰み（取り消しでしか戻れない形）は手の一部として許す。

## 4. 画面

- **title** — 見本の題名の画面（盤を背に題字。題字の下に読みやすさのための帯）。←→ で開いた面を選ぶ。
- **play** — 見本の play を規則の値から描く。盤・水・先読み・HUD（潮見表・手数・最少手数・貝殻・キーの絵）。
- **clear** — 面クリア: ヤドカリが巻き貝へ入る短い演出 + 貝殻の数 + 次へ。play の上に重ねる。
- **washed** — 流された: play の上に重ねる（波がさらう演出 +「Z で戻る」）。
- **ending** — 全面クリア。
- 動き（時間が流れている）: 1 手の水位の変化は `EcsTween` でなめらかにつなぐ（0.35 秒前後・Doc）。
  動いている間に次のキーが来たら、動きを終わりへ飛ばしてから次の手を当てる（溜めない）。海藻・魚・泡は常に。

画風は見本のまま（見本の `AGENTS.local.md` の画風の節を、`make status` が探す見出し「この画面の画風」で写す）。
描き出しが重い（見本で GIF 24 コマ 7.5 分）ので、水は高さの段の数だけ全面で塗るのをやめ、**沈んだマスの塊だけ** を
`DualGrid.maskPolys` の型抜きで塗る。目標は静止画 1 枚 10 秒以内。シェーダーは 3 本（岩・水・コースティクス）まで。
小石が水の中でも水を通さない壁であることは、小石の周りの水際の泡と、小石の上が乾いた色のままで見せる。

描き出しの場面: `title` `play` `flood`（同じ盤の満ち潮）`dam`（面 5 のせき止めた池）`clear` `washed` `ending`。

## 5. 音（docs/audio.md の下限）

`art/sfx.snd.star` → `assets/sfx/`: 歩く（砂・岩で 2 種）・小石を押す・流木・潮が満ち切った / 引き切った時だけ
（毎手は鳴らさない。単調になる）・流された・取り消し・面クリア・選ぶ。環境音は波のループ 1 本。音量はミキサーのバス（Doc）。

| `tidepool.rules.json` | 既定の cycle・貝殻の幅・水位の変化の秒・先読みの濃さ・Worldline の cap |

## 7. コードの層（lint/rules.flix で一方通行を止める。tetris-starter の rules.flix を写す）


## 8. テスト（/quality-assurance）

- 水: せき止めた水が残る・抜け口より上はあふれる・小石を退けると抜ける・外海とつながると潮位まで来る・
  **池の中で小石を押しても乾いた穴ができない**（レビューの反例をそのまま）・**乾いた段の隣のくぼみは乾いたまま**・
  小石のマスは乾いている・堤の内側は満ち潮でも乾く・1 列の盤「外海 | h0 | h1 | h0 | h3」を L=2→1→0 で回した水位・
  初めの水（2 周目の後 = 1 周目の後）。
- ヤドカリ: 立つ高さの差 2 は登れない・流木に乗って満ち潮で持ち上がる・沈んだマスへ入れない・流された。
- 押す: 2.5 の表の行ごとに 1 本。動けなかった手で t が進まない。
- 先読み: 「先読みの朱の輪（次の手で流される）」と「実際に待った後の流された判定」が、どの局面でも一致する（性質テスト。決まった種の手の列で局面を作る）。
- 面ごと: Doc の `solution` を流すとクリアし、手数 = `par`。
- `par` が最少であること（`par − 1` 手では解けない）は、深さを区切った幅優先の **`make solve`** で確かめる（重いのでテストの道から外す）。
  回し忘れを止めるため、`make solve` は確かめた面の中身（heights・props・cycle）のハッシュを面の Doc の `solvedHash` に書き、
  テストは「今の面の中身のハッシュ = `solvedHash`」を見る（面を直して solve を回さないと赤になる）。
- 取り消し: 手 → Z で前の World と同じ。
- Doc・Starts のテスト、TestTrace 相当（trace と flow の答えが一致・1 回の出来事で音は 1 つ）。
- e2e: `e2e/level1.flow` で表紙から面 1 クリアまで。`e2e/vocab.json`。

## 9. やらないこと

- 水の量の保存・流れる向き・波の物理。
- 面の自動生成（面は手で作り、解く道具で確かめる）。
- セーブは「開いた面と貝殻の数」だけ（`saves/`、git に入れない）。

## 10. テンプレートの手順（/add-template。漏らすと Studio で出ない・作れない）

- Makefile は共有の mk を include するだけ（`SHOTS`・`PALETTE` 系と `solve` だけ持つ）。
- `reference/title.png` と `reference/SHA256SUMS.txt`（`make reference-update`）。
- `make lint-palette`（見本の Palette.flix と palette.json → 生成の make ターゲットと、生成物と実機の色を pin するテスト）。
- 「この画面の画風」の宣言と View.flix の頭の層の並び。
- Studio の登録: `Genesis.flix` の puzzle は starter を 1 つしか持てず、今は `templates/tetris-starter`。
  **差し替えるか・別のジャンルとして足すかは依頼主が決める**（未決。決まるまで Studio 側は触らない）。

量の目安: src + test で 2500 行まで（tetris-starter は 1597 行）。超えそうなら面・画面・シェーダーから削る。

## 11. 進め方

1. 規則（Board・Tide・World）とテスト・解く道具（`make solve`）— 1 人
2. 面の設計（解く道具で par と solution を出す）— 1 の後
3. View を規則の値から描く（見本の View を移す）・title / clear / washed / ending — 1 の後
4. 音 — 3 と並行（`art/` だけ触る）
5. テンプレートの手順（10 節）
6. レビュー役の点検 → 直し → コミット
