# ノベルを「台本 + Doc + 素材」だけで作る — 調査と計画の下書き

- 状態: 下書き（2026-11-15）。着手は WebGPU の計画（plans/engine-webgpu.md）の後。エンジンを広げる話なので、着手の前に人と相談する。
- 目的: 演出込みのノベルを、Flix をほぼ触らずに作れるようにする。製作の速さ・AI のトークン・テンプレート追随の手間・Web の読み込みの量をまとめて減らす。

## 1. 調べた物と数（数えた値。【推】は手で振り分けた目安）

| | src の行数 | テンプレートから Flix で足した・変えた行 | 内訳 |
|---|---|---|---|
| sound-novel-starter | 6,407（render 757・test 3,135 は別） | — | 土台 A 4,669 / Doc の読み手 B 1,050 / 演出の語彙 C 571 / このゲームだけ D 117（Shots） |
| izakaya（会話劇・立ち絵あり） | 6,227 | +105 | Doc で済む 39 / コマンドで書ける 66（`<<hop>>`・湯気と煙の fx）/ 新しい仕組み 0 |
| kankan（縦の怪談） | 6,374 | +327 | Doc で済む 約 76 / コマンドで書ける 約 217（dim・flash・zoom・text・speed・hold・shake big）/ 新しい仕組み 0 |
| haioku（縦の配信ホラー） | 6,322 | 約 2,450 | 3D の部屋を歩く 約 530 / 縦の UI と入力 約 565 / 状態バーと配信の表示 約 235 / カメラの質感 約 200 / 場面表 約 170 / 一度だけの演出 約 140 / コメント欄 約 135 / その他【推】 |

ほかに分かった事:
- **演出コマンドを 1 つ足すと 4〜6 か所を同時に直す**（`Stage.Cue` の case・`cueOf`・`commandNames`・`applyCue`・`settle`・`Saves.Mark`・`WorldRead` の素材待ち・`View`）。haioku は 13 個足したので Stage・Saves・WorldRead がほぼ書き直しになった。
- **舞台の値がセーブに残らない**ので、kankan は各ノードの頭で同じコマンドを書き直している（`<<text bottom normal left>>` だけで 32 回）。
- **効果音を足すたびに Flix を直した**（kankan の `holdSecondsOf` の表）。
- **テンプレートへの追随が最大の手間**。ゲームが src を 33 本丸ごと持つので、kankan は +1,724 行と +2,830 行の当て直しを 2 回した。
- `bin/fge yarn build` の検査はコマンドの**名前**だけを見る。引数の誤りは実行するまで分からない。
- 語彙の正（話し手・最初のノード・コマンド名）が Flix の enum にあり、`vocab.json` を作るのに Flix を走らせる。
- Web 書き出しはゲームごとに fatjar → TeaVM で wasm を作り直す。
- エンジンには、時間で動かす（EcsTween・Curve・Lifetime）・Render の修飾（移動・拡大・回転・透明度・色）・ShaderDoc（JSON から読める）・Pass・Transition・CameraRig の揺れ・FxDoc の粒・AudioMixer がもうある。**足りないのは、それを台本の語彙につなぐ層**。

## 2. 目指す形

```
ゲーム = 台本（.yarn）+ Doc（*.json）+ 素材
エンジン = ノベルのプレイヤー（土台 A + 演出の語彙 + Doc の読み手）
```

- 演出の**部品**（描き方）はコード。台本と Doc は**選んで並べるだけ**。台本に入れる計算は Yarn の `set` / `if` / `jump` まで。
- 台本と Doc で書けない演出だけ、エンジンに部品を足す。足した部品はどのノベルからも台本で呼べる。
- ゲーム固有のコードが要る作品（haioku の 3D の歩きなど）は、今の「src を持つ」形を残す。データだけの作品とコードを持つ作品の 2 本立て。

## 3. 段の案（効く順）

| 段 | 中身 | 消える物（調べた 3 本で） |
|---|---|---|
| N1 | 語彙の正を Doc と台本へ移す: 話し手は story.json の `names` の鍵、最初のノードは Doc、場面表（Shots）は Doc にノード名と行で書く | Talk・Starts・Shots の直し（3 本とも毎回） |
| N2 | 演出コマンドの共通の口: コマンドを「名前・引数の型・どの層のどの値を替えるか・何秒かけるか・ease」の表で持ち、Stage・セーブ・素材待ち・描画へ自動で通す。名前付きの引数（`key=value`）を許し、引数の検査を `bin/fge yarn build` でする | 1 コマンド 4〜6 か所の直し。kankan の約 217 行・izakaya の 66 行 |
| N3 | 舞台の値をセーブに残す（今の Cast の Mark と同じ扱いをすべての層へ） | ノードの頭の書き直し（kankan で数十回【推】） |
| N4 | 標準の語彙を広げる: 層（背景・立ち絵・文字のウィンドウ・覆い・カメラ）の位置・大きさ・透明度・色・ぼかしを時間で動かす、`dim` `flash` `zoom` `shake 強さ 秒` `speed` `text 位置 大きさ 揃え`、切り替えの種類（fade・黒・ワイプ）、`<<se 名 wait>>`（wav の長さで待つ）、BGM の口、粒は FxDoc の名前で増やす | kankan・izakaya の (C) のほぼ全部。haioku の一度だけの演出と音 |
| N5 | 組んだ演出に名前を付けて使い回す（Ren'Py の transform・Tyrano の macro に当たる物。Doc に置き Studio で触れる） | 同じ組み合わせの書き直し |
| N6 | 汎用の UI 部品: 台本の変数を見せる HUD（字・アイコン・ゲージ・時計）を Doc で並べる、時間差で流れるメッセージのレイヤー（コメント欄・チャット・SNS） | haioku の状態バー・配信の表示・コメント欄（約 370 行） |
| N7 | 共通のプレイヤーの wasm を 1 本にし、ゲームごとには bundle（台本・Doc・素材）だけを配る | ゲームごとのビルドと書き出し。4G で 2 本目からエンジンの分（gzip で 2 MB 前後）を落とさずに済む |

順番の考え: N1〜N3 が土台（これが無いと語彙を広げるたびに Flix を直す）。N4・N5 で演出の幅を出す。N6 は作品が増えてから汎用の形を決める。N7 は N1〜N6 でゲームの src が要らなくなってから。

## 4. 決める前に軽く試す事（スパイク）

- N2 の書き方: (a) Yarn の位置引数のまま型だけ付ける (b) `key=value` (c) Naninovel 風 `pos:50,0`。kankan の台本の 20 行を 3 通りで書き、AI に書かせた時の誤りの数とトークンで比べる。
- N2 のコマンドの表をどこに置くか: Flix の record の一覧（型で守る）か、Doc（ゲームが足せる）か。ゲームが新しい「部品」を足せない以上、表はエンジン側の Flix に置き、Doc は名前付きの組み合わせ（N5）だけ、が有力【推】。
- N7: 汎用のプレイヤーの wasm に別のゲームの bundle を差して動くかを、sound-novel-starter と kankan で試す。

## 5. 測り方

- 段の前と後で、同じお題（例: kankan の 1 ノードを足す、効果音を 1 つ足す、izakaya の `<<hop>>` を足す）を AI にやらせ、**触った .flix の行数・トークン・かかった時間**を比べる（agent-eval にお題を足す。今の agent-eval がトークンを記録しているかは【未確認】）。
- 目標の案: izakaya・kankan 型の作品は Flix 0 行。haioku 型は 3D の歩き以外を 0 行。

## 6. 他のエンジンとの対比（知識による。細部は【未確認】）

- Ren'Py: `show 名前 表情 at 位置 with dissolve`、ATL で `linear 1.0 xalign 0.5 alpha 1.0`・`parallel`・`repeat`。
- Naninovel: `@char 名前.表情 pos:50,0 time:1`、`@back`・`@bgm`・`@shake`・`@spawn`。足りないコマンドは C#。
- TyranoScript: `[chara_show name=… time=1000]`、`[quake]`、`[anim]`、`[macro]`。
- 3 つとも、名前付きの引数・時間と ease の指定・台本の中で演出をまとめる口を持つ。今の語彙には 3 つとも無い。
