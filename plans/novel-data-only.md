ほかに分かった事:
- **演出コマンドを 1 つ足すと 4〜6 か所を同時に直す**（`Stage.Cue` の case・`cueOf`・`commandNames`・`applyCue`・`settle`・`Saves.Mark`・`WorldRead` の素材待ち・`View`）。haioku は 13 個足したので Stage・Saves・WorldRead がほぼ書き直しになった。
- **舞台の値がセーブに残らない**ので、kankan は各ノードの頭で同じコマンドを書き直している（`<<text bottom normal left>>` だけで 32 回）。
- **効果音を足すたびに Flix を直した**（kankan の `holdSecondsOf` の表）。
- **テンプレートへの追随が最大の手間**。ゲームが src を 33 本丸ごと持つので、kankan は +1,724 行と +2,830 行の当て直しを 2 回した。血鱗も src 約 +2,300/−1,380・test 約 +2,000 の当て直しをし、テープはゲームとテンプレートで二重に作った（約 5 時間）。
- **3D の背景を 2 本が別々に書いた**（血鱗の Lair3d・haioku の Walk）。どちらも glb を光を当てずに描き、休みの位置のカメラで撮った 2D の絵と同じ見た目にし、後から読み、Blender で作った道筋でカメラを動かす。
- `bin/fge yarn build` の検査はコマンドの**名前**だけを見る。引数の誤りは実行するまで分からない。
- 語彙の正（話し手・最初のノード・コマンド名）が Flix の enum にあり、`vocab.json` を作るのに Flix を走らせる。
- Web 書き出しはゲームごとに fatjar → TeaVM で wasm を作り直す。
- エンジンには、時間で動かす（EcsTween・Curve・Lifetime）・Render の修飾（移動・拡大・回転・透明度・色）・ShaderDoc（JSON から読める）・Pass・Transition・CameraRig の揺れ・FxDoc の粒・AudioMixer がもうある。**足りないのは、それを台本の語彙につなぐ層**。

## 2. 目指す形

```
ゲーム = 台本（.yarn）+ Doc（*.json）+ 素材
エンジン = ノベルのプレイヤー（土台 A + 演出の語彙 + Doc の読み手）
```

- 演出の**部品**（描き方）はコード。台本と Doc は**選んで並べるだけ**。台本に入れる計算は Yarn の `set` / `if` / `jump` まで。
- 台本と Doc で書けない演出だけ、エンジンに部品を足す。足した部品はどのノベルからも台本で呼べる。
- ゲーム固有のコードが要る作品（haioku の 3D の歩きなど）は、今の「src を持つ」形を残す。データだけの作品とコードを持つ作品の 2 本立て。

### 3.1 3D の背景（Backdrop3d）の契約の案

- 汎用にできる理由: ノベルの背景はカメラが決まった道を動くだけで、プレイヤーは歩き回らない。光と影は Blender で焼き込めるので、実行中は形・テクスチャ・カメラ・後がけだけで済む。
- 台本と Doc から見える物:
  - 背景: `backdrops3d.<名>` = { glb, textures, still（休みの位置のカメラで描き出した 2D の代わりの絵）, restCamera, fog, light }
  - カメラの道筋: `paths.<名>` = { keys, from?, to?, shake }。背景から背景へ歩く道筋（haioku）と、着く・沈む道筋（血鱗）を同じ形で持つ
  - 動く部品: `animated[]` = { glb の node の名前, kind = sway|path|billboardParticles|followPoint, 値 }
  - 台本: `<<bg 名>>`（3D があれば 3D、無ければ写真）・`<<camera 道筋 time= ease=>>`・`<<bg 名 walk>>`
- 並行で触る境目: 台本が知るのは背景と道筋の**名前だけ**。glb・シェーダー・絵・動く部品・霧は Doc と素材の側（絵の担当）。名前の正は Doc に置き、`bin/fge yarn build` が台本の名前を照らす。3D が読めなければ still で進む（fail-open）。台本の流れと時刻は 3D の有無で変えない。still と 3D のずれは描き出しの比較で見張る。
- シェーダーは部品の中に閉じる。ゲームが選べるのは ShaderDoc と材質のプリセットの名前まで。
- 決める前のスパイク: 血鱗の住処で (a) Blender で動画・連番に書き出して 2D で流す (b) glb + 焼き込んだ光 (c) 実行中の光と影、を大きさ・スマホの速さ・見た目で比べる。glb の材質とライトマップをどこまで読めるかは【未確認】。

### 3.15 語彙の増やし方（2026-11-15）

- エンジンの部品は少なく保ち、引数で幅を出す。名前付きの組み合わせ（N5・Doc）は自由に増やしてよい。
- 部品にするのは 2 本の作品で要った物だけ（「層は実装が 2 つある所にだけ」と同じ）。1 本だけの物はゲームのコードで足す口へ。
- 似た物は 1 つにまとめる（例: kankan の `dim`、血鱗の `black`・`lights` は覆いの濃さを時間で変える同じ物）。
- 4 本のコマンドは名前で約 50 個。まとめると基本の部品 15〜20 個でほとんど書ける【推】。語彙の一覧表を作る時に 4 本の台本を当てて確かめる。

### 3.16 標準の語彙の案と台本のグラフ（2026-11-15）

- 4 本の 50 個を、他のエンジン（Ren'Py・Naninovel・TyranoScript・Dialogic 2・KAG）と並べて 19 個の部品にまとめた案: bg・overlay・camera・shake・filter・show・hide・move・swap・speak・fx・audio・window・text・wait・gate・hud・feed・preset。共通の引数は time=（秒）・ease=（1 系統）・wait=。表は artifact「ノベル演出の標準語彙の案」。
- 台本のグラフの試作: `dialogue.json`（`bin/fge yarn build` の出力）から、分岐のグラフ・ノードごとの演出の帯・矢印ごとの持ち越す舞台・たどり着けないノードと行き止まりの検査を HTML に出す（scratchpad の yarn_graph.py。Python で 200 行ほど）。道具にするなら go の `bin/fge yarn graph` に移し、テープの「ここから遊ぶ」とつなぐ。

### 3.17 スパイク: 4 本を 19 個で書き直す（2026-11-15）

- 4 本の演出コマンド 924 行を機械で書き直した。書けなかった行は 0。案の引数のままで意味まで同じ 610 行（66.0%）、引数を足せば 879 行（95.1%）、意味が変わる 11 行（1.2%）、preset へ 34 行（3.7%）。コマンドの字数は 1.45 倍。
- 案に足す引数（多い順）: text の at=（NVL の頁の中の置き場）・bg の grade=・ease の smoothstep・overlay の layer=・音の間タップで送れない秒（音の Doc へ）・show / hide の置き場に 1 つだけ・bg の via=slide|pan ほか。
- 表の直し: hold は wait でなく text の lock=。同じ名前で別の動き（bg pan）を分ける。位置引数は 2 つまで。feed の本文は "…" で包む。shake の強さと time の既定はゲームの Doc に置く。
- 1 本でしか使われていない部品が多い（camera・text・feed・gate・move・swap・speak）。3.15 の「2 本で要った物だけ」に当てると根拠が弱い物がある。標準に入れるか、ゲームの口に置くかを決める。
- preset の Doc の案: `steps: [{ at: 秒, cue: "台本と同じ 1 コマンド" }]` の平らな時刻表。hop は書ける。stab は切り抜き・物だけの揺れ・重ね順・線が足りない。crash は ShaderDoc に時間で動く値が要る。scene の深さの決まり・wound の線・days の針・end のカードは、ゲームのコードで足す口。
- 置き場: scratchpad の vocab-spike/（convert.py・vocab.json・vocab.md・presets.json・out/issues.md）。

### 3.2 ゲームの作り方の流れ（人の案・2026-11-15）

1. **判断**: シナリオと演出の要望を、語彙の一覧表（コードから作る 1 頁）に照らし、「そのまま」「組み合わせ（N5）」「足りない」に振り分ける。
2. **追加**: 足りない物だけを**エンジンの汎用部品**として足す。足す前に組み合わせで書けないかを見る。ゲーム固有のまま残すのは 1 本だけの絵作りに限る。
3. **作り切る**: 台本・Doc・素材の操作だけで最後まで。
- 並行: 3D の背景のシェーダーと絵作りは、§3.1 の契約の裏で別の人が触る。段 3 は still で進める。

順番の考え: N1〜N3 が土台（これが無いと語彙を広げるたびに Flix を直す）。N4・N5 で演出の幅を出す。N6 は作品が増えてから汎用の形を決める。N7 は N1〜N6 でゲームの src が要らなくなってから。

## 4. 決める前に軽く試す事（スパイク）

- N2 の書き方: (a) Yarn の位置引数のまま型だけ付ける (b) `key=value` (c) Naninovel 風 `pos:50,0`。kankan の台本の 20 行を 3 通りで書き、AI に書かせた時の誤りの数とトークンで比べる。

- N7: 汎用のプレイヤーの wasm に別のゲームの bundle を差して動くかを、sound-novel-starter と kankan で試す。

## 5. 測り方

- 段の前と後で、同じお題（例: kankan の 1 ノードを足す、効果音を 1 つ足す、izakaya の `<<hop>>` を足す）を AI にやらせ、**触った .flix の行数・トークン・かかった時間**を比べる（agent-eval にお題を足す。今の agent-eval がトークンを記録しているかは【未確認】）。
- 目標の案: izakaya・kankan 型の作品は Flix 0 行。haioku・血鱗型は、1 本だけの絵作り（ゲームのコードで足す口）以外を 0 行。

## 6. 他のエンジンとの対比（知識による。細部は【未確認】）

- Ren'Py: `show 名前 表情 at 位置 with dissolve`、ATL で `linear 1.0 xalign 0.5 alpha 1.0`・`parallel`・`repeat`。
- Naninovel: `@char 名前.表情 pos:50,0 time:1`、`@back`・`@bgm`・`@shake`・`@spawn`。足りないコマンドは C#。
- TyranoScript: `[chara_show name=… time=1000]`、`[quake]`、`[anim]`、`[macro]`。
- 3 つとも、名前付きの引数・時間と ease の指定・台本の中で演出をまとめる口を持つ。今の語彙には 3 つとも無い。
