## 手法ごとの判定

| 手法 | 効いたか（盲検） | 支え方 |
|---|---|---|
| 冷たい目のレビュー（描いていない役が、お題を読む前に「何に見えるか」を書く） | **効いた。** 描き手の自己批評が見落とした物を当てた: ランプが灯っていない・石畳がレンガの壁・光の輪が板。(1) の石畳は自己批評で直したのに最後の審判にも「レンガの壁」と読まれた＝自己批評では見えない種類の誤り | **スキルの文に足す**（批評の頼み方 2 行） |
| 直しは 1 つずつ・名前を伏せた A/B で残す | **半分。** A/B は 3 回とも新しい方を選び、悪くした直しは無かった（守りとしては安い）。ただ r2 で止める決まりと組むと 1 周に 1 つしか直せず、(1) が r2 で 4〜6 か所を直したのに負けた（B・C）。C は「最初に直す 1 つ」が 1 回では直りきらなかった | **スキルの文に足す**（1 つずつは捨て、BLOCKING を全部直す形に変える）。A/B は迷った時だけ |
| 色相をずらした段（暗い段ほど色相を回す） | **キャラでは効いた**（A の決め手に「黄から橙へずらした影」）。地面では裏目（草の彩度が高すぎる） | **スキルの文に 1 行**（キャラの影）。道具は要らない: 今の `bin/fge px measure` がすでに `px.ramp-hue.*`・`px.ramp-chroma.*` で段の色相と彩度を測る |
| grid loop: 読み戻して間違った字だけ直す・字 = 色の固定 | **差が出なかった。** sprite.json は最初から「1 字 = 1 画素・legend で 1 字 = 色の名前に固定」の文字の格子なので、取り込めるのは読み戻しの所だけ。(2) は読み戻しで 3 か所（131 画素）を直し、直しの範囲が狙った所だけなのを diff で確かめた。どちらの組も 64×48 は手打ちせず、部品の格子を python で置いた | **道具の案だけ**（下）。スキルの文には足さない |
| アニメは前のコマの行を写して動く部品だけ変える | **効かなかった。** (2) の A は写しすぎて「息がランプの上下だけ」と批評役に読まれた（(1) も息は弱く、どちらも減点） | 足さない |
| 役の分担（palette-smith・rig-builder・animation-director） | 測れない。palette 先決めは上の色相の段に含まれる。rig（層）は sprite.json に層が無いので当てはまらない | 足さない |

### 作るなら（今回は作らない）

- `bin/fge px show <sprite.json> <名> [<コマ>]`: 行と列の目盛りつきで格子を出す（今の `render.py show`）。批評役の「何行目の何列目」と描き手の直しが同じ座標で話せる。
- `bin/fge px diff` を sprite.json の 2 つにも: コマごとに変わった画素の数と範囲（今の `render.py diff`）。直しが関係ない所へこぼれていないかの確かめ。今の `px diff` は pxsrc の周どうし向け。
- 批評役の頼み文を 1 枚（`critic.md` の形）にして、お題の文と絵を別のファイルに分けて渡す口（冷たい読みをお題より先に書かせるため）。
